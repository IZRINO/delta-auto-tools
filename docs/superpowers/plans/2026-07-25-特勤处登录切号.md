# 特勤处登录切号 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付可实机验证的单账号登录切号闭环：按完整 exe 路径结束旧进程、重新登录 WeGame、选择置顶游戏、启动并确认游戏窗口；任何不确定状态全面暂停，且不会重复提交登录。

**Architecture:** `special_ops` 保留现有配置、调度和校准入口；新增 Windows desktop adapter、模板双采样 observer、纯登录状态机和单实例 runtime。状态机只依赖窄 trait，生产实现调用 Win32、现有 NCC 和 `input_simulation`，单测使用脚本化 fake。前端继续保存业务配置，另订阅轻量 `run-changed` 事件显示试运行进度；操作提示 overlay 常驻，键鼠动作前显示 3 秒倒计时。

**Tech Stack:** Rust 2021、Tauri 2、Tokio、`windows-sys`、Enigo、React 19、TypeScript、daisyUI 5、Vitest、Bun。

## 固定实现约束

- 模板匹配阈值复用 Recognition 默认值 `0.75`；本阶段不增加阈值 UI。
- `verifiedSignature` 绑定 target key、rect、参考图 canonical path、文件长度、修改时间和阈值。重新框选、换图、清图、文件变化会使验证失效。
- 试运行签名绑定账号 QQ/密码、两个 exe canonical path及七项登录校准签名；任一输入变化后不再视为通过。
- v1 只结束完整路径匹配的进程实例，不递归结束 descendants，不按 basename 执行 `taskkill`。
- 登录按钮一次运行只点击一次。点击后只等待 `wegame.gameEntry`，失败时不得返回账号/密码输入步骤。
- 每个独立步骤各有 180 秒 timeout；固定延时只用于 400ms 双采样和键鼠前 3 秒倒计时，不作为成功条件。
- 密码只进入 Enigo 输入；日志、事件、错误、测试快照不得包含密码。

实现要求：

1. `CreateToolhelp32Snapshot` 按 basename 缩小候选。

5. `Command::new(exe).current_dir(exe.parent().unwrap()).spawn()` 启动，不经过 shell。
6. `EnumWindows` 只接受 visible、无 owner、面积大于 0、PID 与完整路径匹配的顶层窗口。
7. 输入前重新验证 HWND→PID→完整路径；最小化则 `ShowWindowAsync(SW_RESTORE)`；`SetForegroundWindow` 后用 `GetForegroundWindow` 确认。
