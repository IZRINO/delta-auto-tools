# 特勤处多账号制作自动轮次 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把现有登录、导航和四制作台 batch 串成可自动触发、可暂停恢复、逐账号隔离故障的多账号制作轮次；本阶段不执行子弹兑换。

**Architecture:** 新建纯 `round_planner.rs` 冻结到期任务，新建纯 `round_runner.rs` 编排账号状态机，新建 `round_scheduler.rs` 负责可唤醒等待与休眠跳变。`special_ops/mod.rs` 只承担 Tauri wiring、生产 driver、持久化和资源生命周期；现有 login/navigation/craft 状态机保持单一来源。

**Tech Stack:** Rust、Tokio、Tauri 2、React 19、TypeScript、Vitest、Bun、CodeGraph。

**执行约束:** Inline Execution；不用子代理或 worktree；严格 TDD；实机验收前不 stage、不 commit；不改现有倒计时；round/scheduler 忽略子弹任务。

- [ ] **Step 4：双账号实机验收，不提交**

1. A 两台到期、B 一台到期：A 一次登录处理两台，再登录 B。
2. A 找不到 QQ：标记 A，继续 B。
3. A 第一台成功、第二台失败：第一台新时间保留，继续 B。
4. B 运行中点击暂停：B 完成后停止切号。
5. 紧急停止：释放输入，当前账号/台 Uncertain，不自动重跑。
6. 应用重启与休眠恢复：保持未 armed；点击继续后才执行。
7. 仅子弹到期：不得启动 round。
