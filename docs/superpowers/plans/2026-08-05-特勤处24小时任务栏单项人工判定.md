# 特勤处 24 小时任务栏单项人工判定 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan inline, task-by-task, with review checkpoints. Do not spawn subagents, create worktrees, stage files, or create commits.

**Goal:** 将 24 小时时间轴的账号级人工校正改为失败制作台或子弹目标的行内单项判定，同时保留账号页完整人工校正。

**Architecture:** Rust 持久化层增加结构化失败归属，round runtime 按制作台或子弹目标写入失败，scheduler 只排除实际阻断范围。两个单项 Tauri command 复用现有 revision 临界区原子保存；React 时间轴根据 `manualFailure` 渲染行内状态按钮，账号页 modal 不变。

**Tech Stack:** Rust、Tauri 2、React 19、TypeScript、Vitest、Bun、serde、chrono、daisyUI。

**Execution constraints:** 当前 checkout 直接 inline 开发。保留工作树全部既有改动；不提交、不合并、不创建 worktree。开始 Task 1 编码前必须调用项目 `ponytail` skill；每项按 red → green → regression 顺序执行。

```rust
fn set_ammo_manual_failure(
    account: &mut AccountPlan,
    target_id: &str,
    step: &str,
    message: &str,
    at_ms: i64,
) -> Result<(), String> {
    let failure = AccountFailure {
        step: step.to_string(),
        message: message.to_string(),
        at_ms,
        station_kind: None,
        ammo_target_id: Some(target_id.to_string()),
    };
    let target = account.ammo_targets.iter_mut()
        .find(|target| target.id == target_id)
        .ok_or_else(|| "子弹兑换目标已不存在".to_string())?;
    target.last_failure = Some(failure.clone());
    if account.last_failure.as_ref().and_then(|item| item.station_kind.as_ref()).is_none() {
        account.last_failure = Some(failure);
        account.status = AccountStatus::Ready;
    }
    Ok(())
}
```

`apply_ammo_isolated()`、独立试运行 `Uncertain` 与 `apply_round_account_failure()` 的 ammo 分支调用该 helper。普通 `apply_ammo_failure()` 只维护当天 retry，不写人工失败。制作分支写 `stationKind`，继续把账号设为 `Uncertain` / `Isolated`。若账号已存在制作台失败，子弹 helper 不得覆盖制作失败摘要或把账号提前恢复为 `Ready`。

```typescript
export type InlineStationCorrectionDraft = {
    state: ManualStationState | null;
    hours: string;
    minutes: string;
};

export function createInlineStationCorrectionDraft(
    station: Pick<StationPlan, "finishesAtMs">,
    nowMs: number,
): InlineStationCorrectionDraft {
    const remaining = station.finishesAtMs !== null && station.finishesAtMs > nowMs
        ? Math.ceil((station.finishesAtMs - nowMs) / 60_000)
        : null;
    return {
        state: "crafting",
        hours: remaining === null ? "" : String(Math.floor(remaining / 60)),
        minutes: remaining === null ? "" : String(remaining % 60),
    };
}
```

## 验收场景

1. 制作台失败：24 小时任务行显示三个按钮；选择状态后只改该台，账号恢复正常。
2. 正在制作：未来完成时间自动向上取整预填；无未来时间必须手填；1 分钟与 168 小时可保存。
3. 子弹失败：只在对应子弹行显示两个按钮；其他制作与子弹仍可进入后续轮次。
4. 多子弹失败：每条独立显示、独立保存；处理一条不覆盖另一条。
5. 未兑换：清除当天成功与 retry 耗尽状态；scheduler 唤醒后可重新创建当天任务。
6. 已兑换：记录 Asia/Shanghai 当天成功，不再创建当天任务。
7. 登录、导航、窗口或旧版无定位失败：不显示单项按钮，只提示账号页完整处理。
8. revision 陈旧、写盘失败、runtime 运行中：不产生部分提交，行内输入和错误保留。
9. 账号页完整人工校正：原 UI、二次核对、原子提交继续工作，并清除全部目标失败。
10. 暂停状态：人工判定可保存，但 scheduler 不自动执行；用户点击继续后再处理到期任务。
