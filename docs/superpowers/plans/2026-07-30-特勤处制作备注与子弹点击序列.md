# 特勤处制作备注与子弹点击序列 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为四制作台配方点增加备注，把子弹业务目标改为带备注、指定点击点和兑换后滚轮动作的可持久化配置。

**Architecture:** 延续 `BusinessConfig` 作为默认/独立业务配置真相；制作备注放入 `StationBusinessConfig`，子弹点和滚轮动作放入 `AmmoBusinessTarget`。复用现有 calibration overlay，使用显式 `CalibrationSelectionScope` 区分全局、账号配方、默认子弹和账号子弹，不新增 overlay 或 command 名。完整子弹兑换 runtime 留到后续独立计划。

**Tech Stack:** Rust、serde、Tauri 2、React 19、TypeScript、Vitest、daisyUI、Bun。

- [ ] **Step 3: 写 scope 与原子提交**

```rust
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq, Eq)]
#[serde(tag = "kind", rename_all = "camelCase")]
pub enum CalibrationSelectionScope {
    AccountRecipe { account_id: String, station: StationKind },
    DefaultAmmo { target_id: String },
    AccountAmmo { account_id: String, target_id: String },
}
```

把现有 calibration commands 的 `account_id: Option<String>` 改为 `selection_scope: Option<CalibrationSelectionScope>`：`None` 保持全局目标；`Some` 只允许 `1 × 1` 点击点。`AccountRecipe` 要求账号开启独立设置；`DefaultAmmo` 更新默认目标；`AccountAmmo` 更新账号独立目标。继续使用现有 command 名、`settingsRevision` 临界区、磁盘先写和窗口恢复逻辑。
