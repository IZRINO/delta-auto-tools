# 特勤处联网利润筛选设计

状态：代码实现与自动化回归已完成，待 KKRB/Moligod 实机验收。

## 目标

在现有多账号子弹兑换 round 前增加可独立开关的联网利润 gate：

1. 只处理工具内已配置点击点的子弹目标。
2. 利润筛选关闭时，现有制作、子弹兑换、scheduler、暂停和错误处理行为完全不变。
3. 利润筛选开启时，截止时间前仅让达到最低总利润的目标进入 round。
4. 未达标、网站暂时失败或目标暂未出现时保持当天待执行，不记兑换失败。
5. 到达用户设定的利润截止时间后，忽略利润条件并执行当天剩余目标。
6. 每种子弹当天最多成功兑换一次；任何配置变化、查询恢复或后续 round 都不得重复成功目标。

本功能只决定“某个尚未成功的子弹目标现在是否允许进入 round”，不修改现有游戏内兑换状态机。

## 既有规则

本设计继承以下现行规则：

- 每日兑换时间使用 `HH:mm`，固定按 `Asia/Shanghai` 解释。
- 当天状态按 `Asia/Shanghai` 自然日 `00:00` 重置，不补做前一天。
- scheduler 启动时保持暂停；用户点击“继续”并成功持久化后才 armed。
- 同账号同时有到期制作和子弹任务时，先制作后兑换。
- round 启动时冻结账号、制作台和子弹目标；执行中修改配置不改变当前 round。
- 子弹逐项成功后立即持久化，后续失败不得回滚已成功目标。
- 账号级、系统级、紧急停止和仓库隔离规则继续沿用现有实现。
- 当前 active round 期间不重新查询利润，不向 active round 注入新目标。

## 非目标

- 不使用截图、OCR、模板匹配或颜色识别读取网站利润。
- 不根据子弹在网页中的位置或排序定位。
- 不保存 Moligod 兑换配方，不在工具内按材料价格重新计算网站利润。
- 不把备注作为网站绑定键。
- 不增加账号级利润门槛。
- 不比较、平均或合并 KKRB 与 Moligod 同一时刻的利润。
- 不用历史查询结果在重启后直接创建新 round。
- 不改变现有游戏内子弹点击点、A/D 重置、滚轮、二次确认或成功识别流程。

## 术语

### 每日兑换时间

现有全局 `dailyExchangeTime`。到达该时间后才允许启动利润查询或当天子弹 round。

### 利润截止时间

新增全局 `profitCutoffTime`，默认 `17:00`。必须严格晚于每日兑换时间。

截止时间前，目标必须通过利润 gate；截止时间后，当天剩余目标绕过利润 gate。

### 利润规则

网站中的一种子弹与最低总利润门槛组成的全局规则。多个账号的子弹业务目标可引用同一条规则。

### 查询审计

用于解释最近一次查询结果的持久化记录。审计只能展示和诊断，不能在应用重启或重新继续后充当有效利润凭证。

### 运行期资格

当前应用会话、当前配置 generation、当前自然日内由最新有效查询产生的临时资格。只有运行期资格可以在截止时间前参与新 round 冻结。

## 数据模型

### 全局利润配置

`SpecialOpsSettings` 增加全局利润配置，逻辑结构如下：

- `enabled: bool`：联网利润筛选开关，默认 `false`。
- `cutoffTime: String`：利润截止时间，默认 `17:00`。
- `rules: Vec<AmmoProfitRule>`：全局利润规则库。
- `audits: Vec<AmmoProfitAudit>`：当天每条规则最近一次查询审计。

字段可直接放入 `SpecialOpsSettings`，也可封装为 `ProfitFilterSettings`；实施时以保持 schema 清晰、normalize 集中为准。

### AmmoProfitRule

每条规则保存：

- `id: String`：工具生成的稳定内部 ID。
- `displayName: String`：只用于 UI。
- `kkrbMatchName: String`：KKRB 精确名称，必填。
- `moligodMatchName: Option<String>`：Moligod 精确名称，可选。
- `minimumProfit: u64`：最低总利润，只允许非负整数，不设业务上限。

匹配条件使用 `actualProfit >= minimumProfit`。利润计算使用有符号整数；Moligod 负利润合法解析，但无法通过非负门槛。

唯一性约束：

- `id` 全局唯一。
- 非空 `kkrbMatchName` 不得被多条规则重复绑定。
- 非空 `moligodMatchName` 不得被多条规则重复绑定。

### AmmoBusinessTarget

现有 `AmmoBusinessTarget` 增加：

- `profitRuleId: Option<String>`。

行为：

- 默认配置和账号独立配置只引用全局规则 ID，不复制门槛或网站字段。
- 开启账号独立设置并复制默认配置时保留 `profitRuleId`。
- 点击点、备注、普通/赛季类型、滚轮次数和执行顺序保持账号业务配置语义。
- 当天成功日、`retryDay` 和重试次数仍按账号目标保存，不进入利润规则。
- 旧目标迁移后 `profitRuleId = null`。

利润开关开启时，未绑定规则的目标标记“利润规则未配置”并跳过；关闭时仍按原流程兑换。

### AmmoProfitAudit

每条规则只保留当天最近一次审计：

- `ruleId`
- `day`
- `queriedAtMs`
- `source`：产生权威利润或目标缺失结论的 `kkrb` / `moligod`；两站均失败或未配置时为空。
- `attemptedSources`：本次实际尝试的数据源有序列表。
- `sourceDataAt`：网站提供数据时间时保存，否则为空。
- `sourceVersion`：网站提供版本时保存，否则为空。
- `profit`：成功解析时保存有符号整数，否则为空。
- `threshold`：本次比较使用的门槛快照。
- `outcome`：`qualified`、`belowThreshold`、`targetMissing`、`sourceFailure` 或 `unconfigured`。
- `detail`：短错误或匹配说明。
- `nextQueryAtMs`：保存时预计的下一查询时间，仅用于 UI。

应用重启后审计显示为“历史记录”。`qualified` 审计不等于当前运行期资格。

### ProfitQueryRuntime

利润决策另存于内存运行态，不持久化：

- 当前自然日。
- 当前配置 revision / query generation。
- 当前查询是否 active。
- 当前组内查询序号。
- 下一次查询时间。
- 本会话已达标但尚未冻结的规则 ID。
- cancel token。

以下动作必须清空或递增 generation，使旧异步结果失效：

- 应用启动。
- 暂停或健康检查强制暂停。
- 休眠时间跳变。
- 修改利润开关、截止时间、规则绑定或门槛。
- 修改每日兑换时间。
- active round 结束且仍有待处理目标。
- round 启动失败或系统级失败。

## 配置 UI

特勤处页面新增全局“联网利润筛选”区：

- 启用开关。
- 利润截止时间。
- 当前阶段：等待兑换时间、查询中、等待下轮、active round、已到截止时间。
- 下一次查询时间。
- 最近整轮数据源与错误摘要。

利润规则列表每行显示：

- 显示名称。
- KKRB 精确名称和绑定状态。
- Moligod 精确名称或“备用源未配置”。
- 最低总利润。
- 最近利润、来源、查询时间和数据版本。
- 达标、未达标、目标缺失、查询失败或历史记录。
- 被默认配置和账号独立配置引用的数量。

### 建立 KKRB 绑定

- 网站当前返回目标时，通过可搜索下拉列表选择。
- 因 KKRB 不显示负利润目标，当前列表缺失时允许手动填写精确名称。
- 手填名称在首次真实命中前显示“尚未在网站命中过”。
- KKRB 正常响应但名称缺失时，结果为 `targetMissing`，不是数据源失败。

### 建立 Moligod 绑定

- Moligod 绑定可选。
- UI 提供精确名称输入与“验证绑定”动作。
- 后台页面按输入名称搜索并扫描过滤后的结果页；只有一个结果的显示名称精确一致时才允许保存。其他仅包含该名称的相似结果不算命中。
- 比较前只去除名称首尾空白，不做大小写、标点、空格或别名归一化。
- 网站名称变化后旧名称匹配失败；必须由用户重新验证并保存，禁止根据相似名称静默改绑。

### 删除利润规则

未被引用的规则可直接删除。

被引用的规则删除前必须显示：

- 规则名称。
- 引用它的默认配置和账号独立配置。
- 受影响目标数量。

二次确认后，在同一 revision 临界区内：

1. 清空全部相关 `profitRuleId`。
2. 保留子弹目标、点击点、备注、顺序和当天运行态。
3. 删除全局规则。
4. 一次写入 `special_ops_settings.json`。

任一步失败则零写入，禁止悬空引用或 UI 假成功。

## 查询窗口与节奏

利润查询只在以下条件全部成立时运行：

- 特勤处功能和全局自动化开关均开启。
- scheduler 已 armed，应用未暂停。
- 不存在 active round。
- 当前时间达到每日兑换时间但尚未到利润截止时间。
- 至少存在一个当天未成功、未重试耗尽、账号可参与、业务目标启用且已绑定利润规则的目标。

查询组节奏：

1. 进入查询窗口后立即执行第 1 次。
2. 第 1 次结束后等待 5 分钟，执行第 2 次。
3. 第 2 次结束后等待 5 分钟，执行第 3 次。
4. 第 3 次结束后等待 50 分钟，开始下一组第 1 次。
5. 重复直到利润截止时间或没有待处理目标。

等待从上一次查询完成时计算，禁止查询重叠。

暂停、关闭或休眠跨过查询点：

- 兑换时间前继续：等待兑换时间。
- 兑换时间至截止时间之间继续：立即开始新查询组。
- 截止时间后继续：不查询，直接按截止规则计划当天剩余目标。

## 数据源适配

### KKRB 主源

主源使用 KKRB 结构化数据。当前适配入口为 `POST https://www.kkrb.net/getTradeAmmoData`；具体 URL 与 schema 必须封装在 KKRB adapter 内，禁止散落到 scheduler 或 UI。

一次查询只请求一次 KKRB，并为本轮全部待查询规则建立名称索引。

裁决：

- HTTP、连接、超时、`code` 失败、“系统繁忙”、根 schema 无效 → KKRB 整体失败，允许调用 Moligod。
- KKRB 正常响应且精确名称唯一命中 → 读取网站给出的总利润。
- KKRB 正常响应但目标缺失 → `targetMissing`，视为当前未达标，不为该目标调用 Moligod。
- 精确名称重复或命中行利润无效 → 该规则 `sourceFailure`；KKRB 整体仍视为成功，因此不以 Moligod 掩盖主源数据歧义。

工具不依据 KKRB 排名位置匹配。

### Moligod 备用源

只有 KKRB 整体失败时才启动 Moligod。页面入口：

- `https://moligod.com/ammo-exchange`

采集使用专用隐藏 WebView：

- 不显示、不抢焦点、不占用键盘鼠标。
- 每次查询创建新页面实例，禁止复用上次页面或审计利润。
- 等待页面完成数据加载后，通过 DOM 读取网站已经计算并显示的“预估净利润”。
- 不下载并固化兑换配方，不在工具中重算材料成本、手续费或产出价值。

截至 2026-08-02，Moligod 结果 DOM 显示子弹名称和预估净利润，但不显示稳定网站 ID。本设计使用网站精确名称作为明确匹配键。adapter 使用以下定位方式：

1. 以配置的精确名称程序化设置网页搜索框并触发网页自身过滤。
2. 等待过滤稳定。
3. 扫描过滤后的全部结果页；忽略只包含搜索词但显示名称不完全相同的相似项。
4. 要求精确名称只命中一行。
5. 读取该行的显示名称和“预估净利润”。

该流程不发送真实键盘或鼠标输入。搜索能力、DOM selector 或唯一性失效时，判为 Moligod 数据源失败，禁止退化为按页面位置读取。

利润文本规范化：

- `+270,458` → `270458`。
- `-12,300` → `-12300`。
- 删除首字符 `+` 与千位逗号。
- 保留负号。
- 空值、`--`、小数、非数值、超出有符号整数范围均拒绝。

### 数据源裁决

同一次查询对每条规则只产生一个权威结果：

1. KKRB 整体正常 → 只使用 KKRB。
2. KKRB 整体失败 → 对配置了 Moligod 精确名称的规则使用 Moligod。
3. KKRB 整体失败且规则未配置 Moligod → 保持待执行。
4. 两站均失败 → 保持待执行。

两个网站不同时比较，不要求同时达标，也不取较高值或平均值。

## scheduler 与 round 集成

### 利润筛选关闭

- `build_schedule()`、timeline 和 round 行为保持现有语义。
- 不联网、不校验 `profitRuleId`、不读取利润审计。
- 当天剩余子弹按每日兑换时间和现有合并规则进入 round。

运行中关闭利润筛选：

- 当前冻结 round 不变。
- 当前 round 结束后，剩余目标按现有非利润流程立即重新计划。
- 没有 active round 时，scheduler 立即重新计划。

### 利润筛选开启且未到截止时间

查询结束后：

1. 只把 `profit >= minimumProfit` 的规则放入当前运行期资格集合。
2. planner 将引用这些规则、当天可执行且账号为 `Ready` 的目标冻结进新 round。
3. 同一规则达标时，所有引用该规则且符合账号运行态条件的目标均可进入 round。
4. 同账号有到期制作时，沿用“先制作后子弹”。
5. 只有子弹时，沿用 Tab 后直接进入子弹入口。

未达标、目标缺失、未绑定或数据源失败的目标不进入本轮，保持待执行且不增加 `retryCount`。

冻结成功后立即清除对应未冻结资格；active round 期间停止利润查询。round 完成后仍有待处理目标且未到截止时间时，立即开始新查询组。

一次游戏内兑换尝试失败后，后续新 round 必须重新通过当时利润 gate；不得复用失败 round 的资格。到截止时间后则按截止规则处理。现有当天重试耗尽目标继续排除。

### 利润截止时间

到达截止时间时：

- 未冻结且当天仍可执行的目标统一绕过利润 gate。
- 没有 active round时立即创建剩余 round。
- 已有 active round 时不注入；当前 round 结束后创建后续 round。
- 正在进行的利润查询必须取消或使 generation 失效，查询结果不得覆盖截止决策。
- 已成功或当天重试耗尽目标仍排除。

### 设置变化

修改门槛、网站绑定、每日兑换时间或截止时间：

- active round 不变。
- 无 active round 且当前位于查询窗口 → 保存成功后立即重新查询。
- 新每日兑换时间仍在未来 → 等待新时间。
- 新截止时间已到 → 立即应用截止规则。
- 已过截止时间时不因设置变化重新查询。
- 当天已成功目标永不重新进入。

## 24 小时时间轴

利润筛选关闭时保持现有投影。

利润筛选开启时：

- 每日兑换时间前，子弹任务显示为“等待利润查询”，不得承诺到点一定登录。
- 查询窗口内，利润区显示下一次查询时间。
- 尚未达标的账号子弹任务在时间轴上以截止时间作为“最晚执行”锚点，并明确标记“可能在利润达标后提前执行”。
- 规则达标并冻结 round 后，时间轴刷新为实际 queued / running 状态。
- 暂停且到达截止时间后，相关任务仍显示“0 分钟后”，直到用户点击继续。

时间轴展示不得反向修改 planner 的实际执行时间。

## 持久化与并发

配置、规则、引用和审计继续写入 `special_ops_settings.json`，不进入 Profile。

所有写入必须：

1. active round 期间允许保存利润开关、截止时间、规则、门槛和引用，但新值只对下一轮生效；当前 plan 必须持有独立利润决策快照，禁止重新读取新利润配置。
2. 校验 `settingsRevision`。
3. 在 `SettingsCoordinator` / special_ops revision 临界区内读取权威状态。
4. 在副本上完成 normalize、唯一性、引用和时间校验。
5. 一次写盘成功后再替换内存。
6. 发布 bootstrap/state 更新并唤醒 scheduler。

查询本身不得持有设置锁或 revision 临界区等待网络与页面。查询开始时捕获 revision 和 generation；返回时只在两者仍匹配时应用。过期结果直接丢弃。

审计写入失败属于系统级持久化故障：不创建使用该结果的 round，按现有规则全面暂停。网站查询失败本身不是持久化故障。

## 错误分级

### 规则未配置

- 利润开关开启时跳过目标。
- UI 显示“利润规则未配置”。
- 不记当天失败，不修改账号状态。

### 当前未达标

- 包括利润低于门槛和 KKRB 正常响应中的目标缺失。
- 保持待执行，等待下一查询。
- 不增加游戏内 retry。

### 数据源失败

- KKRB 整体失败时尝试 Moligod。
- Moligod 失败或未绑定时保持待执行。
- 两站失败不暂停整套自动化，不修改账号状态。
- 到截止时间后统一绕过利润条件。

### 配置或持久化失败

- 非法时间、重复绑定、悬空引用、revision 冲突或写盘失败时拒绝保存。
- UI 保留用户草稿并显示具体错误。
- 内存和文件维持旧状态。

### 游戏内失败

一旦 round 已创建并开始登录，后续失败完全沿用现有：

- 单目标失败与当天 retry。
- `Uncertain`、`Isolated`、`NeedsManualLogin`、`LoginFailed`。
- 系统级全面暂停。
- 紧急停止。

利润模块不得覆盖或弱化这些状态。

## 安全边界

Moligod 隐藏 WebView 使用独立 label 和独立 capability：

- 顶层导航只允许 `https://moligod.com/*`。
- 不复用允许任意 `http://*` / `https://*` 的 `strategy-content` capability。
- 不授予 shell、文件、剪贴板、窗口管理、键鼠输入或任意应用 command 权限。
- DOM 结果通过单向、最小结果通道回传；payload 必须包含 query generation，并在 Rust 端执行完整 schema、长度和数值校验。
- 任意跳转到其他 origin、弹窗、新窗口或下载请求均取消查询。
- WebView 使用隔离的临时数据目录，不与主窗口或攻略 WebView 共享会话；销毁后清理。

第三方页面拥有其展示数据，无法通过客户端技术证明数据本身真实。安全目标是：页面异常只能导致“不执行利润 gate 目标”，不能获得本机权限或伪造其他工具状态。

## 旧配置迁移

迁移规则：

1. 利润筛选默认关闭。
2. 利润截止时间默认 `17:00`。
3. 旧子弹业务目标的 `profitRuleId` 为空。
4. 不自动根据备注、目标名称或点击顺序建立网站绑定。
5. 现有当天成功、retry、点击点和账号独立配置原样保留。
6. normalize 幂等；再次加载不得重复生成规则或审计。
7. 截止时间不晚于每日兑换时间的旧/损坏配置不得静默改写；保持暂停并要求用户修正。

## 测试

### 纯领域测试

- `actualProfit >= minimumProfit` 的边界：0、等于门槛、大于门槛、负利润。
- 规则 ID、KKRB 名称和 Moligod 名称唯一性。
- 规则删除时原子解除引用，保留业务目标和当天运行态。
- 旧 schema 迁移与 normalize 幂等。
- 历史 `qualified` 审计不能生成运行期资格。

### KKRB adapter

- 正常响应与利润解析。
- “系统繁忙”、HTTP、网络、超时和根 schema 错误。
- 精确名称唯一命中、缺失、重复和无效利润。
- 正常响应目标缺失时禁止调用 Moligod。

### Moligod adapter

- 新页面加载、精确名称搜索、相似名称过滤、跨页扫描、唯一精确命中。
- `+270,458`、`0`、负数、空值、`--`、小数、溢出。
- 搜索框缺失、DOM selector 变化、零结果、多结果、页面超时。
- redirect、新窗口和非 Moligod origin。
- 每轮销毁并重新创建，禁止复用旧 DOM。

自动测试使用固定 HTTP 与 DOM fixture，不依赖实时网站。另保留明确标记的实机手动验收，验证当前网站 schema 和 selector。

### query scheduler

- 每日兑换时间前不查询。
- 立即、5 分钟、5 分钟、50 分钟节奏。
- 查询互斥和 completion-based 等待。
- 暂停、继续、休眠、关闭恢复。
- config revision / generation 改变后丢弃迟到结果。
- active round 期间不查询，结束后立即重启查询组。
- 截止时间取消 in-flight 查询并绕过利润。

### round planner / runner

- 关闭利润筛选时行为与现有实现一致。
- 达标规则冻结全部符合条件的账号目标。
- 未达标、缺失、未配置和来源失败不进入 round。
- 同账号制作与子弹继续合并。
- 当前 round 不受设置变化影响。
- 一次失败后的新 round 重新经过利润 gate。
- 已成功与 retry 耗尽目标不重复。
- 截止后创建剩余 round；active round 时排队为后续 round。

### 前端

- 全局开关关闭时隐藏或禁用利润配置校验，不阻塞原流程。
- 规则新增、编辑、双站精确名称绑定、手动 KKRB 名称和 Moligod 可选验证。
- 删除引用规则的二次确认摘要。
- 最近利润、来源、历史标记、失败原因和下一查询时间。
- 未绑定目标的明确提示。
- 时间校验和 revision 冲突保留草稿。
- 24 小时时间轴显示等待利润、最晚执行和暂停后的 0 分钟。

## 验收标准

1. 利润筛选关闭时，现有多账号流程无行为变化。
2. 开启后，截止时间前只有达标规则对应目标进入 round。
3. 未达标与查询失败不记兑换失败、不改变账号状态。
4. KKRB 正常缺目标时不错误切换 Moligod。
5. KKRB 整体失败时才使用 Moligod。
6. 到截止时间后，剩余目标正常进入 round。
7. 已成功目标永不重复。
8. 页面排序、分页和屏幕布局变化不影响定位。
9. Moligod 全程不使用识图，不弹出可见窗口，不占用键鼠。
10. 历史审计不能在重启后直接触发兑换。
11. UI 能解释每个目标为何执行、等待或跳过。
12. 网站结构变化只能产生查询失败，不能产生错误兑换。

- 数据源裁决：KKRB 主源，只有整体失败时使用 Moligod。
- Moligod 利润：读取页面“预估净利润”，不重算配方。
- 匹配：KKRB 精确名称；Moligod 精确名称。
- 门槛：全局规则，非负整数，包含等于边界。
- 查询窗口：每日兑换时间至利润截止时间。
- 查询节奏：立即、5 分钟、5 分钟、50 分钟后重复。
- 截止时间：默认 `17:00`，到点后忽略利润。
- 冻结：达标目标只冻结当前 round，active round 期间不重查。
- 失败：未达标和网站失败保持待执行，不记当天失败。
- 历史：持久化审计但禁止复用作决策。
- 删除：解除全部引用后原子删除规则。

无待定产品问题。实施细节必须遵守本设计的状态、并发和安全边界。
