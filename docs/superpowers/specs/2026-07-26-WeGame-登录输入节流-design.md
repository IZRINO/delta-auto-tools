# WeGame 登录输入节流设计

> 已废止：WeGame 密码框拒绝合成输入。登录流程改由 `2026-07-27-WeGame-记住密码账号选择-design.md` 定义。

## 目标

降低 WeGame 登录表单因输入框尚未获得焦点、字符输入过快而漏输账号或密码的概率。输入节奏更接近人工操作，但不承诺绕过 WeGame 风控。

## 范围

- 仅调整特勤处 WeGame 登录流程的账号与密码输入。
- 不修改 Morse、Recognition 等其他自动输入流程。
- 不增加 UI 配置、持久化字段或 Tauri command。
- 不改变登录失败后停止提交密码的规则。

## 输入时序

每次输入账号或密码时执行：

1. 完成现有三秒键鼠占用提醒。
2. 聚焦 WeGame 并通过现有识别守卫。
3. 点击目标输入区域。
4. 等待 `800ms`，让输入框完成聚焦。
5. 执行现有全选与清空逻辑。
6. 以每字符 `100ms` 间隔输入内容。
7. 输入完成后等待 `500ms`，再结束本次输入动作。

现有步骤级倒计时继续负责账号输入、密码输入、登录点击之间的外部间隔。本设计只补足单次输入动作内部的聚焦等待、字符节流和结束等待。

## 实现边界

登录 driver 向共享输入模拟函数显式传入聚焦等待、字符间隔和结束等待。共享函数继续负责串行化、取消检查与紧急停止后的按键释放。其他调用方沿用原有行为，不继承 WeGame 专用延时。

所有等待必须可取消。紧急停止发生时，不得继续输入剩余字符，也不得等待完整延时后才释放按键。

## 错误处理

- 点击、按键或等待被取消 → 沿用现有输入取消错误，登录流程停止。
- 输入模拟失败 → 沿用现有登录步骤失败处理，全面暂停，不重复提交密码。
- 不增加基于固定延时的成功判定；后续步骤仍依赖现有识别区域。

## 测试

- 单元测试先证明登录输入参数为 `800ms / 100ms / 500ms`。
- 输入模拟测试验证点击后不会立即发键，并验证输入结束等待可被取消。
- 运行相关 Rust 单元测试。
- 运行 `bun run check` 全量质量门禁。
