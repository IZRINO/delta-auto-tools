# 特勤处多账号制作自动轮次设计

## 目标

在不执行子弹兑换的前提下，把现有单账号登录、游戏内导航、四制作台批处理、状态持久化和未来 24 小时任务投影串成完整自动化闭环。

调度器发现到期制作任务后创建一轮。每轮按账号顺序登录目标账号，处理该账号全部到期制作台，保存结果，再切换下一账号。账号级故障跳过账号；系统级故障全面暂停。

## 本阶段范围

包含：

- 到期制作任务自动触发。
- 逾期任务在用户点击“继续”后补执行。
- 同账号到期制作台合并为一次登录流程。
- 多账号顺序执行。
- 当前账号结束后暂停。
- 紧急停止、休眠恢复、应用重启恢复。
- 账号级故障隔离与系统级全面暂停。
- 逐台、逐账号权威持久化。
- 操作窗口、进度事件和下一任务时间轴刷新。

不包含：

- 子弹兑换执行器。
- 子弹兑换与制作任务合并执行。
- 手工拖动任务顺序或改期。
- 并行登录或并行操作多个账号。
- 修改现有键鼠操作倒计时规则。

现有子弹业务配置继续保存和展示，但调度器与 round worker 忽略子弹任务。

## 总体架构

新增两个纯编排层，复用现有 runtime：

1. `round_planner`：从持久化设置生成不可变 `RoundPlan`。
2. `round_runner`：按 `RoundPlan` 串行执行账号，调用现有登录、导航和制作 batch。

后台调度器只负责判断“是否需要创建一轮”，不执行键鼠操作。所有键鼠操作仍由单实例 `LoginRuntime` 管理，继续复用操作窗口、紧急停止热键、资源清理和 persistence claim。

不得从前端串联多个 Tauri command。round 必须由单个后端 worker 持有，以保证应用窗口重载、前端事件丢失或 autosave 不会中断编排。

## 数据模型

### RoundPlan

`RoundPlan` 在轮次启动时冻结：

- `roundId`
- `createdAtMs`
- `trigger`: `manual | scheduled | resume`
- `accounts`

每个账号任务包含：

- `accountId`
- `qqAccount`
- `accountOrder`
- 启动时已到期且启用的制作台列表
- 每台冻结的制作时长、配方点击点和 runtime 识别配置

轮次启动后新增到期任务不插入当前轮次，由下一轮处理。这样避免当前轮次执行时间变化导致任务集合漂移。

### 持久化状态

不持久化键鼠步骤断点，不在应用重启后从中间步骤自动重放。

继续持久化：

- 每台实际开始时间与下一完成时间。
- 账号与制作台状态。
- 最后失败步骤、消息和时间。
- 全局暂停状态。

应用异常退出时，现有 active run 恢复规则继续 fail-closed：账号或当前制作台标为 `Uncertain`，应用保持暂停，用户人工校正后才能恢复。

## 轮次状态机

```text
Idle
  -> Planned
  -> AccountLogin
  -> GameNavigation
  -> CraftBatch
  -> PersistAccount
  -> NextAccount
  -> Completed

任一账号级失败：
AccountLogin/GameNavigation TimedOut/CraftBatch
  -> PersistAccountFailure
  -> NextAccount

任一系统级失败：
GameNavigation Paused/任意运行态 SystemFailure
  -> PersistPause
  -> Paused

紧急停止：
任意键鼠运行态
  -> ReleaseInput
  -> PersistUncertain
  -> Paused
```

## 任务选择与排序

调度输入只读取制作任务：

- 账号启用。
- 账号已初始化。
- 账号状态为 `Ready`。
- 制作台业务配置启用。
- 制作台状态不是 `Uncertain`。
- `finishesAtMs <= round.createdAtMs`。

排序固定为：

1. 账号 `order`。
2. 技术中心。
3. 工作台。
4. 制药台。
5. 防具台。

同账号所有符合条件的制作台合并为一个 `AccountRoundTask`。账号间不做 10 分钟视觉分组；时间轴分组只影响展示，不改变执行顺序。

## 单账号执行流程

每个账号执行：

1. 无条件关闭目标 WeGame 实例并重新启动。
2. 从已记住账号列表选择目标 QQ，复制并精确复核。
3. 登录、选择置顶游戏、启动游戏。
4. 执行现有游戏内导航，进入四制作台页面。`game.modeReady` 双采样命中后先按全局 `navigationBeaconDelayMs` 固定等待，再点击 `game.beaconMode`；默认 `3000ms`，UI 范围 `0–60000ms`。该等待只解决切号后模式选择页面尚未可交互的竞态条件，不新增中间识别、不改点击点。
5. 调用现有四制作台 batch，处理本账号冻结的全部到期台。
6. 每台重做成功后立即保存实际开始时间和下一完成时间。
7. 保存账号最新状态和失败信息。
8. 释放本账号占用的进程与键鼠资源。
9. 检查暂停请求；未暂停则进入下一账号。

不得因后一制作台失败回滚前一制作台已持久化的完成时间。

## 暂停与继续

### 用户暂停

运行中点击暂停只设置 `pauseRequested`，不打断当前账号。当前账号流程结束后：

- 持久化 `paused = true`。
- 不切换下一账号。
- 未执行账号任务回到调度队列，显示为逾期。

未运行时点击暂停立即持久化。

### 用户继续

点击继续：

- 重新读取当前持久化状态。
- 重新计算逾期制作任务。
- 创建新的 `resume` 轮次。
- 同账号逾期制作台再次合并。

不得复用暂停或休眠前冻结的游戏会话。

### 休眠与时钟跳变

后台调度器使用单调时钟检测休眠/长时间跳变。检测后：

- 设置暂停。
- 不自动登录或关闭程序。
- 汇总逾期任务并提示。
- 等待用户点击继续。

## 故障分类

### 账号级故障：标记并继续下一账号

- 已记住账号列表找不到目标 QQ：`NeedsManualLogin`。
- 登录提交失败：`LoginFailed`。
- 游戏内导航步骤耗尽三分钟预算：账号 `Uncertain`，不修改任一制作台。
- 制作状态、配方选择、生产确认或仓库空间异常：账号及相关制作台 `Uncertain` 或 `Isolated`。
- 单账号游戏首次崩溃后重开仍无法完成，但 WeGame 与全局环境仍健康：记录账号失败并继续。

账号级故障不得重试提交密码，也不得自动重跑当前账号。

### 系统级故障：全面暂停

- WeGame 无法启动或连续崩溃。
- 游戏连续崩溃且无法恢复。
- 校准环境失效。
- 游戏内导航的窗口、截图、输入或 runtime 步骤执行错误。
- operation window、紧急停止、输入释放或权威持久化失败。
- runtime 内部状态损坏。

系统级故障必须停止当前轮次、释放输入、保存暂停状态并等待人工处理。

## 自动调度

应用内部启动单个轻量 scheduler：

- 未暂停、总开关开启、无 active run 时读取 `build_schedule`。
- 只关注 `dueAccounts[].stationKinds`，忽略 `ammoTargetIds`。
- 有到期制作任务时创建一轮。
- 无到期任务时等待 `nextWakeAtMs` 或设置变更事件。
- 设置保存、任务完成、人工校正、暂停/继续后唤醒重新计算。

scheduler 不使用固定高频轮询。等待必须可被设置变更、应用关闭和紧急停止唤醒。

## 前端与事件

新增一个“开始当前到期轮次”入口用于实机测试；正式自动调度与该入口共用同一 planner/runner。

操作窗口显示：

- 当前轮次进度：账号序号/总账号数。
- 当前 QQ。
- 当前阶段：登录、导航、制作台。
- 当前制作台序号/本账号制作台总数。
- 紧急停止快捷键。

不新增暂停按钮到操作窗口。主页面暂停按钮只登记 `pauseRequested`。

时间轴继续显示原计划时间。任务执行成功后刷新为下一完成时间；失败或隔离后保留状态标记。

## 并发与持久化约束

- 同时只能存在一个 special_ops run。
- round 启动、逐台成功、账号失败、暂停请求和最终清理都通过 `SettingsCoordinator` revision 临界区。
- 每次成功重做先持久化，再继续下一台或下一账号。
- active run 清空前禁止保存配置、校准、模板测试和启动新轮次。
- worker 完成权威持久化 claim 后才能清理 operation window、热键和 runtime。
- 旧 worker 的事件、持久化或 cleanup 不得影响新轮次。

## 测试策略

### 纯 Rust 单元测试

- planner 只选到期、Ready、启用任务。
- 同账号任务合并，账号和制作台排序稳定。
- 轮次启动后新增到期任务不插入当前轮次。
- 账号失败继续下一账号。
- 系统失败停止全轮并暂停。
- 暂停请求在当前账号完成后生效。
- 紧急停止标记当前账号不确定并停止后续账号。
- 前一台已持久化结果不因后一台失败回滚。
- scheduler 忽略子弹任务。
- scheduler 不重复启动 active round。
- 休眠跳变转暂停，不自动执行。

### 前端测试

- 手动轮次按钮使用新 command。
- active run 期间禁止重复启动。
- round snapshot 正确显示账号和制作台进度。
- 暂停按钮在 active round 中显示“当前账号结束后暂停”。

### 验证

- 定向 Rust/前端测试。
- `bun run build`。
- `cargo check`。
- `bun run check`。
- `git diff --check`。
- 实机使用至少两个账号：一账号多台到期、另一账号单台到期；覆盖账号失败继续与当前账号结束后暂停。

## 完成标准

- 制作任务到期后可自动创建多账号轮次。
- 每账号只登录一次并处理其全部到期制作台。
- 账号级失败不会阻断其他账号。
- 系统级失败全面暂停。
- 暂停在当前账号结束后生效。
- 紧急停止立即释放输入并阻止自动重跑。
- 休眠、重启不会自动接管电脑。
- 子弹兑换未进入执行链。
- 全量质量门禁通过，并完成双账号实机验收。

## 后续跨功能扩展（2026-08-05）

本设计原始范围只覆盖制作轮次；当前实现已接入子弹兑换。以下规则覆盖本文中“任一账号级失败”对可定位子弹异常的泛化描述：

- `AccountFailure.stationKind` / `ammoTargetId` 互斥定位制作台或子弹，`AmmoTarget.lastFailure` 保存子弹目标级人工失败。
- 制作异常仍阻断账号；可定位子弹补齐、购买、确认或完成异常只冻结当前目标，账号保持 `Ready`，当前账号本轮结束后继续下一账号。
- 24 小时时间轴通过 `TimelineTask.manualFailure` 在失败任务行提供单项判定；旧版无定位失败继续走账号页完整人工校正。
- `special_ops_confirm_station_state` 与 `special_ops_confirm_ammo_state` 只改目标任务；`special_ops_confirm_account_station_states` 继续一次原子恢复四制作台和全部启用子弹。
