# 游戏内导航固定时间动作设计

## 目标

将游戏内导航试运行中的活动弹窗、大厅视角切换和特勤处入口操作从模板识别触发改为固定等待时间触发，删除这些步骤的运行期识别依赖。导航 run 首个键鼠操作块显示 5、4、3、2、1；后续原本需要提示的块只显示 1，固定等待本身不倒计时。

## 范围

本次只修改 `special_ops` 游戏内导航试运行、对应全局设置及校准列表 UI。不修改登录试运行、制作试运行、多账号 round 或子弹兑换。

## 导航状态机

导航试运行按以下固定顺序执行：

1. 对 `game.modeReady` 执行模板双采样，确认模式选择可用。
2. 聚焦游戏窗口，点击 `game.beaconMode` 点击点。
3. 等待 `navigationSpaceDelayMs`，聚焦游戏窗口，按 `Space`。
4. 等待 `navigationTabDelayMs`，聚焦游戏窗口，按 `Tab`。
5. 等待 `navigationSpecialOpsDelayMs`，聚焦游戏窗口，点击 `game.specialOps` 点击点。
6. 对 `game.stationGrid` 执行模板双采样，确认四制作台页面已出现；命中后试运行成功。

删除原有“等待活动弹窗或开始游戏”分支。`Space`、`Tab` 和特勤处点击前不再执行模板守卫。每次输入前仍重新查找、恢复并聚焦 canonical 游戏窗口；聚焦失败时不得发送输入。

## 时间配置

在 `SpecialOpsSettings` 新增三个全局字段：

| 字段 | 含义 | 默认值 |
|------|------|--------|
| `navigationSpaceDelayMs` | 点击烽火地带后，按 `Space` 前的等待时间 | `3000` |
| `navigationTabDelayMs` | 按 `Space` 后，按 `Tab` 前的等待时间 | `3000` |
| `navigationSpecialOpsDelayMs` | 按 `Tab` 后，点击特勤处前的等待时间 | `3000` |

三个字段只允许 `0–60000` 范围内的整数，单位为毫秒。`0` 表示立即执行。旧配置缺少字段时补默认值 `3000`。启动试运行时冻结三个值；运行中修改只影响下一次试运行。

固定等待必须支持取消。等待期间沿用 50ms 取消轮询，普通取消或紧急停止生效后不得执行后续动作。

## 校准目标迁移

- `game.modeReady` 保持模板识别区域。
- `game.beaconMode` 保持点击点。
- `game.activityPopup` 从默认目标、导航 preflight 和 runtime config 删除。
- `game.startGame` 从默认目标、导航 preflight 和 runtime config 删除。
- `game.specialOps` 从模板识别区域改为点击点。加载旧配置时清除旧矩形、参考图、验证签名和验证时间，要求用户重新点选。
- `game.stationGrid` 保持模板识别区域。

## UI

三个时间输入不放在“全局配置”卡片，放在“点击区域校准”流程列表中，并按实际导航顺序排列：

1. 模式选择可用状态识别区域 `game.modeReady`
2. 烽火地带入口点击点 `game.beaconMode`
3. 跳过活动弹窗等待时间：编辑 `navigationSpaceDelayMs`
4. 切换大厅视角等待时间：编辑 `navigationTabDelayMs`
5. 特勤处入口点击点 `game.specialOps`，同一行编辑 `navigationSpecialOpsDelayMs`
6. 四制作台页面识别区域 `game.stationGrid`

第 3、4 项是时间配置行，不提供框选、参考图或测试按钮。第 5 项同时提供点击点框选和时间输入。字段仍属于全局 `SpecialOpsSettings`，不属于账号或校准目标。

输入框显示单位 `ms`。空值、小数、负数或大于 `60000` 的值不得持久化，并在当前配置区域显示明确错误。

## 运行态与错误处理

- 导航试运行在首个键鼠操作块前发布 5、4、3、2、1 秒 `Countdown`；后续原本需要提示的操作块只发布 1 秒。
- 固定等待期间 operation window 显示当前等待动作，不把等待误标为识别。
- `game.modeReady` 或 `game.stationGrid` 识别超时沿用导航步骤失败与全局暂停逻辑。
- `game.specialOps` 点击点未校准时，preflight 拒绝启动。
- 游戏窗口查找、恢复或聚焦失败时，当前步骤失败且不得盲操作。
- 普通取消与紧急停止沿用现有单实例 runtime、输入释放、持久化和资源清理规则。

## 测试

Rust 测试覆盖：

- 固定动作顺序为点击烽火地带、`Space`、`Tab`、点击特勤处。
- 三段等待分别使用冻结的配置值。
- `0ms` 允许立即推进。
- 固定等待期间取消后不执行下一动作。
- 导航流程按 run 级规则发布倒计时；固定等待不发布倒计时。
- preflight 只要求 `game.modeReady`、`game.beaconMode`、`game.specialOps`、`game.stationGrid`。
- 旧配置删除 `game.activityPopup`、`game.startGame`，并把 `game.specialOps` 迁移为待重新校准的点击点。
- 三个时间字段的默认值、整数要求及范围校验。

前端测试覆盖：

- 三个时间输入按流程顺序出现在校准列表。
- 第 3、4 项不显示框选、参考图或测试按钮。
- 特勤处点击点行同时显示框选和等待时间。
- 非法输入显示错误且不进入保存请求。
- active run 期间时间输入与校准操作保持禁用。

最终运行 `bun run check`，并由用户在真实游戏中验证固定等待节奏、operation window 文案、取消和紧急停止。
