# 游戏内导航试运行设计

## 范围

登录试运行仍以指定游戏 PID/HWND 出现为成功。新增独立“游戏内导航试运行”，直接使用当前已打开游戏，不结束或启动游戏、不操作 WeGame，成功门槛为四制作台页面 `game.stationGrid` 连续双采样命中。

账号下四制作台删除“制作物品”输入框，只保留启用开关、小时、分钟和状态。持久化结构中的 `itemName` 暂时保留为空兼容字段，避免破坏旧配置；运行时按每台已校准的置顶配方区域操作，不依赖物品名称。

## 导航状态机

1. 按 canonical 完整路径查找并聚焦游戏窗口。
2. 等待 `game.modeReady` 连续双采样命中。
3. 再次确认 `game.modeReady` 连续双采样命中后，点击 `game.beaconMode` 点击点。
4. 同时观察 `game.activityPopup` 与 `game.startGame`：活动弹窗先出现则按一次空格，之后只等待 `game.startGame`；直接出现 `game.startGame` 时跳过空格。
5. 聚焦游戏窗口并按一次 `Tab`。
6. 等待 `game.specialOps` 连续双采样命中，校验自身模板后点击。
7. 等待 `game.stationGrid` 连续双采样命中并结束试运行。

每步最长 3 分钟。识别不一致时继续采样，不点击、不更新持久化状态。窗口缺失、截图失败、参考图失败或输入失败时全面暂停试运行。紧急停止沿用现有 operation window、运行期热键和输入释放机制。

## 烽火地带入口校准

- `game.beaconMode` 从 `RecognitionRegion` 改为 `ClickPoint`，UI 文案改为“烽火地带入口点击点”。
- 点击点不上传参考图、不执行自身模板测试；点击前守卫固定使用 `game.modeReady`。
- 校准 overlay 对点击点采用单击立即保存 `1×1` 坐标；识别区域继续使用拖拽框选。后端按目标类型分别校验提交尺寸。
- 导航预检要求 5 个已验证模板：`game.modeReady`、`game.activityPopup`、`game.startGame`、`game.specialOps`、`game.stationGrid`，以及 1 个已框选点击点 `game.beaconMode`。
- 加载旧配置时发现 `game.beaconMode` 仍是识别区域，则清除旧矩形、参考图与验证结果，要求用户重新点击校准。禁止把旧识别区域中心静默当作点击点。

## 边界

- 导航试运行不读写制作计时、子弹当天状态或账号登录状态。
- 导航试运行不处理收取、补齐、生产或账号切换。
- 当前只有一个特勤处 operation run；登录试运行或导航试运行运行中，另一试运行不得启动。
- `game.modeReady` 未命中时不得点击 `game.beaconMode`；点击后仍以活动弹窗或“开始游戏”模板作为状态推进条件。
- 现场验证通过后，后续制作执行器从同一 `game.stationGrid` 成功状态进入。

## 测试

- 纯状态机测试覆盖无活动弹窗、存在活动弹窗、单步超时和取消。
- 输入层测试覆盖 `Space`、`Tab` 成对按下/释放及取消时释放。
- 校准测试覆盖 `game.beaconMode` 默认类型、旧识别区域迁移清空、点击前复用 `game.modeReady` 守卫，以及预检不再要求入口参考图。
- 前端测试覆盖制作台不再渲染物品名称输入框、导航试运行命令参数与运行中互斥。
