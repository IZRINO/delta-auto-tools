## 目标与边界

本设计只覆盖从一个目标 QQ 账号开始，到《三角洲行动》游戏进程与窗口已出现为止的登录切号流程。制作、子弹兑换、调度与崩溃恢复由后续独立设计承接。

首版优先保证每次处理目标账号前都建立新的 WeGame 会话，不使用 WeGame 内的切换账号菜单，不复用旧登录会话。

## 已排除

- 不读取或比对 WeGame ID、游戏 ID 或 UID。
- 不以密码作为账号身份依据；不同账号允许使用相同密码。
- 不使用 WeGame 内「切换账号」菜单。
- 不最大化 WeGame，不对旧坐标静默缩放。
- 不内置 WeGame 或游戏 UI 参考图。
- 不搜索或滚动 WeGame 游戏列表。
- 不自动判断密码错误、验证码、风控或网络异常的具体原因。
- 不重复提交同一账号的登录请求。

## 配置模型

全局业务配置增加：

- `wegameExecutablePath`：用户通过文件选择器指定的 `WeGame.exe` 绝对路径。
- `gameExecutablePath`：用户通过文件选择器指定的游戏 `.exe` 绝对路径。

账号配置保留：

- `qqAccount`：目标 QQ 账号，所有参与执行的账号必须唯一。
- `password`：对应 QQ 密码，按已确认需求明文保存。

配置页必须提示用户先在 WeGame 中将《三角洲行动》置顶。流程只识别置顶后的固定游戏条目。

## 校准项

静态 UI 识别目标分别配置框选区域和用户上传的参考图；纯输入区域只保存坐标，并由已命中的识别目标守卫：

1. `wegame.loginMode`：QQ 账号密码登录入口；当登录表单已出现时跳过。
2. `wegame.loginFormReady`：QQ 账号密码表单就绪。
3. `wegame.account`：QQ 账号输入区域，不上传参考图，由 `wegame.loginFormReady` 守卫。
4. `wegame.password`：QQ 密码输入区域，不上传参考图，由 `wegame.loginFormReady` 守卫。
5. `wegame.login`：登录按钮识别与点击区域。
6. `wegame.gameEntry`：置顶的《三角洲行动》条目识别与点击区域。
7. `wegame.launch`：选中游戏后出现的启动按钮识别与点击区域。

旧版登录成功分类、身份读取、头像/主页和会话内切号校准项全部删除；加载旧配置时按当前 7 项登录契约重建，不复制旧坐标。

## 状态机

1. canonicalize `gameExecutablePath`，按完整路径定位并结束所有精确匹配的当前游戏进程；不递归结束进程树。
2. 等待 native 进程检查确认游戏进程已消失。
3. canonicalize `wegameExecutablePath`，按完整路径定位并强制结束所有精确匹配的 WeGame 进程；同名不同目录进程不匹配。
4. 等待 native 进程检查确认 WeGame 进程已消失。
5. 检查 `wegameExecutablePath` 存在后启动 WeGame。
6. 等待 `wegame.loginFormReady` 或 `wegame.loginMode` 连续两次命中。
7. 若 `wegame.loginFormReady` 已命中，直接进入输入步骤；否则点击 `wegame.loginMode`，再等待 `wegame.loginFormReady`。
8. 在 `wegame.loginFormReady` 守卫下，清空账号输入区并输入目标 `qqAccount`。
9. 再次确认 `wegame.loginFormReady`，清空密码输入区并输入对应 `password`。
10. `wegame.login` 连续两次命中后只点击一次。
11. 等待 `wegame.gameEntry` 连续两次命中，将其作为本次登录已进入游戏列表的唯一正向后置信号。
12. 点击 `wegame.gameEntry`，等待 `wegame.launch` 连续两次命中。
13. 点击 `wegame.launch`。
14. 通过 native 进程与窗口检查，确认 `gameExecutablePath` 对应游戏进程和游戏窗口已出现。

游戏进程与窗口确认成功后，登录切号状态机结束，由后续游戏内导航状态机接管。

## 识别契约

- 模板识别要求连续两次结果都达到默认阈值 `0.75`，采样间隔固定为 `400ms`。
- 两次结果不一致时继续重新采样，不点击、不输入、不更新持久化状态。
- 每个静态 UI 识别目标都必须同时具备框选区域、用户参考图和可用参考图文件。
- 每个静态 UI 识别目标都提供独立双采样测试；输入区域不提供模板测试。
- 测试通过后保存验证签名。签名绑定目标 key、区域、参考图 canonical 路径、文件长度与修改时间、阈值；重新框选、换图、清图、图片变化或阈值变化后必须重新测试。
- 进程存在、进程消失、可执行文件路径与窗口存在使用 native 状态，不上传图片代替。
- 不以固定等待时间作为成功判定。

## 超时与失败

- 每个独立步骤的等待上限为 180 秒。
- 180 秒内持续采样并等待真实后置状态，不因时间到达而伪造成功。
- 任一步骤超时、路径失效、进程无法结束、进程无法启动或窗口无法出现时，全面暂停。
- 暂停后立即停止后续输入，保留失败步骤、最后识别结果和错误时间，不继续下一账号。
- 登录按钮已点击但 `wegame.gameEntry` 未命中时，不推断具体原因，不再次提交密码。

## 预检查

试运行或真实执行前必须同时满足：

- `wegameExecutablePath` 与 `gameExecutablePath` 非空，两个文件存在且扩展名为 `.exe`。
- 存在一个用户选定的启用账号。
- 所选账号具备非空 QQ 账号与密码。
- 所有参与执行的 QQ 账号唯一；密码允许相同。
- 所有必需静态 UI 识别目标具备框选区域和存在的用户参考图文件；账号与密码输入区域已框选。
- 配置页明确提示用户将《三角洲行动》置顶。

## 试运行与测试

单账号试运行执行完整登录切号状态机，包含结束旧游戏与 WeGame 进程、重新登录、选择《三角洲行动》和启动游戏。它在游戏进程与窗口确认成功后结束，不进入制作或兑换操作。

运行入口为 `special_ops_start_login_trial`，普通取消为 `special_ops_cancel_login_trial`，紧急停止为 `special_ops_emergency_stop`。单实例 runtime 通过 `special-ops://run-changed` 向主窗口与 `special-ops-operation` window 推送无密码的 `LoginRunSnapshot`。operation window 无按钮、点击穿透且不抢焦点；每次键鼠输入前显示 3/2/1 倒计时。登录按钮每次 run 只提交一次。紧急停止立即取消输入、释放已注入按键，并把账号持久化为 `Uncertain`。

自动化启动门禁：

- 每个必需静态 UI 识别目标已通过独立双采样测试。
- 至少一个用户选定账号已通过完整登录切号试运行。
- 未通过试运行前，不得解锁多账号自动流程。

当前实现只交付上述单账号登录试运行。多账号 round、制作、购买、收取和子弹兑换仍属于后续阶段。

## 与后续子系统的接口

登录切号状态机只输出以下结果：

- `GameReady { accountId, qqAccount, gameProcessId, gameWindowHandle }`
- `Paused { failedStep, lastObservation, failedAt }`
- `EmergencyStopped { accountId, stoppedAt }`

`GameReady` 是后续游戏内导航与制作流程的唯一正常入口。登录切号模块不读写制作计时和子弹当天状态。
