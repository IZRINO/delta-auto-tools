# 特勤处运行期窗口仲裁设计

> 状态：已确认；进入代码实现。

## 目标

特勤处登录试运行、游戏内导航试运行以及后续制作/兑换执行器进行键鼠输入或屏幕识别时，隐藏本应用其他功能窗口，避免窗口内容进入屏幕截图并遮挡目标 UI。纯计时等待不触发窗口仲裁。

## 范围

- 触发时机：特勤处 run 进入首个键鼠动作或模板/OCR 采样前。
- 作用对象：启动时可见的其他功能窗口，包括计时器/计数器/连发器显示窗口及其他工具窗口。
- 保留对象：主窗口与 `special-ops-operation` 操作提示窗口。多屏环境中主窗口不得隐藏、最小化或临时置顶。
- 不变对象：其他工具运行态、计时逻辑、热键、watcher、配置和持久化数据。
- 恢复时机：特勤处 run 成功、失败、普通取消、紧急停止、生命周期停止及启动回滚后。

## 交互冲突

若区域框选、位置选择或其他需要用户点击桌面的 overlay 正在运行，特勤处 run 拒绝启动并报告存在未结束的交互。执行器不静默隐藏这类窗口，避免 pending selection session 与目标游戏输入竞争。

## 数据流

1. 特勤处启动资源锁内枚举应用窗口，记录每个当前可见且不是主窗口、操作提示窗口的 label。
2. 隐藏记录窗口；不关闭、不销毁，不改变任何工具模块状态。
3. 创建并保留 `special-ops-operation`，开始 run。
4. 所有退出路径先释放已注入按键、注销紧急热键并销毁操作提示窗口，再逐个恢复快照中仍存在的窗口。
5. 窗口在运行期被用户关闭或被所属模块销毁时，恢复阶段跳过该 label；不得重建窗口或覆盖模块当前状态。

## 错误处理

- 快照或隐藏任一窗口失败：回滚已隐藏窗口，拒绝启动特勤处 run，不发送键鼠输入。
- 恢复单个窗口失败：继续恢复其余窗口，记录中文错误日志；run 结果保持原结果，避免把业务成功误标为失败。
- 纯计时等待：保持当前窗口可见状态；下一次实际键鼠/识图片段前若尚未仲裁，再执行一次快照与隐藏。

## 测试

- 单元测试：窗口快照过滤主窗口和操作提示窗口；隐藏集只包含启动时可见的其他功能窗口；恢复只恢复仍存在的原窗口；隐藏失败触发反向恢复。
- runtime 测试：登录与导航启动失败、普通取消、紧急停止均执行窗口恢复；纯等待分支不隐藏窗口。
- 现场测试：开启计时器/计数器/连发器显示和主窗口后启动试运行，确认其他功能窗口隐藏、主窗口留在原显示器且不最小化，截图模板不受遮挡；结束后仅恢复启动前可见的其他功能窗口。
