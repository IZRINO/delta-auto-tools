# 制作台固定动作状态探测设计

## 目标

删除制作台入口对奖励页、制作中共享参考图和制作列表就绪页的识别。改用固定动作序列进入稳定页面，再以 `craft.abort` 一次性双采样区分“正在制作”和“制作列表”。

## 固定动作状态机

单台流程进入四制作台页面后执行：

1. 直接点击当前制作台。
2. 等待“收取点击后按 Space 等待”配置时间，按 `Space`。
3. 等待“Space 后再次点击制作台等待”配置时间，再次点击当前制作台。
4. 等待“再次点击后确认置顶等待”配置时间，点击四台共用的“确认置顶点击点”。
5. 对 `craft.abort` 执行一次双采样，两次采样间隔 400ms。

步骤 1–5 属于连续状态探测段，不执行点击前模板复核。run 首个键鼠输入前显示 `5→4→3→2→1`；该输入之后，探测段内原本不提示的后续输入继续不提示。每次输入仍检查取消状态、重新查找并聚焦游戏窗口，输入后将鼠标移至 `runtime.mouseParking`。

### 正在制作

`craft.abort` 两次均达到 threshold 时：

1. 直接点击 `craft.returnToStationGrid`“制作中返回点击点”，不执行通用倒计时，也不发送 `Esc`。
2. 点击后将鼠标移至 `runtime.mouseParking`，等待现有 `game.stationGrid` 双采样命中，确认已返回四制作台页面。
3. 当前台返回 `StillInProgress`，不修改开始时间或完成时间。

### 制作列表

`craft.abort` 两次均低于 threshold 时，视为当前处于制作列表：

1. 恢复 run 级倒计时：后续原本需要提示的操作块只显示 `1`。
2. 点击当前台 `craft.recipe.<station>`“制作物品选择点击点”。
3. 同时识别 `craft.produce` 与 `craft.fill`。
4. 生产按钮命中时继续生产；一键补齐命中时继续补齐、购买和生产流程。
5. 最终识别 `craft.abort`，以确认时间记录实际开始时间并计算完成时间。

置顶配方功能分为两个不同点击点：固定探测段使用一个四台共用的“确认置顶点击点”；判定为制作列表后，使用四个按制作台独立保存的“制作物品选择点击点”，因为各台目标物品位置可能不同。

### 无法归类

`craft.abort` 一高一低、截图失败、参考图读取失败或取消时，不得降级为制作列表，不点击制作物品，也不继续生产。由于固定探测段已经发生输入，账号及当前制作台标记为 `Uncertain`。

返回点击失败或 `game.stationGrid` 返回确认超时同样标记 `Uncertain`。

## 固定等待配置

新增三个全局整数配置：

| UI 文案 | 持久化字段 | 默认值 | 范围 |
|---|---|---:|---:|
| 收取点击后按 Space 等待 | `craftSpaceDelayMs` | 3000ms | 0–60000ms |
| Space 后再次点击制作台等待 | `craftReopenDelayMs` | 3000ms | 0–60000ms |
| 再次点击后确认置顶等待 | `craftConfirmPinnedDelayMs` | 3000ms | 0–60000ms |

三项按显示环境全局共享，不按账号保存。UI 放在点击区域校准流程对应步骤旁。

## 校准项变更

新增：

- `craft.confirmPinned`：四台共用“确认置顶点击点”，类型为 `clickPoint`。
- `craft.returnToStationGrid`：四台共用“制作中返回点击点”，类型为 `clickPoint`。

保留：

- 四个 `craft.station.<station>` 制作台点击点。
- 四个 `craft.recipe.<station>`，UI 改名为“制作物品选择点击点”。
- `craft.abort`、`craft.produce`、`craft.fill`、`craft.purchase`。
- `game.stationGrid`。

删除：

- `craftInProgressReferenceImagePath`。
- `craftInProgressMatchThreshold`。
- 四个 `craft.inProgress.<station>`。
- 四个 `craft.recipeListReady.<station>`。
- `craft.reward`。

旧配置加载时清理废弃 target；旧共享制作中图片路径和 threshold 不再进入前后端类型及保存结果。用户无需手工清理配置文件。

## Preflight

单台制作试运行要求：

- 当前台 `craft.station.<station>` 点击点。
- `craft.confirmPinned` 点击点。
- `craft.returnToStationGrid` 点击点。
- 当前台 `craft.recipe.<station>` 点击点。
- `craft.abort`、`craft.produce`、`craft.fill`、`craft.purchase` 模板与区域。
- `game.stationGrid` 模板与区域。
- 三项固定等待均为 `0–60000ms` 整数。

Preflight 不再要求奖励页、制作中或制作列表就绪相关配置。

## 失败规则

- 第一次输入前失败：普通失败，不修改制作台业务状态。
- 第一次输入后失败：账号及当前台标记 `Uncertain`。
- 普通取消、紧急停止、应用生命周期停止及持久化 claim 规则保持现状。
- 固定探测段不新增点击重试；每个动作只执行一次，避免重复收取或错误页面连点。

## 测试

Rust 测试覆盖：

1. 制作中：固定动作序列、`abort` 命中、`craft.returnToStationGrid` 点击、`stationGrid`、零 Esc 输入、零生产点击。
2. 制作列表：固定动作序列、`abort` 两次低分、当前台物品选择、生产/补齐分支。
3. `abort` 一高一低或采样错误：停止且不点击制作物品。
4. 三项等待默认值、边界和越界拒绝。
5. 旧校准项清理、新 `craft.confirmPinned` 与 `craft.returnToStationGrid` preflight。
6. 前端校准列表删去废弃项，保留四个制作物品选择点，并显示三个等待输入。

实机验收分别使用正在制作制作台与可进入制作列表的制作台。制作中路径必须点击“制作中返回点击点”返回四制作台页面；制作列表路径必须选中当前台配置物品并进入生产或补齐流程。

## 非目标

- 本阶段不实现四台批处理、多账号 round 或子弹兑换。
- 不改补齐、购买、生产和制作完成时间算法。
- 不新增奖励页、空闲中或制作列表 fallback 识别。
