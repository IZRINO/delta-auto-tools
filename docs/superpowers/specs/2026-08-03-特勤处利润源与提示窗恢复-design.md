# 特勤处利润源与提示窗恢复设计

## 背景

当前存在三个彼此独立的问题：

1. KKRB 名称目录接口可返回 HTTP 200 与业务码 `-101`，表示服务端繁忙。
2. Moligod 隐藏 WebView 销毁后，WebView2 可能继续占用独立数据目录；同步删除目录会得到 Windows `os error 32`，并错误覆盖已取得的查询结果。
3. 轮次启动把操作提示窗的前端页面加载限定为 3 秒。超时会使 `LaunchRound` 返回错误，scheduler 把正常待执行任务全局暂停。

## 决策

### KKRB

不伪造目录结果，也不无限重试服务端 `-101`。名称目录继续最多请求三次，每次间隔一秒。失败时保留当前已加载目录，前端提示用户可直接填写并保存 `KKRB 精确名称`；该输入框继续只把目录作为 datalist 建议，不依赖目录才能保存规则。

### Moligod

WebView 查询结果、窗口销毁结果与临时目录清理拆开处理：

- 隐藏窗口销毁失败仍视为查询失败。
- 已取到的查询结果不得被临时目录清理失败覆盖。
- 目录清理由后台执行有限时间的重试；最终失败只记录 warning，不向利润验证、调度或 UI 返回 `os error 32`。
- 不修改查询的网页访问权限、解析逻辑或利润规则。

### 操作提示窗

采用已确认的 B 方案：

- 操作提示窗页面加载超时前，不创建 worker、不发送键鼠输入。
- scheduler 保持 armed，保留原到期任务，等待一秒后重新尝试启动该轮次。
- 页面加载成功后才交给 worker；既有首个键鼠操作前 5 秒倒计时不变。
- 普通系统级启动、窗口创建、热键注册、持久化或 worker 故障仍全局暂停；只有“操作提示窗页面加载超时”可重试。
- 操作提示窗挂载时主动读取权威 `runSnapshot`，避免运行状态事件早于前端 listener 注册而丢失。

## 测试边界

- scheduler 测试覆盖可重试启动：不暂停、等待一秒、再次尝试。
- Moligod 测试覆盖清理失败不覆盖已得到的查询结果，以及销毁失败仍返回失败。
- 前端测试覆盖 KKRB 繁忙提示包含手动填写路径，以及操作提示窗的首次权威状态回读。

## 非目标

- 不尝试绕过或修复 KKRB 服务端负载。
- 不增加新的利润数据源、缓存格式、持久化字段或 Tauri command。
- 不改变到期任务、子弹兑换和利润判定规则。
