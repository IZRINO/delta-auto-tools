# 制作试运行取消与收尾设计

> 后续修订：普通取消在已经进入制作键鼠输入后，状态处理以 `2026-07-28-特勤处识图停放与停止可靠性-design.md` 为准；本文件“不标记状态不确定”的旧约束只适用于首次输入前取消。

## 目标

解决两个关联问题：

1. 点击生产后，提示长期停留在“正在执行游戏点击”，无法区分点击阻塞与中止按钮识别等待。
2. 模板截图或匹配单次调用未返回时，普通取消只能设置取消标志，worker 无法及时进入资源清理，operation window 长期显示“正在取消登录试运行”。

## 设计

### 制作开始确认阶段

生产点击返回后、等待 `craft.abort` 前，runtime 发布新的 Waiting 状态：

```text
正在确认制作已开始
```

该状态只说明执行器正在等待 `craft.abort` 连续双采样，不提前宣告生产成功。`craft.abort` 双采样成功后才记录实际开始时间并保存下一次完成时间。

### 可取消模板采样

`template_observer` 增加统一的单次可取消采样边界。每次等待模板相似度时，同时等待：

- 当前 `SimilaritySampler::sample` 完成；
- 取消标志变为 `true`。

取消检查间隔沿用 50ms。取消先发生时立即返回“模板识别已取消”，上层 worker 进入现有停止与资源清理路径。被放弃的截图/NCC `spawn_blocking` 任务只读屏幕和参考图，不执行键鼠操作、不写业务状态；任务稍后自行结束。

所有循环模板等待统一使用该边界，包括：

- 单目标连续双采样；
- 多目标连续双采样；
- 制作台初始状态的一次性双采样。

不得在取消 command 中提前移除 active run，也不得允许旧 worker 与新 run 并行。operation window、紧急热键和其他工具窗口仍由 worker 的既有清理路径统一释放和恢复。

## 错误处理

- 普通取消：采样最多延迟约 50ms 感知取消；worker 返回 Stopped 并清理资源。
- 截图/NCC 正常报错：保留原错误，不伪装成取消。
- 点击生产后未识别 `craft.abort`：持续显示“正在确认制作已开始”，允许用户普通取消或紧急停止。
- 不给生产确认增加固定超时，避免机器负载或游戏网络延迟导致误判。

## 测试

1. 阻塞中的单目标采样收到取消后及时返回。
2. 阻塞中的多目标采样收到取消后及时返回。
3. 一次性制作台状态采样收到取消后及时返回。
4. 生产点击完成后、等待 `craft.abort` 前发布“正在确认制作已开始”。
5. 现有制作状态分流、取消、资源清理及全量质量门禁继续通过。

## 非目标

- 不改变紧急停止语义。
- 首次制作键鼠输入前的普通取消不把账号标记为状态不确定。
- 不增加固定生产确认超时。
- 不修改制作完成时间计算或持久化结构。
