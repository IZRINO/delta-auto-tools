# 特勤处默认业务配置与人工校正设计

## 目标

本阶段解决两个直接阻塞多账号调度的问题：

1. 账号业务配置重复。新增一套默认业务配置；账号默认继承，仅在显式开启“独立设置”后维护自身配置。
2. `Uncertain` 账号没有安全恢复入口。新增账号级四制作台人工校正，要求逐台确认实际状态并一次原子保存。

本阶段不实现滚动 24 小时任务日历、多账号 round 或子弹兑换执行器。日历另立规格；本阶段只提供日历后续需要的权威业务配置与运行态数据。

## 核心边界

- 默认配置与账号独立配置只保存业务意图，不保存运行结果。
- 制作完成时间、制作台状态、账号状态、失败记录、当天子弹兑换状态始终按账号保存。
- 账号关闭独立设置后，独立业务配置永久删除；运行态不删除。
- 人工校正只改当前账号运行态，不改默认业务配置或账号独立业务配置。
- active run 期间禁止修改默认配置、独立设置或人工校正，避免冻结配置与持久化结果竞态。

## 数据模型

### 默认业务配置

`SpecialOpsSettings` 新增 `defaultBusinessConfig`，包含：

- 四制作台业务配置：`kind`、`enabled`、`durationMinutes`。四台默认全部启用。
- 四制作台默认“制作物品选择点击点”。逻辑上属于默认业务配置；底层可继续复用现有全局 `craft.recipe.<station>` 点击点，避免复制完整校准环境。
- 有序子弹目标配置：稳定目标 ID、名称、启用状态、普通/赛季类型、顺序、相对滚轮步数。

默认业务配置不包含：

- `startedAtMs`、`finishesAtMs`、制作台当前状态。
- 账号状态、失败记录。
- 子弹当天成功日期、重试次数或失败状态。

### 账号独立业务配置

`AccountPlan` 新增：

- `independentSettingsEnabled: bool`，新账号默认 `false`。
- `independentBusinessConfig: Option<AccountBusinessConfig>`。

独立业务配置包含四制作台启用状态、时长、四个账号级制作物品选择点击点和有序子弹目标配置。独立设置关闭时该字段必须为 `null`；不能保留隐藏草稿。

### 账号运行态

每个账号继续独立保存：

- 四制作台 `startedAtMs`、`finishesAtMs`、`status`。
- 当前计时来源：`automatic` 或 `manual`。
- 账号 `status` 与 `lastFailure`。
- 按有效子弹目标 ID 保存的当天成功与重试状态。

业务配置与运行态在 Rust 领域层逻辑分离。旧 `StationPlan` / `AmmoTarget` 混合字段通过迁移读取，写回新结构后不得再作为第二套执行真相。

## 有效配置解析

新增单一 resolver，所有 preflight、制作批处理、后续多账号 round 与日历生成均调用该 resolver：

1. `independentSettingsEnabled = false`：使用 `defaultBusinessConfig` 与全局默认配方点击点。
2. `independentSettingsEnabled = true`：使用账号独立业务配置与账号级配方点击点。
3. 运行态始终从当前账号读取，不从默认配置或其他账号复制。

禁止前端自行合并默认值与账号覆盖。前端只展示后端返回的原始配置及有效配置摘要；执行器只相信后端 resolver。

## UI

### 默认账号配置

特勤处页面新增“默认账号配置”区域：

- 四制作台开关与小时/分钟。
- 四个默认制作物品选择点击点校准入口。
- 默认有序子弹目标配置。

默认子弹目标编辑器是本阶段必需 UI，不得只在 `BusinessConfig.ammoTargets` 中保留数据字段。用户必须能新增、删除、启停、区分普通/赛季子弹并调整执行顺序和相对滚轮步数；编辑器只改业务目标，不展示或复制当天兑换状态。

保存默认配置前显示受影响账号列表并二次确认。时长仍使用小时、分钟两个整数输入，保存为分钟，范围 `1` 分钟至 `168` 小时。

默认时长变化不得重算账号当前 `finishesAtMs`；新时长从下一次“收取并重做”成功后生效。默认配方点与子弹目标从账号下一次运行开始生效。

### 账号独立设置

账号卡片新增“独立设置”开关：

- 默认关闭。
- 关闭时隐藏制作台业务参数、制作物品选择点击点和子弹目标编辑器，只显示“继承默认配置”摘要。
- 开启时复制当时有效默认配置到独立配置，保证开启瞬间行为不变；当天子弹运行态不得随复制产生。
- 关闭时弹出破坏性二次确认，列出将永久删除的四制作台业务参数、四个独立配方点击点和独立子弹目标。确认后删除独立业务配置并立即继承默认配置；取消则不改。

独立设置开启后，账号卡片必须显示技术中心、工作台、制药台、防具台四个独立“制作物品选择点击点”框选入口。框选结果分别写入 `independentBusinessConfig.recipePoints`，不得覆盖全局 `craft.recipe.<station>` 点击点。执行器与 preflight 必须通过统一 resolver 读取这些账号级点击点，禁止只保存但运行时仍使用全局点击点。

账号运行态在开关切换时保持不变。

### 四制作台人工校正

账号卡片新增“人工校正四制作台”入口。Dialog 同时展示四台，并要求每台明确选择：

- `立即到期`：`finishesAtMs` 写入后端确认时刻，状态可进入到期调度。
- `正在制作`：输入剩余小时/分钟，后端以确认时刻计算绝对 `finishesAtMs`。
- `空闲`：清空 `startedAtMs` 与 `finishesAtMs`，状态设为空闲。

四台必须全部选择；正在制作的剩余时间范围同样为 `1` 分钟至 `168` 小时。点击保存后显示二次确认摘要，再一次提交四台。

人工校正成功后，当前计时来源标记为 `manual`。下一次自动收取并重做成功、写入真实开始时间后，来源改回 `automatic`。

## 账号恢复规则

- 原账号状态为 `Uncertain`：四台校正全部成功后恢复 `Ready`。
- 原账号状态为 `NeedsManualLogin`、`LoginFailed` 或 `Isolated`：制作台校正不得自动恢复账号，仍需对应人工处理流程。
- `lastFailure` 保留用于诊断，不作为恢复后继续运行的 gate。
- 任一制作台未确认或校正保存失败：账号状态不变。

## 持久化与并发

新增账号级人工校正 command；默认配置与独立设置沿用设置保存 command，或拆出窄 command，但所有路径必须满足：

1. 校验 active run 为空。
2. 校验 `settingsRevision`。
3. 在 `SettingsCoordinator` 临界区内读取当前权威设置。
4. 在内存副本上完成全量校验、有效配置解析和状态转换。
5. 一次写入 `special_ops_settings.json`。
6. 写入成功后替换内存状态并发布新 bootstrap/state 事件。

任一校验失败、revision 冲突或磁盘保存失败时，不得部分修改四台、账号状态或默认配置。不得先改内存再尝试磁盘回滚。

### 修改默认配置

默认配置修改与受影响账号的运行态兼容检查在同一临界区完成：

- 当前制作计时保留，不按新时长重算。
- 被关闭的制作台保留其运行态数据，但不进入自动调度；重新启用后仍需人工确认实际状态。
- 删除或替换默认子弹目标时，只清理不再属于有效目标的业务关联；不得把一个目标的当天成功状态复制到另一个目标。

### 关闭独立设置

关闭操作为破坏性写入：

- 原子删除 `independentBusinessConfig`。
- 立即切换到默认业务配置。
- 保留四制作台运行态。子弹当天运行态只按稳定目标 ID 保留仍存在于默认配置的匹配项；已删除独立目标产生的孤儿运行态一并清理，禁止映射给同名或同位置的其他目标。
- 若默认配置无法通过执行校验，允许在暂停状态保存草稿；恢复自动化时由统一 preflight 拒绝并指出首个缺失项。

## 旧配置迁移

首次读取旧 schema 时：

1. 按账号顺序取第一个账号的制作台业务字段、当前全局四个配方点击点和该账号子弹业务字段生成默认业务配置。
   没有账号时使用四制作台全开、合法默认时长和空子弹列表生成默认配置。
2. 其他现有账号业务配置与默认配置完全相同：`independentSettingsEnabled = false`。
3. 其他现有账号任一业务字段不同：`independentSettingsEnabled = true`，把原值迁入独立业务配置，避免静默丢失差异。
4. 制作运行态、账号状态、失败记录与当天子弹状态原样保留。
5. 新 schema 成功持久化前保留原文件；迁移或保存失败时沿用现有备份与恢复机制，不覆盖原配置。

迁移必须幂等；新 schema 再次加载不得重复复制或重置运行态。

## 错误处理

- 独立设置开启但独立配置缺失：配置异常，禁止执行；不得静默回退默认配置。
- 独立设置关闭但仍存在独立配置：normalize 时清除该隐藏配置，并记录迁移日志。
- 四台校正有未选择项、无效数值、小数、负数、零或超过 168 小时：整体拒绝。
- active run 中提交：前后端共同拒绝。
- settings revision 冲突：保留 Dialog 草稿，刷新权威状态并要求用户重新确认，不自动覆盖。
- 磁盘写入失败：内存与文件保持旧状态，显示原始错误。
- 默认配置修改影响多个继承账号：用户取消确认则零写入。

## 测试

### Rust

- 旧 schema 迁移生成默认配置，并保留有差异账号为独立配置。
- 迁移幂等，运行态与当天子弹状态不被复制或重置。
- 有效配置 resolver 正确选择默认或独立配置。
- 独立开关开启复制业务字段但不复制当天状态。
- 关闭独立设置永久删除独立配置且保留运行态。
- 默认时长修改不重算当前完成时间。
- 四台人工校正一次成功写入，并按确认时刻计算完成时间。
- 四台任一无效时整体不改。
- `Uncertain` 校正成功恢复 `Ready`；其他非 Ready 状态不自动恢复。
- revision 冲突、active run 与持久化失败均零部分写入。

### 前端

- 独立设置关闭时隐藏三类独立设置 UI，并显示继承摘要。
- 开启时显示独立设置并调用复制流程。
- 关闭时必须经过破坏性二次确认。
- 人工校正 Dialog 要求四台全部选择；只对正在制作显示时间输入。
- 二次确认摘要与实际提交 payload 一致。
- active run 期间所有入口禁用。
- revision 冲突保留用户草稿并提示重新确认。

### 实机验收

1. 用当前 `Uncertain` 账号逐台确认：一台正在制作、三台立即到期；保存后账号恢复 `Ready`，批处理只选择三台到期任务。
2. 正在制作台到达校正完成时间后进入到期任务。
3. 开启账号独立设置后修改配方点击点，不影响默认配置及其他继承账号。
4. 关闭独立设置后独立 UI 隐藏，重新开启时从当时默认配置重新复制，而非恢复旧独立值。
5. 修改默认时长后，继承账号当前完成时间不变；下一次自动重做使用新时长。

## 非目标

- 不在本阶段实现多账号 round。
- 不在本阶段实现子弹兑换执行器。
- 不在本阶段实现滚动 24 小时日历或 10 分钟执行组。
- 不保存独立设置关闭前的历史业务草稿。
- 不允许制作台校正解除登录失败或仓库隔离。
