# 校准验证被旧草稿覆盖修复设计

## 问题

校准测试通过后，后端已保存目标的 `verifiedSignature`，但前端仍可能暂时持有测试前草稿。用户立即启动制作试运行时，`flushSettings()` 在没有待保存修改的情况下仍提交整份旧草稿，从而把刚保存的验证签名覆盖为 `null`，随后制作 preflight 报“尚未测试或验证失效”。

## 修复

保持现有校准测试、签名和 revision 协议不变。修改前端 `flushSettings()`：

- 有 debounce 中的待保存配置时，立即提交并等待完成。
- 有正在执行的保存时，等待完成。
- 没有未保存修改时，不调用 `special_ops_save_settings`，直接返回当前 bootstrap。

该规则修复所有“无修改 flush 回写旧草稿”路径，不为单个制作台增加特例。

## 边界

- 真正存在未保存编辑时仍必须先保存，不能跳过。
- 保存失败继续阻止试运行启动并显示原错误。
- 不修改校准模板、双采样、匹配阈值、持久化格式或 Tauri command 名。

## 验证

新增前端回归测试：校准测试完成后立即启动制作试运行，断言无脏草稿时不会调用 `special_ops_save_settings`，且会调用制作试运行 command。随后运行相关 Vitest、前端 build 和统一质量门禁。
