# WeGame 登录后窗口切换设计

## 问题

登录前，WeGame 顶层窗口归属 `wegame.exe`。账号登录后，主界面顶层窗口归属 `wegame.exe` 进程树内的 `browser.exe`。现有聚焦逻辑只查找配置 exe 自身拥有的窗口，导致 `OpenGameEntry` 在倒计时结束后报告未找到 WeGame 窗口，未点击置顶游戏入口便结束试运行。

## 目标

- 登录前后均能找到、恢复并聚焦真实 WeGame 主窗口。
- 不放宽进程终止范围，不按进程名或窗口标题误杀其他程序。
- 不改变登录状态机、校准目标、点击顺序和三秒键鼠提示。

## 设计

### 窗口发现

为 `WindowsDesktopRuntime` 增加“按配置 exe 进程树查找主窗口”能力：

1. 按 canonical 完整路径找出配置 exe 对应的根进程。
2. 从同一进程快照构建父子关系，收集根进程及全部后代 PID。
3. 枚举顶层窗口，只在这些 PID 中选择可见、无 owner、面积最大的窗口。
4. 找不到符合条件的窗口时返回 `None`，由现有步骤超时/暂停机制处理。

`ProductionLoginDriver::focus_wegame` 使用该能力。恢复与聚焦前校验窗口 PID 仍属于本次查得的进程树，避免 PID/HWND 竞态条件导致误操作。

### 进程终止

`terminate_exact` 保持现状：只结束 canonical 完整路径精确匹配的进程实例，不递归结束后代。窗口发现范围扩大不影响终止范围。

### 游戏窗口

`WaitGameWindow` 继续按游戏 exe 自身查找窗口。本次不扩大到游戏进程树；没有实机证据证明游戏窗口存在同类切换，避免扩大变更面。

## 错误处理

- 无法读取根进程或后代进程信息：忽略该候选，不按 basename、标题或固定 PID 回退。
- 枚举进程或窗口失败：返回现有 Windows 错误，当前账号流程全面暂停。
- 进程树中没有有效顶层窗口：返回 `None`，保持现有最长三分钟等待或步骤失败规则。

## 测试

先写失败测试，再写实现：

1. 根进程无窗口、直接子进程有窗口时，选择子进程窗口。
2. 多层后代有窗口时，能沿完整进程树选择。
3. 无关 `browser.exe` 窗口不属于进程树时，禁止选择。
4. 根进程与后代均有窗口时，沿用可见、无 owner、最大面积规则。
5. `terminate_exact` 现有“不递归结束子进程”测试继续通过。

完成后运行相关 Rust 单测、`cargo test`、`bun run check` 和 `codegraph sync`，再进行实机试运行。

## 非目标

- 不按窗口标题 `WeGame` 查找。
- 不新增 `browser.exe` 配置项。
- 不改游戏列表校准或启动游戏流程。
- 不实现游戏内烽火地带、特勤处、制作或子弹兑换流程。
