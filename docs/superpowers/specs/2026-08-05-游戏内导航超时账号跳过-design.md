# 游戏内导航超时账号跳过设计

## 目标

多账号自动轮次中，游戏内导航步骤未在时限内完成时，不再将整轮自动化设为暂停。系统保存当前账号失败信息，将账号标记为“状态不确定”，结束该账号剩余制作与子弹任务，再继续下一个账号。

本设计只改变多账号 round 对导航业务失败的归类，不改变独立“游戏内导航试运行”的诊断语义。

## 当前问题

导航状态机目前把步骤超时与步骤执行错误都表示为 `GameNavigationResult::Paused`，并在 round 内映射为系统级 `AccountRunError`。因此模式选择页、特勤处入口或四制作台页面识别超时，会立即结束整轮并持久化全局暂停。

这与账号级登录、制作、子弹确认失败的处理不一致：后者会保存当前账号状态，并由 round runner 继续遍历后续账号。

## 方案

### 多账号 round

导航状态机增加独立结果：

- `GameNavigationResult::TimedOut { failed_step }`

`ProductionRoundDriver::navigate` 仅在收到 `TimedOut` 时返回账号级 `AccountRunError`：

- `scope = Account`
- `step = navigation.<failed_step>`
- `message = 步骤超时`
- 不携带 `station`

现有 `round_runner` 随后执行：

1. 通过 `persist_account_failure` 保存失败。
2. 将当前账号标记为 `Uncertain`，保留 `lastFailure`。
3. 不标记任一制作台，因为失败发生在制作前的公共导航阶段。
4. 不执行当前账号剩余制作台或子弹目标。
5. 继续下一账号。

下一个账号沿用既有登录流程；该流程负责关闭旧游戏、重启 WeGame 并选择目标账号。导航失败分支不新增额外点击、重试或进程操作。

`GameNavigationResult::Paused { failed_step, message }` 保持系统级错误映射。它表示窗口、截图、输入或其他步骤执行错误，round 必须立即持久化全局暂停。

### 独立导航试运行

`special_ops_start_navigation_trial` 保持原行为：导航超时、模板未命中或步骤执行失败时持久化特勤处全局暂停，试运行报告失败。它没有可切换的后续账号，仍应作为校准和页面状态诊断入口。

### 系统级错误边界

以下错误继续是系统级错误，全面暂停，不得降级为账号跳过：

- 游戏窗口查找、恢复或聚焦失败。
- 截图、模板采样或输入模拟的基础能力错误。
- 状态持久化、runtime 状态或 operation window 资源错误。
- 紧急停止。

仅 `GameNavigationResult::TimedOut` 改为账号级。不得依据错误消息文本猜测错误类型。

## 不包含

- 不把导航识别超时改为重试十分钟。
- 不改每个导航步骤现有三分钟超时预算。
- 不改独立导航试运行的暂停行为。
- 不新增前端设置、校准项或 Tauri command。
- 不重试当前账号，不回放已发送的导航输入。

## 测试

1. 导航状态机：步骤耗尽三分钟预算返回 `TimedOut`；步骤执行错误仍返回 `Paused`。
2. `ProductionRoundDriver::navigate`：导航 `TimedOut` 映射为账号级错误，步骤名保留 `navigation.*`。
3. `round_runner`：首账号导航账号级失败后，保存失败并执行第二账号。
4. 失败持久化：账号为 `Uncertain`，四制作台状态不被修改。
5. 导航 driver 的窗口或输入基础能力错误仍映射系统级错误，并暂停整轮。
6. 既有独立导航试运行测试继续断言导航超时和导航执行失败均导致全局暂停。
