# 单账号四制作台批处理设计

## 目标

在现有单账号单制作台试运行闭环上增加“当前账号四制作台批处理试运行”。后端按固定顺序处理当前账号所有已启用且已到期的制作台，每台复用现有 `run_craft_station` 状态机，并在进入下一台前完成结果持久化和四制作台页面确认。

本阶段只组合制作台流程，不接入登录、游戏内导航、多账号 round 或子弹兑换。

## 入口与边界

保留现有“单制作台试运行”，用于单点校准和故障诊断。新增 Tauri command `special_ops_start_craft_batch_trial` 与 UI 按钮“当前账号四制作台批处理试运行”。

批处理入口沿用单实例 `special_ops` runtime、operation window、紧急停止热键、全局总开关和 active-run gate。运行期间禁止保存设置、修改校准、测试模板或启动其他试运行。

批处理复用当前已打开的游戏，不启动或关闭游戏，不操作 WeGame，不执行登录或游戏内导航。开始前必须确认游戏窗口存在，并双采样命中 `game.stationGrid`；未处于四制作台页面时不执行首次制作台点击。

## 到期选择与顺序

启动命令冻结所选账号和当前时间，只选择同时满足以下条件的制作台：

- 账号状态为 `Ready`。
- 制作台 `enabled = true`。
- 制作台状态不是 `Uncertain`。
- `finishesAtMs` 存在。
- `finishesAtMs <= frozenNowMs`。

`finishesAtMs = null`、未启用或尚未到期的制作台不进入本轮。运行期间即使其他制作台新到期，也不动态插入当前批次；下一轮重新计算，避免执行集合在键鼠操作中变化。

固定顺序：

1. 技术中心。
2. 工作台。
3. 制药台。
4. 防具台。

没有到期制作台时，命令在创建 operation window 和登记 active run 前返回“当前账号没有到期制作台”，零键鼠输入。

## 冻结配置与 Preflight

批处理启动前为每个入选制作台冻结现有 `CraftRunConfig` 与配置时长。冻结结果按固定顺序保存为不可变列表，每台包含：

- 制作台类型与用户配置时长。
- 当前台 `craft.station.<station>` 点击点。
- 当前台 `craft.recipe.<station>` 制作物品选择点击点。
- 共享 `craft.confirmPinned` 与 `craft.returnToStationGrid` 点击点。
- `game.stationGrid`、`craft.abort`、`craft.fill`、`craft.purchase`、`craft.produce` 模板与区域。
- 三段制作固定等待和 `runtime.mouseParking`。

所有入选台必须一次性通过 preflight 后才能创建 operation window。任一台缺失校准、参考图或有效时长时整批拒绝启动，不允许先处理前几台再在中途发现静态配置缺失。

## 批处理状态机

### 批次开始

1. 创建并确认 operation window 可见。
2. 注册紧急停止热键并登记单实例 active run。
3. 聚焦 canonical 游戏窗口。
4. 对 `game.stationGrid` 执行标准双采样；失败则零制作台点击并结束。

### 单台执行

对冻结列表逐台执行：

1. 将当前步骤和提示更新为当前制作台。
2. 调用现有 `run_craft_station`。
3. `StillInProgress`：不修改 `startedAtMs` 或 `finishesAtMs`。该分支已点击 `craft.returnToStationGrid` 并确认 `game.stationGrid`，可进入下一台。
4. `Started { startedAtMs }`：按当前台配置时长计算 `finishesAtMs`，立即通过 `SettingsCoordinator::with_runtime_change` 持久化开始时间、完成时间和 `Crafting` 状态。
5. `Started` 持久化成功后，点击 `craft.returnToStationGrid`，再等待 `game.stationGrid` 双采样命中，才允许进入下一台。最后一台也执行返回确认，使批处理结束状态确定。

每台结果单独持久化。禁止把四台结果积存在内存后一次保存；后续制作台失败不得丢失前面已确认并保存的制作结果。

### 批次完成

冻结列表全部处理完成后发布成功状态，清理 operation window、热键和 active run。成功时当前游戏停留在四制作台页面。

## 失败、取消与不确定状态

- `run_craft_station` 返回 `requiresUncertain = true`：保存实际失败步骤，账号与当前制作台标记 `Uncertain`，停止剩余制作台。
- 当前台生产已经确认并持久化，但返回点击或 `game.stationGrid` 确认失败：保留该台新开始/完成时间，同时把账号与当前台标记 `Uncertain`，停止剩余制作台。
- 任一运行时持久化失败：全面暂停，禁止继续下一台；内存不得领先于磁盘。
- 普通取消发生在当前台首次输入前：停止批次，保留此前已持久化结果，不把尚未输入的当前台标记为 `Uncertain`。
- 普通取消发生在当前台首次输入后：账号与当前台标记 `Uncertain`，停止剩余制作台。
- 紧急停止沿用现有 fail-closed 规则；立即释放输入。已进入当前台时标记账号与当前台 `Uncertain`；制作台之间尚未进入下一台时至少标记账号 `Uncertain`，此前已持久化结果不回滚。
- 账号状态不是 `Ready`，或任一入选制作台状态为 `Uncertain` 时，不得启动批处理。

批处理不因某台 `StillInProgress` 停止；该结果只表示本轮无需改动此台，继续处理下一台。

## Runtime 与持久化边界

`LoginRunKind` 继续使用 `craft`，不新增持久化枚举。run snapshot 的 message 显示当前制作台与批次进度，例如“正在处理 2/3：工作台”。

新增纯编排层负责：

- 从冻结列表按顺序取下一台。
- 调用单台状态机。
- 在每台后触发权威持久化。
- 对 `Started` 分支执行返回四制作台页面。
- 在失败、取消或紧急停止时终止后续台。

单台状态机继续只判断并执行一个制作台，不感知账号、批次索引或文件持久化。批处理不得通过前端连续调用四次单台 command；否则会重复创建 operation window、重复注册热键并产生 settings revision 竞态。

## UI

在现有制作试运行区域保留账号选择与单制作台选择：

- “单制作台试运行”继续使用选中的制作台。
- 新增“当前账号四制作台批处理试运行”，只使用选中账号，不读取单制作台选择值。

active run 期间两个按钮都禁用。批处理没有到期制作台时，后端错误原样显示在现有 alert，不新增前端计时或到期判断，避免前后端时钟与状态不一致。

## Tauri 注册与文档

新增 command 必须同步：

- `src-tauri/src/lib.rs` 的 `generate_handler![]`。
- 不新增局部 app permission；仓库尚未把全部 app commands 迁移到 ACL，单独授权新 command 会拒绝既有 commands。
- 前端 invoke 与测试。
- `README.md`、`AGENTS.md`、`droid-wiki/features/special-ops.md`。

不新增持久化字段，不修改 `special_ops_settings.json` schema。

## 测试

Rust 纯编排测试覆盖：

1. 只选择已启用且 `finishesAtMs <= frozenNowMs` 的制作台。
2. 固定按技术中心、工作台、制药台、防具台排序。
3. 无到期任务时零键鼠输入且不启动 runtime。
4. 每台调用单台状态机，`StillInProgress` 不修改时间并继续下一台。
5. `Started` 先持久化时间，再点击返回点并确认 `game.stationGrid`，随后进入下一台。
6. 最后一台 `Started` 也返回四制作台页面。
7. 中途 `requiresUncertain`、返回失败或持久化失败时停止剩余台。
8. 普通取消在当前台输入前后使用不同不确定状态规则。
9. 紧急停止不回滚此前已持久化结果。
10. preflight 一次冻结所有入选制作台所需校准，缺一项整批拒绝。

前端测试覆盖：

- 保留单台试运行入口。
- 显示批处理按钮并调用 `special_ops_start_craft_batch_trial`。
- active run 期间禁止启动批处理。

完整门禁沿用 `bun run test`、`bun run build`、Rust fmt、Clippy `-D warnings`、Rust lib tests 和 `codegraph sync`。自动化测试通过后由用户在不同到期组合下实机验收，生产代码在实机确认前不 stage、不 commit。

## 实机验收

至少覆盖：

1. 两个已到期制作台，均为 `StillInProgress`，按固定顺序处理并回到四制作台页面。
2. 一个已到期台完成重做并保存新完成时间，随后继续第二个台。
3. 中途手动触发紧急停止，后续台不再点击。
4. 无到期制作台时点击批处理，游戏无键鼠输入。

## 非目标

- 不实现登录、游戏内导航或账号切换。
- 不实现多账号 round。
- 不实现子弹兑换。
- 不在运行期间动态加入新到期制作台。
- 不修改制作配方、时长算法或仓库异常规则。
