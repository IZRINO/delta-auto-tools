# 特勤处子弹二次确认与多账号兑换轮次设计

状态：已实现，待桌面实机验收。

## 目标

在现有单账号子弹兑换试运行上增加置顶二次确认窗口处理，并把当天子弹任务接入现有多账号 round。制作与子弹属于同一账号时只登录一次；单账号业务失败不得阻塞其他账号。

## 已关闭缺口

- `exchange_target` 已执行 `ammo.exchange → ammo.confirm → ammo.success`。
- `special_ops_start_ammo_trial` 保留当前账号试运行入口；多账号登录、导航和切号由 `special_ops_start_due_round` 负责。
- `AccountRoundTask` 已同时冻结制作台与子弹目标；scheduler、planner 和 round 共用权威 schedule。
- `ammo.success` 通过用户参考图做模板匹配；“按钮变灰”只是视觉描述，不是颜色识别规则。

## 校准目标

新增全局目标：

| Key | UI 名称 | 类型 | 用途 |
|---|---|---|---|
| `ammo.confirm` | 兑换二次确认按钮识别与点击区域 | 模板识别区域 | 双采样命中后点击区域中心，关闭置顶确认窗口 |

规则：

- 用户框选整个确认按钮区域并上传参考图。
- 普通子弹、赛季子弹和全部账号共用同一目标。
- 旧配置规范化时自动补入该目标，但保持未框选、未上传、未验证。
- 包含子弹任务的试运行或 round 必须在输入前检查 `ammo.confirm` 的区域、参考图及有效验证签名。
- 预检失败发生在登录前，不操作游戏、不改变账号状态。
- 不增加账号级或子弹级确认区域配置。

现有 `ammo.success` 的 UI 名称改为“兑换完成状态识别区域”。它仍是用户参考图模板，用于区分兑换前后的按钮状态；不读取颜色。

## 兑换状态机

单种子弹的兑换顺序：

1. 点击目标子弹指定点。
2. 双采样识别 `ammo.success / ammo.exchange / ammo.fill`。
3. 已命中 `ammo.success`：立即保存当天成功。
4. 命中 `ammo.fill`：沿用补齐、购买和最多 3 次重试。
5. 命中 `ammo.exchange`：识别并点击兑换按钮。
6. 双采样等待 `ammo.confirm`。
7. 命中后点击 `ammo.confirm` 区域中心。
8. 双采样等待 `ammo.success`。
9. 命中后立即保存该目标当天成功，再按配置滚轮并处理下一目标。

补齐购买最终重新出现 `ammo.exchange` 时，必须进入同一套第 5–9 步，不允许绕过二次确认。

普通目标全部完成后，存在赛季目标才点击一次 `ammo.seasonal`，再执行赛季目标。

## 多账号 round

`AccountRoundTask` 同时冻结：

- 已到期且启用的制作台；
- 当天已到每日兑换时间、尚未成功、启用且仍允许尝试的子弹目标。

账号两类任务都为空时不登录。账号按 `order` 串行执行。

单账号流程：

1. 登录目标 QQ 并启动游戏。
2. 导航至按 Tab 后的大厅 UI。
3. 仅有子弹任务：跳过特勤处入口，直接点击 `ammo.department`。
4. 有制作任务：进入特勤处并执行冻结制作台；回到四制作台页面后点击同一个 `ammo.department`。
5. 执行冻结子弹目标。
6. 保存账号最新状态并关闭游戏。
7. 继续下一账号。

内部导航配置增加“是否进入四制作台页面”的目标分支，不复制第二套登录或导航状态机。

## 调度与合并

- 每日兑换时间继续使用 `HH:mm`，固定按 `Asia/Shanghai` 解释。
- 到点后，scheduler 可启动包含当天未成功子弹目标的 round。
- 制作任务在每日兑换时间前 5 分钟内到期时，延迟到兑换时间并与子弹合并。
- 当前时间已过每日兑换时间，账号仍有当天未成功子弹时，下次进入该账号顺带兑换。
- 暂停期间正常计时；恢复后首次继续将同账号全部逾期制作与当天子弹合并。
- 当天未执行不补做前一天；当天成功目标不重复执行。
- 时间轴保留原 `scheduledAtMs`；视觉合并不改变实际执行时间。

## 持久化

- 每台制作成功后立即保存下一完成时间。
- 每种子弹命中 `ammo.success` 后立即保存 `lastSuccessDay`，重置当天 retry 状态。
- 已保存结果不因同账号后续失败而回滚。
- round 启动时冻结任务集合；执行期间配置修改不改变本轮目标。
- 人工校正仍一次确认四制作台和全部启用子弹的当天状态。

## 错误分级

### 账号级失败，关闭游戏后继续下一账号

- `ammo.confirm` 模板识别超时或有效双采样未命中；
- 已点击 `ammo.confirm`，但 `ammo.success` 未命中；
- 其他已发生输入且无法确认实际兑换结果的子弹步骤。

处理：账号标记 `Uncertain`，记录目标子弹、失败步骤、消息和时间；停止该账号剩余任务。下一轮跳过，直到人工处理并校正。

仓库空间不足或购买重试耗尽沿用 `Isolated`；停止当前账号剩余任务，关闭游戏后继续下一账号。

登录失败沿用 `NeedsManualLogin / LoginFailed`，继续下一账号。

### 单目标失败，继续当前账号其他子弹

仅适用于点击兑换前、实际状态确定且不会遗留置顶窗口的目标失败。记录当天失败和 retry 状态，不回滚已成功目标。

### 系统级失败，全面暂停

- 状态持久化失败；
- 目标窗口、截图或输入系统故障；
- 关闭游戏失败；
- 无法安全判断是否可继续的 runtime 故障。

紧急停止立即释放输入，当前账号标记 `Uncertain`，停止整轮并保留现场，不继续下一账号。

运行中普通暂停只登记请求；当前账号结束后关闭游戏并停止切号。

## UI

- 校准列表新增 `ammo.confirm`，复用现有上传参考图、测试、框选交互。
- `ammo.success` 文案改为“兑换完成状态识别区域”。
- “开始当前到期轮次”同时处理制作和子弹，不新增第二个多账号启动按钮。
- 操作窗口复用现有消息显示账号、子弹备注与步骤，不扩展新的进度结构。

## 测试

### ammo runtime

- 直接兑换严格执行 `ammo.exchange → ammo.confirm → ammo.success`。
- 补齐购买后出现兑换按钮时复用同一确认流程。
- `ammo.confirm` 失败后不执行当前账号后续子弹或滚轮。
- 确认后 `ammo.success` 未命中返回账号不确定结果。
- 成功目标立即持久化，后续失败不回滚。

### planner / scheduler / runner

- 每日时间前不加入子弹；到点加入；当天成功目标跳过。
- 制作与子弹任务按账号合并并保持账号顺序。
- 兑换时间前 5 分钟内的制作任务延迟合并。
- ammo-only 账号跳过特勤处；制作+子弹账号先制作后兑换。
- 账号级确认失败保存 `Uncertain`、关闭游戏并继续下一账号。
- 关闭游戏或持久化失败转全局暂停。
- 暂停恢复后合并同账号逾期任务。

### 配置与前端

- 旧配置补入未校准 `ammo.confirm`。
- 子弹执行预检要求 `ammo.confirm` 当前验证有效。
- 校准列表显示新名称并保留测试/框选能力。
- “开始当前到期轮次”在仅有子弹任务时可启动。

完成门禁：相关 Vitest、Rust 单元测试、`bun run build`、Clippy `-D warnings` 和 `git diff --check` 全部通过；随后执行桌面开发版实机验收。

## 非目标

- 不为每种子弹建立独立确认区域。
- 不使用 OCR 或颜色阈值判断兑换成功。
- 不改变每种子弹每天最多成功兑换一次、普通优先赛季、失败重试次数等既有业务规则。
- 不增加任务拖动排序。
