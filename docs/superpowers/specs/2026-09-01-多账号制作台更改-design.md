# 多账号制作台更改

## 一句话

独立登录流程：按账号顺序登录到四制作台页面后停手，等人改配方，按「下一账号」快捷键再切号。入口放在特勤处默认账号配置里，和特勤处轮换/试运行互斥，不能同时跑。

## 互斥

本功能与特勤处其它运行态二选一：

- 轮换未暂停、总开关关闭、全局自动化关闭、已有试运行/轮次、没有启用账号：不能打开。
- 打开期间：禁止点「继续」恢复轮换、禁止启动任何试运行或到期轮次。
- 紧急停止：留游戏现场，同时关掉本功能（快捷键失效）。无人值守的登录运行时按现有紧急停止取消；制作台等人、没有运行时按紧急停止只关本功能、不关游戏。

不改制作计时、子弹状态、交易行、利润筛选。工具只负责登录到制作台，配方由人在游戏里改。

## 界面

默认账号配置区块顶部一行：

- 开关「多账号制作台更改」，默认关。
- 「下一账号」热键录制，复用紧急停止同一套录制器。
- 不能打开时开关 disabled，title 写明原因（未暂停轮换 / 未录热键 / 与紧急停止撞键 / 没有启用账号 / 正在运行）。
- 开关旁 inline alert 显示打开/关闭失败。
- 打开且当前没有运行时，显示「等待下一账号（第 n/m 个 · QQ …）」；最后一号已关游戏后显示「已巡检完全部启用账号」。

热键与紧急停止必须互斥：录成同一组合键时拒绝保存、拒绝打开。

## 数据

`SpecialOpsSettings` 新增：

| 字段 | 类型 | 默认 | 持久化 |
|---|---|---|---|
| `stationWalkthroughEnabled` | `bool` | `false` | 是 |
| `nextAccountHotkey` | `string` | `""` | 是 |

旧 JSON 缺字段按默认值。Profile 快照随 `specialOps` 整包走。

进程内另有不落盘的巡检游标：启用账号列表（按 `order`，跳过 `enabled == false` 或 QQ 非纯数字）、当前下标、是否已巡完。重启后若开关仍为开：只登记热键、游标视为已巡完，不自动登录。只有关→开这条边沿才从第一号登录。

`nextAccountHotkey` 走 `special_ops_save_settings`。`stationWalkthroughEnabled` 只走独立命令，自动保存必须像 `paused` 一样强制沿用进程内值，前端草稿不得回滚。

## 命令与运行态

- `special_ops_set_station_walkthrough { enabled: bool, settingsRevision: u64 } -> SpecialOpsBootstrap`
- `LoginRunKind` 增加 `stationWalkthrough`（camelCase）。提示窗标题：「多账号制作台更改中」。
- 热键 scope：`special-ops-next-account`（普通 scope，全局自动化关闭时不触发）、`special-ops-emergency`（已有 safety scope，开关打开期间由本功能持有）。
- 新 command 注册到 `generate_handler![]`，不单独建 ACL。

打开成功：写盘 `stationWalkthroughEnabled = true`、登记两枚热键、从第一个启用账号启动一次 `stationWalkthrough` 运行（登录 + 导航到 `game.stationGrid`）。

关闭成功：写盘 `false`、撤下一账号热键；若本功能持有紧急停止则在无运行后撤掉（有运行时仍由该次运行的紧急停止路径接管，停止完成后再撤）。不关游戏。进行中的本功能运行按普通取消，不走紧急停止留现场逻辑之外的额外关进程。

## 单账号运行

复用 `start_account_session`：登录（先停游戏和 WeGame）+ 导航到四制作台。不跑制作、子弹、限时商品、交易行。

成功：结束本次运行、释放 operation 窗、游戏留在制作台。游标停在当前账号，等人按下一账号。

失败：按现有登录/导航失败落账号状态。不自动跳号。开关仍开，人按快捷键才去下一号。

预检与完整轮次的登录+导航相同（两条 exe、WeGame 校准、`game.modeReady` / `game.stationGrid`、导航点击点、`runtime.mouseParking`）。不要求制作/子弹校准。

`roundProgress`：`accountIndex` / `accountTotal` / `qqAccount`，`stationKind` 为空。

## 下一账号快捷键

开关关闭：scope 不登记 → 无效。

开关打开：

| 当前状态 | 行为 |
|---|---|
| 登录/导航进行中 | 忽略 |
| 制作台等人，还有后续启用账号 | 启动下一号的登录+导航（流程自己先关游戏和 WeGame） |
| 制作台等人，已是最后一号 | 只关游戏和 WeGame，开关保持打开，游标标已巡完 |
| 已巡完（含应用带着开关重启） | 忽略 |
| 中途关掉再打开 | 新一轮：从第一号登录（登录流程先关当前游戏） |

每次按键按**当前**账号列表取启用项，不在打开时冻死名单。中途关掉某账号，下一跳跳过它。

最后一号关闭游戏失败：只记 warn，仍标已巡完，开关仍开。不升级成系统暂停。

## 热键寿命

开关打开期间，紧急停止和下一账号由本功能持有。单次运行的资源清理不得把这两枚热键清掉；若清理路径会 `clear_scope`，开关仍开时必须立刻补登记。

紧急停止回调：

1. 关掉本功能（写盘、撤下一账号热键、清游标）。
2. 若有运行中的 login runtime，再走现有 `request_emergency_stop_core`（留游戏现场）。
3. 若没有运行，只做第 1 步，不报「当前没有运行中的登录试运行」。

切 Profile、应用关闭：关掉本功能并撤热键。有运行时仍先走现有「运行中拒绝切 Profile」。

## 前端

- 开关 `onCheckedChange` 调 `special_ops_set_station_walkthrough`，不走 `save()`。
- 热键录制 commit 走 `save({ ...draft, nextAccountHotkey })`；与 `emergencyHotkey` 相同则拒绝并提示。
- `controlsLocked`（有运行 / 暂停切换中）时开关不可点。打开期间「继续」按钮 disabled，title 说明先关本功能。
- 打开期间试运行启动按钮 disabled。
- `SpecialOpsBootstrap` 增加只读 `stationWalkthrough: { accountIndex: number; accountTotal: number; qqAccount: string | null; exhausted: boolean } | null`。开关关闭时为 `null`。不要另开事件；写盘后走现有 `state-changed` / bootstrap。`accountIndex` 从 1 计；等人时指向当前号；已巡完时等于 `accountTotal`。

## 测试

后端：

- 打开：未暂停 / 空热键 / 撞紧急停止 / 无启用账号 / 已有运行 → 拒绝，settings 不变。
- 打开：跳过未启用账号，第一号是第一个 `enabled &&` 纯数字 QQ。
- 下一账号：功能关 → 无 scope；运行中 → 游标不变；最后一号 → 只关游戏且 `stationWalkthroughEnabled` 仍为 true。
- 关闭：不调用关游戏；进行中运行改为普通取消。
- 再打开：游标回到第一号。
- 紧急停止：`stationWalkthroughEnabled` 变 false，下一账号 scope 清除。
- `save_settings` 不能把 `stationWalkthroughEnabled` 改回草稿值。
- `set_paused(false)` 在本功能打开时拒绝。

前端：

- 默认账号配置渲染开关和下一账号热键。
- 未暂停时开关 disabled。
- 打开期间试运行和「继续」disabled。

## 不做

- 不碰 `round_runner` 的到期分桶、交易行让位、利润 gate。
- 不在制作台自动改配方、不写 `recipeNote`、不重算 `finishesAtMs`。
- 不新增 beta 通道或独立窗口。
- 不把本功能做成 scheduler 的一种任务。
