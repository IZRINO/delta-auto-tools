# 特勤处限时商品检查与交易行购买设计

日期：2026-08-08  
状态：设计已确认，进入实施

## 1. 目标

在现有特勤处多账号自动轮次中增加两个任务类型：

1. 每日 12:00、20:00 检查军需处限时商品，通过九个区域识色判断是否出现高价值物品。
2. 每日 02:00-04:00 进入交易行，循环读取单个目标物品价格，价格不高于设定值时执行购买点击。

两个任务必须复用现有登录、游戏导航、统一 scheduler、24 小时时间轴、暂停、休眠检测、紧急停止及多账号轮换。不得创建并发键鼠 worker。

## 2. 非目标

- 不识别限时商品名称、价值或具体物品数量。
- 不自动购买限时商品，只提供识别结果。
- 不判断交易行购买是否成功。
- 不计算交易行实际花费、库存或购买成功率。
- 不支持多个交易行目标物品。
- 不提供可编辑的限时商品刷新时间或交易行时间窗口。
- 不设计通用点击工作流 DSL。

## 3. 统一任务模型

`TimelineTaskKind` 扩展为四类：

```text
Craft
Ammo
LimitedSupplyCheck
MarketPurchase
```

四类任务进入同一个 scheduler，按现有全局时间顺序排序。相同账号、相同计划时间的业务优先级固定为：

```text
制作任务 -> 子弹兑换 -> 限时商品检查 -> 交易行购买
```

限时商品和交易行分别维护自己的业务运行态，不复用 `StationStatus`、子弹当天状态或账号人工状态。

新任务继续遵循现有账号资格与会话保持规则：

- 非 `Ready` 账号的任务仍投影到 24 小时时间轴，但不会被冻结进自动轮次。
- 账号在任务有效期内恢复 `Ready` 后，可重新进入当前有效周期或交易行窗口。
- 同账号相邻任务符合现有 10 分钟保持条件时复用当前游戏会话；其他账号任务按全局计划时间优先。

## 4. 配置归属

### 4.1 限时商品全局配置

限时商品检查完全按显示环境全局共享，不提供账号独立配置：

- 功能开关。
- 固定刷新时间 12:00、20:00。
- 研发部门点击前等待时间，范围 0-60 秒，使用现有固定等待 UI 形式。
- `limited.research` 研发部门点击点。
- `limited.ready` 页面就绪识别区域与用户参考图路径。
- 页面就绪超时，默认 10 秒，范围 5-60 秒。
- `limited.color.1` 至 `limited.color.9` 九个识色区域。
- 两种共享目标 RGB 颜色。
- 每种目标颜色独立容差，范围 0-255，默认 30。
- 识色方法固定为 `AnyPixel`。

所有启用账号共用上述点击点、参考图、识色区域和颜色参数。账号只保存自己的检查结果。

### 4.2 交易行全局配置

交易行全局配置包含：

- 功能开关。
- 固定时间窗口 02:00-04:00。
- `market.entry`：Tab 后交易行入口点击点。
- 交易行入口后固定等待，默认 3 秒，范围 0-60 秒，使用现有固定等待 UI 形式。
- 默认 `market.product` 商品入口点击点。
- `market.price` 价格 OCR 区域。
- 默认设定价格。
- 每日购买次数。
- `market.return` 高价返回点击点 A。
- `market.buy` 达标购买点击点 B。
- 目标物品备注。

`market.price` 只负责价格 OCR；新增 `market.confirm` 作为独立的最终确认购买点击点，避免 OCR 区域兼任点击坐标。

### 4.3 交易行账号独立设置

账号独立设置只允许覆盖：

```text
商品入口点击点
设定价格
```

账号开启独立设置时复制当时的全局商品入口点击点与设定价格。之后修改全局值不覆盖账号独立值。关闭独立设置后重新继承全局值，但保留独立值，重新开启时继续使用原独立值。

功能开关、价格 OCR 区域、返回点、购买点、购买次数、备注和固定等待始终使用全局配置。

### 4.4 设定价格 UI

- 全局交易行配置必须显示“设定价格”整数输入框。
- 账号开启独立设置后也必须显示独立“设定价格”整数输入框。
- 只接受正整数，不允许空值、负数或小数。
- 保存为整数，不保存显示逗号。
- 比较规则为 `OCR 价格 <= 设定价格` 时进入购买分支。

## 5. 持久化状态

### 5.1 限时商品账号状态

每个账号保存：

- 当前刷新周期 ID。
- 检查结果：待检查、无高价值、发现高价值、检查失败。
- 检查时间。
- 命中区域编号。
- 命中的目标颜色。
- 高价值提醒是否已人工清除。

高价值提醒不修改账号 `Ready` 状态，不阻断制作、子弹、交易行或其他账号。

### 5.2 交易行账号状态

每个账号保存：

- 当前 Asia/Shanghai 自然日。
- 当天已执行购买点击次数。
- 当前状态：待执行、执行中、已完成、价格识别异常、窗口已结束。
- 最后业务错误。

最终购买点击完成后立即执行 `已执行次数 +1` 并持久化。暂停、应用关闭或紧急停止后按已持久化次数恢复。

交易行不识别购买结果，因此点击与持久化之间发生蓝屏或紧急停止时，允许最终次数多一次或少一次，不进入人工状态。

### 5.3 Profile 与备份

新增业务配置和账号运行态继续进入 `SpecialOpsSettings`，随特勤处配置和 Profile 快照备份。用户参考图只保存路径，不复制图片本体。

## 6. 限时商品调度

刷新周期固定为 Asia/Shanghai：

| 周期 | 创建时间 | 有效期结束 |
|---|---:|---:|
| 中午周期 | 12:00 | 19:59:59 |
| 晚间周期 | 20:00 | 次日 11:59:59 |

规则：

- 每个启用账号在每个周期检查一次。
- 暂停、休眠或应用关闭错过计划时间时，用户点击继续后补执行当前有效周期。
- 进入下一周期后，旧待检查任务、失败结果和未人工处理的高价值提醒全部失效。
- 不补查已经失效的周期。
- 无高价值或检查失败后，本周期不再自动重复执行。

## 7. 限时商品运行流程

复用现有子弹入口路径中的部门模板和军需处点击点：

```text
按 Tab
-> 识别并点击 ammo.department
-> 按 ammoSupplyDelayMs 等待并点击 ammo.supply
-> 按研发部门等待配置等待
-> 点击 limited.research
-> 等待 limited.ready 双采样命中
-> 对九个区域执行 AnyPixel 双采样
-> 保存结果
```

首次进入研发部门出现的额外动画不执行跳过操作。runtime 持续等待 `limited.ready`，动画结束且页面稳定后再识色。

### 7.1 页面就绪

- `limited.ready` 必须使用用户上传的参考图。
- 按现有模板匹配规则连续采样两次。
- 在配置超时内未命中时，当前账号限时检查移动到本轮队尾补偿重试一次。
- 第二次仍超时，记录“限时商品检查失败”，账号保持 `Ready`，继续其他账号。

### 7.2 九区域识色

- 九个区域共用两种目标颜色，每种颜色有独立容差。
- 单个区域内任意像素命中任一目标颜色，即该区域当前样本命中。
- 同一区域连续两个有效样本都命中，最终结论为“发现高价值物品”。两个样本可分别命中两种共享颜色中的任一种。
- 九个区域均连续未命中，最终结论为“无高价值物品”。
- 两次样本不一致时不提交结果，在本次识别时限内重新采样。
- 截图失败不计作低分样本。

命中时保存区域编号和目标颜色。识别结果只显示在特勤处 UI，不发送 Windows 通知，不创建置顶提醒窗口。

## 8. 交易行调度

交易行每日窗口固定为 Asia/Shanghai 02:00-04:00：

- 02:00 为所有启用账号创建当天任务。
- 暂停或应用关闭后，可在 04:00 前恢复。
- 账号按现有账号顺序串行执行。
- 当前账号完成配置购买次数后切换下一账号。
- 不为交易行账号分配时间片。市场价格全账号相同，切号不能绕过高价。
- 04:00 到达时，不再启动新原子流程；已开始的当前原子流程完成后结束整个交易行轮次。
- 04:00 后所有未完成账号任务转为“窗口已结束”并从待执行时间轴移除。
- 当天未完成次数不累计到次日。次日 02:00 按配置购买次数重新开始。

## 9. 交易行运行流程

进入大厅 UI 后：

```text
点击 market.entry
-> 固定等待
-> 从单次商品原子流程开始循环
```

点击交易行入口后，商品循环不再显示原本每次操作前的 1 秒键鼠提醒。一轮最开始的全局接管提醒继续保留。

### 9.1 单次商品原子流程

```text
点击当前账号解析出的 market.product
-> 读取 market.price OCR
-> 价格高于设定值：点击 market.return，返回交易行界面
-> 价格不高于设定值：点击 market.buy，再点击 market.confirm
-> 达标分支执行购买次数 +1 并持久化
```

价格高于设定值的返回分支不增加购买次数，立即从商品入口重新开始下一次原子流程。

### 9.2 价格 OCR

- 同一商品页最多读取三次，间隔约 500ms。
- OCR 文本删除所有非 ASCII 数字字符，剩余数字直接拼接为价格。
- 清理后为空或数值为 0，视为读取失败。
- 同一商品页三次失败后，点击返回点 A，进入下一商品页。
- 连续三个商品页均读取失败，结束当前账号当天交易行任务，记录“价格识别异常”，继续下一账号。
- 价格识别异常当天不补偿重试，04:00 后对应任务消失。

### 9.3 让出到期制作任务

交易行每完成一个原子流程后检查全局时间轴：

- 没有制作任务到期：继续当前账号交易行循环。
- 有制作任务到期：保存当前交易行进度，暂停交易行队列，按全局时间顺序执行到期制作。
- 制作完成且当前时间仍早于 04:00：按已保存次数恢复交易行队列。
- 制作完成时已到 04:00：结束交易行轮次，未完成交易行任务全部失效。

交易行只能在原子流程边界让出，不在价格读取或点击序列中间切换账号。

## 10. 暂停、紧急停止与休眠

### 10.1 普通暂停

- 限时商品：完成当前账号本次页面识别后暂停。
- 交易行：完成当前原子流程后暂停，不等待当前账号完成全部购买次数。
- 暂停期间正常计时。
- 04:00 前点击继续可恢复交易行；04:00 后当天交易行任务失效。

### 10.2 紧急停止

- 立即停止输入并释放按键。
- 限时商品结果尚未持久化时，当前有效周期保持待检查，可在继续后重跑。
- 交易行按已持久化次数恢复，不标记状态不确定。
- 不尝试推断紧急停止前最后一次购买是否成功。

### 10.3 休眠与时间跳变

沿用现有规则：检测到 wall clock 与 monotonic clock 跳变后转为暂停，汇总当前有效周期的逾期任务。用户点击继续后重新规划，不自动复用休眠前游戏会话。

## 11. 错误分层

### 11.1 局部业务错误

以下错误只结束当前业务任务，不修改账号状态：

- 研发部门页面补偿重试后仍未就绪。
- 限时商品识色在时限内无法形成一致样本。
- 连续三个商品页价格 OCR 失败。

局部错误不阻断同账号其他制作、子弹或新业务任务。

### 11.2 账号错误

以下情况沿用现有账号重试与人工检查规则：

- 未找到已记住账号。
- WeGame 登录失败。
- 游戏内公共导航连续两次失败。

### 11.3 系统错误

以下情况沿用现有全局暂停规则：

- 游戏窗口或 WeGame 系统级异常。
- 截图系统错误。
- 键鼠输入系统错误。
- 配置或运行态持久化失败。

高价值提醒不是错误，不进入账号人工校正。

## 12. 24 小时时间轴与账号 UI

时间轴新增：

- 12:00、20:00 限时商品检查任务。
- 02:00-04:00 交易行任务，显示“已执行次数/目标次数”。
- 限时商品检查失败与价格识别异常显示在对应任务行。
- 高价值结果显示“发现高价值物品”和“已检查”按钮。

高价值提醒规则：

- 不改变账号状态 badge。
- 不影响 scheduler 选择账号。
- 人工点击“已检查”后立即从待处理任务行移除。
- 未人工处理时，在下一个限时商品刷新周期开始后自动移除。

“无高价值”只显示在操作结果和账号最近检查结果中，不保留待处理任务行。04:00 后不再显示当天未完成交易行任务。

## 14. 试运行

### 14.1 限时商品试运行

- 选择一个账号，完成正式登录与游戏导航。
- 进入研发部门并验证 `limited.ready`。
- 双采样九个区域。
- 显示每个区域是否命中、命中颜色、最近颜色距离。
- 显示最终“有高价值”或“无高价值”。
- 不写正式周期结果，不添加高价值提醒。

### 14.2 交易行安全试运行

“测试导航与价格识别”执行：

- 进入交易行。
- 点击当前账号商品入口。
- 读取价格。
- 显示 OCR 原文、解析数字、设定价格和达标/过高结论。
- 不点击返回点 A、购买点 B 或最终购买区域。
- 不修改正式购买次数。

### 14.3 交易行真实试买

“真实试买 1 次”执行一个完整原子流程：

- 价格过高时点击返回点 A。
- 价格达标时点击购买点 B 和价格 OCR 区域中心。
- 无论执行时间是否位于 02:00-04:00，均不修改正式购买次数。

所有试运行支持操作提示窗、取消和紧急停止。

## 16. 验收标准

- 两个新任务由同一 scheduler 调度，不存在并发键鼠 worker。
- 现有制作和子弹流程顺序不回归。
- 限时商品旧周期不会补查，高价值提醒不会阻断账号。
- 交易行不会提前购买高于设定价格的物品。
- 交易行在 04:00 后不会启动新原子流程。
- 交易行不会饿死已到期制作任务。
- 账号独立设置不会暴露未批准的限时商品或交易行字段。
- 试运行不会修改正式业务状态。
- 新配置与运行态可通过特勤处配置和 Profile 备份恢复，参考图片本体不进入备份。
