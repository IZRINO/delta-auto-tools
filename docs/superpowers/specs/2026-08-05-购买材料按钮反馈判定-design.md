# 购买材料按钮反馈判定设计

状态：已确认并实现

## 目标

修正制作与子弹的材料购买反馈判定。购买后不再检查“一键补齐”是否仍出现；只检查购买材料按钮是否仍停留在购买弹窗中。

## 选择的方案

保留现有两个校准目标：

- `craft.purchase`：制作材料购买按钮识别与点击区域。
- `ammo.purchase`：子弹材料购买按钮识别与点击区域。

两个目标允许使用同一张用户参考图，但继续各自保存点击区域。这样不改校准 schema，也不假设两个游戏页面的坐标永远一致。

不采用合并为一个全局购买目标：会改变既有配置兼容关系。也不采用 OCR 或顶部短暂公告：该公告持续时间短，不能作为可靠的自动判定依据。

## 统一购买状态机

每个材料购买分支均执行以下规则：

1. 点击对应“一键补齐”。
2. 双采样确认并点击对应购买按钮（`craft.purchase` 或 `ammo.purchase`）。
3. 等待 1 秒，仅用于让游戏刷新价格或交易结果，不作为成功条件。
4. 双采样等待两个互斥状态：
   - 继续动作按钮出现：制作为 `craft.produce`，子弹为 `ammo.exchange`。材料购买成功，继续原生产或兑换流程。
   - 购买按钮仍出现：本次购买未生效。可能是价格波动，也可能是仓库空间不足。
5. 购买按钮仍出现时，最多再点击购买两次；每次都重复步骤 3 和 4，下一次点击使用游戏当前显示价格。
6. 第三次购买后仍命中购买按钮：按仓库空间不足处理。制作分支把账号标记为 `Isolated`；子弹分支只把当前目标写入 `AmmoTarget.lastFailure`。两者都停止该账号本轮剩余任务，round 切换下一账号。
7. 等待期间没有稳定命中继续动作按钮或购买按钮、双采样不一致、截图/窗口/输入失败：制作结果保持 `Uncertain`，子弹结果定位到当前目标，系统能力错误保持系统级失败；不得把未知状态误判为仓库空间不足。

## 运行期映射

- 子弹分支保留 `AmmoRunStop::Isolated` 运行结果，但 round 持久化通过目标 ID 写入当前 `AmmoTarget.lastFailure`，账号保持 `Ready`；该目标冻结到人工判定，同账号制作及其他子弹继续参与后续轮次。
- 制作分支新增明确的 `craft.isolated` 失败语义；单制作台试运行、四台批处理和多账号 round 都将其映射为账号 `Isolated`，不把当前制作台写成 `Uncertain`。
- 已成功完成的前序制作台与子弹仍保持其已写入状态；制作隔离阻断账号，子弹隔离只阻断失败目标。

## 非目标

- 不新增校准 UI、配置字段或购买金额上限。
- 不读取或识别顶部“仓库空间不足”公告。
- 不承诺区分价格波动与仓库空间不足的真实原因；三次购买按钮持续出现仅按既定规则进行隔离。

## 测试

- 子弹：前两次购买按钮持续出现、第三次转为兑换按钮时继续兑换；三次持续出现时只冻结当前目标；无稳定状态时记录当前目标人工失败。
- 制作：前两次购买按钮持续出现、第三次转为生产按钮时继续生产；三次持续出现时隔离；无稳定状态时标记不确定。
- 多账号 round：制作购买耗尽后保存账号 `Isolated` 并执行下一账号；不修改当前制作台为 `Uncertain`。
