# 特勤处业务配置与 24 小时任务时间轴设计

## 目标

本轮同时完成两项能力：

1. 四制作台增加制作物品备注；子弹目标改为带备注、指定点击点和兑换后滚轮动作的有序配置。
2. 增加滚动未来 24 小时的小时网格时间轴，展示账号何时需要处理哪个制作台或子弹目标。

两项共用同一套 `BusinessConfig`。时间轴直接读取制作台和子弹目标的新备注字段，不建立第二套展示配置。

## 范围

### 本轮实现

- `StationBusinessConfig.recipeNote`。
- `AmmoBusinessTarget` 的备注、点击点、滚轮方向、滚轮次数和稳定 ID。
- 默认业务配置与账号独立业务配置的编辑、校准和持久化。
- 旧配置幂等迁移。
- 后端未来 24 小时权威任务投影。
- 前端小时网格、10 分钟视觉分组和逾期展示。
- 对应 Rust、TypeScript、React 测试与项目文档。

### 本轮不实现

- 完整子弹兑换 runtime。
- 多账号 round 执行器。
- 后台自动唤醒调度循环。
- 休眠跳变恢复、崩溃 checkpoint 和版本化备份。
- 时间轴拖动、任务改期或手动执行按钮。

## 数据模型

### 制作台业务配置

`StationBusinessConfig` 增加：

```text
recipeNote: string
```

备注仅供用户辨认配方和时间轴展示，不参与 runtime gate。默认配置和账号独立配置分别持久化。

### 子弹业务目标

`AmmoBusinessTarget` 统一为：

```text
id: string
note: string
enabled: boolean
seasonal: boolean
clickPoint: CalibrationRect | null
scrollDirection: up | down
scrollSteps: non-negative integer
order: integer
```

执行语义固定为：

```text
点击目标 -> 补齐/购买/兑换 -> 滚轮 -> 下一目标
```

最后目标允许 `scrollSteps = 0`。仓库空间不足时不滚轮，立即终止该账号剩余流程。当天成功状态和重试状态继续保存在账号运行数据，禁止随默认模板复制。

### 旧配置迁移

- 制作台缺少 `recipeNote` 时补空字符串。
- 子弹旧 `name` 迁入 `note`。
- 子弹旧 `scrollSteps` 保留，方向补 `down`。
- 缺少 `clickPoint` 时补 `null`。
- 稳定 ID、启用状态、普通/赛季类型和顺序保持不变。
- 迁移必须幂等，不得重置账号当天成功或重试状态。

## 校准

复用现有 `special-ops-calibration-*` overlay 和原 command，不新增平行校准系统。

校准 scope 复用现有 `targetKey + accountId` 上下文明确区分：

- 全局校准目标。
- 默认子弹目标点击点。
- 账号独立制作物品选择点击点。
- 账号独立子弹目标点击点。

子弹业务点使用 `business.ammo.<targetId>`；`accountId` 为空时写默认配置，存在时写对应账号独立配置。原 command 参数和 overlay 职责保持不变。

业务点击点必须为 `1 x 1`。active run、revision 冲突、目标不存在或账号未开启独立设置时拒绝提交；磁盘成功写入后才更新内存。

## 24 小时任务投影

`ScheduleSnapshot` 增加：

```text
timelineStartMs
timelineEndMs
timelineTasks[]
```

每个任务包含：

```text
id
accountId
qqAccount
kind: craft | ammo
stationKind?
ammoTargetId?
note
scheduledAtMs
overdue
accountStatus
```

投影窗口是 `[now, now + 24h]`：

- 制作任务来源于启用制作台的 `finishesAtMs`。
- 已逾期制作任务保留原 `scheduledAtMs`，并设 `overdue = true`。
- 子弹任务来源于当天尚未成功的启用目标；若次日每日兑换时间落入窗口，则同时投影次日目标。
- 非 `Ready`、隔离或登录失败账号仍可展示，`accountStatus` 明确标识其不可执行状态。
- 后端负责生成稳定 ID、排序和平铺任务；前端不重新推导业务计划。

## 前端时间轴

时间轴为可滚动 24 小时小时网格：

- 从当前小时附近开始，覆盖未来 24 小时。
- 任务按 `scheduledAtMs` 排序。
- 逾期任务显示“0 分钟后”，同时保留原计划时间。
- 展示 QQ、制作台或子弹备注、计划时间和账号状态。
- 无任务时显示明确空状态。

### 10 分钟视觉分组

前端纯函数 `groupTimelineTasks(tasks, 10min)` 执行视觉分组：

- 每组第一项是固定锚点。
- 仅当 `task.scheduledAtMs - anchor.scheduledAtMs < 10min` 时合并。
- 不链式扩展。
- 组内仍按原计划时间排序；视觉合并不修改任务执行时间。
- 例如 10:20 和 10:28 同组：10:20 处理第一项；需要时等待到 10:28 再处理第二项。

暂停期间到期任务继续显示，延迟文案固定为“0 分钟后”。用户点击继续后，同账号逾期任务由后续 round 合并一轮执行；本轮仅展示该语义，不实现 round。

## UI

### 制作台

默认配置与独立配置的四制作台均显示：

- 启用状态。
- 小时和分钟。
- 制作物品备注。
- 对应制作物品选择点击点及选择/重选入口。

继承账号继续隐藏独立编辑器。

### 子弹目标

默认与独立子弹编辑器每行显示：

- 备注。
- 启用状态。
- 普通/赛季类型。
- 指定点击点及选择/重选入口。
- 兑换后滚轮方向与次数。
- 上移、下移、删除。

新增目标生成稳定 ID，默认普通、启用、向下滚动 0 次、点击点为空。

## 错误处理

- 启用子弹目标缺少点击点：允许保存和展示；自动化 preflight 必须拒绝并指出目标备注及稳定 ID。
- 非法滚轮次数、非法单点坐标、无效 scope：拒绝保存且零部分写入。
- active run 期间禁止新增、删除、排序、改备注、改坐标或改滚轮动作。
- 时间轴输入数据异常时跳过单条无效任务并保留其余投影；不得阻断配置页加载。
- UI 不用时间轴状态反向覆盖账号、制作台或子弹持久化状态。

- Rust：schema 迁移、业务点 scope、24 小时边界、逾期任务、次日兑换任务、账号状态投影、稳定排序。
- TypeScript：10 分钟锚点分组、非链式扩展、逾期文案和 24 小时网格辅助函数。
- React：默认/独立备注与点击点编辑、账号独立设置隐藏、时间轴任务块和空状态。
- 全量门禁：`bun run check`、`bun run build`、`git diff --check`。
