# 特勤处 24 小时任务栏单项人工判定设计

状态：已批准并实施

## 目标

将 24 小时任务栏中的账号级“人工校正”入口改为任务级人工判定。用户只处理实际失败的制作台或子弹，不必重复确认未出问题的任务。

账号页现有“人工校正制作与子弹状态”保留，继续负责初始化、主动全量校正，以及无法定位到具体业务目标的账号异常。

## 已选方案

采用两个独立 Tauri command：

- 单制作台状态校正。
- 单子弹当天状态校正。

两个 command 都携带 `settingsRevision`，复用现有 revision 临界区完成校验、写盘、内存替换、bootstrap 返回和 scheduler 唤醒。

未采用以下方案：

- 复用现有全量校正 command：必须伪造其他制作台和子弹状态，可能覆盖正确运行态。
- 通用配置 patch command：调用面过宽，无法在 command 边界强制单项业务校验。

## UI

### 24 小时任务栏

可定位的失败任务在自身任务行内显示判定控件：

- 制作台：`立即到期`、`正在制作`、`空闲中`。
- 子弹：`已兑换`、`未兑换`。

点击 `立即到期` 或 `空闲中` 后直接提交当前制作台状态。点击 `正在制作` 后展开“小时 + 分钟”输入与保存按钮：

- 保存的 `finishesAtMs` 晚于当前时间时，按剩余毫秒向上取整为分钟并预填。
- 没有有效未来完成时间时不猜测，小时和分钟留空，用户必须填写。
- 用户可以修改预填值。
- 行保持打开期间不自动倒数，提交时使用用户确认的分钟数。
- 剩余时间仍遵守现有范围：1 分钟至 168 小时，只接受整数小时和整数分钟。

每次只锁定正在提交的任务行。其他任务行与页面其他非冲突设置保持可用。提交失败时保留当前行选择、时间输入和错误文案，不自动关闭。

不增加二次确认 modal。任务栏不再打开账号级完整人工校正 modal。

### 账号页

账号页现有完整人工校正入口、两阶段核对和提交行为不变。该入口仍一次校正四个制作台及全部启用子弹。

登录失败、需要人工登录、导航失败、窗口异常等无法结构化定位到具体制作台或子弹的错误，不在任务行显示单项按钮。任务栏只提示“请在账号页处理”，由账号页现有入口处理。

## 持久化模型

### 失败归属

`AccountFailure` 增加两个可选字段：

- `stationKind: StationKind | null`
- `ammoTargetId: string | null`

Rust 字段使用 `#[serde(default)]`，旧配置缺少字段时解析为 `None`。

两个定位字段互斥：制作台失败只设置 `stationKind`，子弹失败只设置 `ammoTargetId`，登录、导航、窗口和系统级失败都不设置。normalize 遇到两个字段同时存在时拒绝保存，避免任务栏把一条失败同时挂到两项业务。

制作台失败最多定位当前失败台。制作 round 在首个制作台失败后结束当前账号，因此账号级 `lastFailure` 足以保存该次制作失败与 `stationKind`。

`AmmoTarget` 增加可选 `lastFailure`，保存该子弹自己的失败步骤、消息和时间。账号允许多个子弹目标分别失败；不能只依赖账号级 `lastFailure`，否则后一次失败会覆盖前一次失败。

账号级 `lastFailure` 保留最近一次诊断摘要。子弹单项目标的 `AmmoTarget.lastFailure` 是“该子弹是否被人工阻断”的权威状态。

### 时间轴投影

`TimelineTask` 增加可选 `manualFailure`。`build_schedule()` 按结构化目标关联失败，不解析 `step` 或 `message` 文案：

- `AccountFailure.stationKind` 与制作任务的 `stationKind` 相同 → 该制作任务显示三种判定。
- `AmmoTarget.lastFailure` 存在 → 对应 `ammoTargetId` 的任务显示两种判定。
- 定位字段缺失或目标已删除 → 不生成单项判定，只提示账号页处理。

失败任务即使已被 round eligibility 排除，也必须保留在滚动 24 小时时间轴中，显示为逾期任务和“0 分钟后”，直到人工判定完成。10 分钟视觉合并规则不变；合并只影响展示，每条任务仍保留独立按钮与提交状态。

### 兼容规则

旧配置中的 `Uncertain` / `Isolated` 账号若没有结构化目标字段，不根据错误文本猜测失败目标，也不自动补齐四台或全部子弹。用户继续使用账号页完整人工校正。

新增、禁用后重新启用、删除后重加制作或子弹业务配置沿用现有同步与轮换规则，不进入新的人工待判定流程。

## 后端命令

### 单制作台校正

新增单制作台 command，参数包括：

- `accountId`
- `station`
- `state`
- `remainingMinutes`
- `settingsRevision`

校验：

1. 当前没有特勤处 runtime 正在执行。
2. revision 与当前设置一致。
3. 账号、制作台和结构化失败归属存在且互相匹配。
4. `NeedsManualLogin` / `LoginFailed` 不得通过制作台校正绕过登录处理。
5. `state = crafting` 时 `remainingMinutes` 必须为 1 至 10080；其他状态不接受剩余时间。

状态写入复用账号页完整人工校正的现有映射：

- `立即到期`：保存为到期制作状态，下一轮可立即处理。
- `正在制作`：以提交时刻为基准保存实际开始时间，并按剩余分钟计算 `finishesAtMs`。
- `空闲中`：清空开始与完成时间，保存为空闲状态。

成功后清除该制作失败。制作台失败会阻断整账号；该失败校正完成后账号恢复 `Ready`。若账号还存在子弹单项目标失败，不阻塞账号恢复，子弹目标继续各自禁用。

### 单子弹校正

新增单子弹 command，参数包括：

- `accountId`
- `targetId`
- `succeededToday`
- `settingsRevision`

校验账号、目标、启用状态和目标级失败记录。不得依靠备注或执行顺序定位子弹。

状态写入：

- `已兑换`：将 `lastSuccessDay` 设为 Asia/Shanghai 当天，清空当天重试状态和该目标失败。
- `未兑换`：清除当天成功，重置当天失败次数，使该目标可重新进入当天兑换调度，并清除该目标失败。

若账号级 `lastFailure` 指向已校正目标，则改为仍未解决目标中的最近一条；不存在其他失败时清空。账号若是由该子弹错误遗留的旧 `Uncertain` / `Isolated` 状态，且结构化定位一致，校正后恢复 `Ready`。

账号页完整人工校正成功后，除现有状态写入外，还必须清空账号级结构化失败及全部子弹目标的 `lastFailure`。用户可继续用该入口一次恢复整个账号。

## Runtime 与调度

### 制作台失败

- 只要求人工判定实际失败台。
- 当前账号剩余制作和子弹流程停止，round 切换下一账号。
- 账号保持 `Uncertain` 或 `Isolated`，所有后续自动调度继续阻断。
- 人工判定该台后账号恢复 `Ready`。

### 子弹失败

- 只把实际失败子弹写入 `AmmoTarget.lastFailure`。
- 当前账号本轮到此结束，round 切换下一账号。
- 账号保持或恢复 `Ready`；该失败子弹从后续 round eligibility 排除。
- 同账号制作任务和其他未失败子弹仍可在后续轮次执行。
- 多个子弹可分别失败、分别显示、分别校正。

本节覆盖此前“子弹购买重试耗尽后将整账号长期设为 `Isolated`”的规则。子弹补齐、购买、确认或完成识别在哪个目标停止，就记录哪个 `ammoTargetId`；当前账号本轮结束，但持久化阻断范围只限该子弹。制作台购买重试耗尽仍属于账号级制作失败，继续阻断整账号。

制作失败与子弹失败同时存在时，制作失败先阻断整账号。制作台校正后，账号恢复 `Ready`，制作任务与未失败子弹恢复调度，尚未校正的失败子弹继续单独排除。

子弹 runtime 现有“先识别 `ammo.success`”规则不变。即使用户把已兑换目标判为“未兑换”，实际进入游戏后仍会先检查完成状态；命中后只记录当天成功，不重复点击兑换。

## 原子性与错误处理

两个 command 均在 `SettingsCoordinator::with_expected_revision_change` 中执行：

1. 再次确认无运行中操作。
2. 克隆当前设置。
3. 只修改目标任务。
4. normalize。
5. 原子写入 `special_ops_settings.json`。
6. 写盘成功后替换内存设置。
7. 构建包含最新 `ProfitRuntimeSnapshot` 的 bootstrap。
8. 发出状态事件并唤醒 scheduler。

写盘失败、revision 陈旧、runtime 运行中或目标已被配置变更删除时，不修改内存和磁盘，不清除失败记录。前端显示原始错误；revision 陈旧时刷新 bootstrap，并按任务 ID 重新挂接仍存在的行内草稿后允许用户重新提交。

## 测试范围

### Rust

- 单制作台三种状态映射。
- `正在制作` 的剩余分钟边界：空值、0、1、10080、超过 10080。
- 单制作台校正只修改目标台，不覆盖其他台和子弹。
- 制作台校正后账号恢复 `Ready`，但保留其他子弹目标失败。
- 子弹“已兑换”和“未兑换”当天状态映射。
- 多个子弹失败时只清除目标失败，其他失败保留。
- 子弹失败目标不进入 round，其他制作和子弹仍进入。
- 登录、导航、窗口错误不获得任务级定位。
- 陈旧 revision、运行中、目标删除、写盘失败均不产生部分提交。
- 旧配置缺少新增字段时可读取，且不从文案推断目标。

### 前端

- 制作失败行显示三个按钮；子弹失败行显示两个按钮。
- 正在制作的未来完成时间按分钟向上取整预填；无有效完成时间时必须手填。
- 提交时只锁当前行；失败保留选择、输入和错误。
- 多个失败子弹分别保存，已保存行消失，其他行不受影响。
- 无结构化目标的账号异常只显示账号页处理提示。
- 账号页完整人工校正 modal 行为不变。
- 10 分钟视觉合并后每条失败任务仍可独立操作。

## 非目标

- 不删除账号页完整人工校正。
- 不新增全量待判定列表或 `manualReview` 聚合结构。
- 不要求新配置项先人工判定后才能加入轮换。
- 不从失败文案猜测制作台或子弹。
- 不修改利润筛选、校准、登录或游戏内导航流程。
- 不增加任务拖动排序或改变 10 分钟视觉合并规则。
