# 特勤处多账号自动化：设计草案

> 状态：分阶段设计中；登录切号已确认。
> 更新时间：2026-07-25
> 当前优先级：登录切号 → 制作流程 → 可用性闭环 → 子弹目标配置与校准。
> 登录切号独立规格：[特勤处登录切号设计](./2026-07-25-特勤处登录切号-design.md)

## 已确认方向

- 面向《三角洲行动》特勤处流程。
- 支持制作物品、收取制作完成物、兑换子弹；“收菜”仅是收取制作物的简称，不包含种植。
- 支持多个指定账号，按账号顺序串行执行。
- 账号列表由用户显式配置；未配置账号不参与自动化。
- 工具需要保存已配置账号的密码，并在切换账号时使用。
- 账号密码按用户明确要求以明文保存，不使用 DPAPI 或 Windows Credential Manager 加密。
- 账号配置导出/备份需要包含明文密码。
- 导出前必须二次确认，并明确提示导出文件包含明文账号与密码。
- 账号编辑页支持一键复制密码。
- 复制密码后不自动清理 Windows 剪贴板。
- 首版仅支持通过 WeGame 使用 QQ 账号与密码登录；不支持微信扫码或其他启动器。
- 切换账号允许关闭当前游戏、退出当前 WeGame 会话，再登录下一个账号。
- 账号身份只由配置的唯一 QQ 账号确定；密码允许相同，不参与身份判定。
- 不读取或比对 WeGame ID、游戏 ID 或 UID，不执行 OCR ID、头像/个人主页或剪贴板复制兜底。
- 每次处理目标账号前都先结束指定游戏进程，再强制结束 WeGame，重新启动 WeGame 并输入目标 QQ 账号与密码。
- WeGame 与游戏 `.exe` 路径均由用户通过文件选择器指定并持久化。
- 登录后必须先选中《三角洲行动》，启动按钮才会出现；配置阶段提示用户将游戏置顶，运行时不搜索、不滚动。
- 登录入口、登录表单、登录按钮、置顶游戏条目与启动按钮均使用用户框选区域和上传的参考图；工具不内置参考图。
- 静态 UI 识别需连续两次一致，采样间隔 `300–500ms`；单步最长重试 3 分钟，仍未命中则全面暂停。
- 登录按钮只提交 1 次；不自动判断密码错误、验证码、风控或网络异常的具体原因。
- 账号列表持续显示状态：等待中、执行中、暂停、状态不确定、已隔离、本轮完成；异常状态附失败步骤、最后识别结果与最后错误时间。
- 主窗口展示每个账号 4 台制作台的当前物品、完成时间与状态，以及当天子弹兑换进度、下一次触发原因与时间、账号异常状态。
- 每轮开始时冻结账号列表与顺序快照；新增账号、删除账号、调整顺序从下一轮生效，正在执行的账号配置不得中途替换。
- 当前轮次执行期间，尚未处理账号在进入时重新扫描并处理全部已到期任务；已经处理账号的新到期任务进入待办队列，当前轮次结束后立即创建下一轮。禁止回跳插队。
- 首次启用账号必须完成初始化向导：逐台确认制作中、可收取或空闲；制作中录入当前完成时间，可收取加入首轮任务，空闲选择是否立即制作；同时确认当天子弹兑换状态。初始化完成前账号不得进入自动轮换。初始化完成后显示摘要，用户点击“开始自动化”才进入无人值守。
- 应用保持运行、自动化未暂停且 Windows 未休眠时，到期任务无需人工确认，直接创建轮次并在键鼠占用提醒后自动执行。
- 功能受应用现有全局开关控制，不使用系统托盘；点击主窗口 `×` 直接关闭软件并停止调度。下次启动恢复持久化时间但保持暂停。
- 首版仅支持单个 WeGame 进程与单个游戏进程串行切号，不支持多开、多窗口并行或跨进程切号。
- 账号、明文密码、制作状态与校准配置启用版本化自动备份，最近保留 5 份；数据损坏时禁止自动执行，用户选择恢复备份或重新初始化。
- 备份仅在账号新增/删除/排序/密码修改、制作状态或完成时间持久化、子弹当天状态变化、校准提交、人工恢复隔离账号、导入配置或模板批量应用时生成；普通 UI 编辑与 tick 不生成备份。
- 提供试运行模式：仅选择一个账号执行「结束旧进程 → 重新登录 → 选择游戏 → 启动游戏」；登录切号试运行在确认游戏进程与窗口后结束，不进入制作或兑换。
- 试运行账号由用户手动选择，默认预选账号列表第一项；试运行结果只代表该账号与当前显示环境，不推断其他账号。
- 隔离账号恢复必须逐台确认 4 台制作状态、确认当天子弹状态，并显式点击“解除隔离”；解除前不得加入下一轮。
- 自动化操作途中关闭全局开关等同紧急停止：立即停止输入并释放按键，当前账号标记“状态不确定”；重新开启全局开关后功能仍保持暂停，人工确认后才能继续。
- 自动化执行期间禁止用户并发操作鼠标键盘；检测到用户输入后在安全点暂停，并置顶显示“当前正在操作”提醒窗口；保留紧急停止热键。
- 操作中 overlay 不提供按钮，只显示“当前正在操作”与紧急停止快捷键；暂停和其他控制保留在主窗口，避免自动鼠标键盘操作期间误触。
- 紧急停止热键允许自定义，默认 `Ctrl+Shift+F12`，使用 `Strict` 冲突策略；仅在自动化实际操作期间注册或生效，其他状态按下无效果。
- 操作中 overlay 复用计时器/连发器的透明、置顶、点击穿透显示风格。
- 每段鼠标键盘自动化开始前显示 3 秒倒计时；倒计时期间可从主窗口取消，倒计时结束后注册紧急停止热键并开始输入。
- 从开始登录当前账号到完成并切换下一账号期间，操作状态 overlay 常驻；等待阶段显示当前步骤，用户可正常使用键盘鼠标；每段实际输入前切换为倒计时提醒并临时占用键鼠。
- 每段倒计时结束后激活目标 WeGame/游戏窗口，校验窗口标题、进程与当前界面状态，再发送输入；任一校验失败则不点击，进入等待或错误状态。
- 窗口最小化时尝试恢复，恢复失败则标记“窗口异常”并跳过账号。
- 游戏窗口关闭或进程崩溃时首次自动重新打开游戏并从中断步骤继续；再次崩溃则全面暂停，等待人工处理。
- 游戏或 WeGame 崩溃后不依赖 ID 恢复；需要重建会话时，必须重新执行目标 QQ 账号的完整登录切号状态机。
- 每个操作片段记录“开始前状态 → 输入已发送 → 成功状态已确认 → 持久化完成”；崩溃恢复从最后一个已确认成功步骤继续。输入已发送但结果未确认时，标记当前账号“状态不确定”，禁止盲目重放。
- 工具自身崩溃、被强制关闭或断电后，当前账号标记“状态不确定”，恢复持久化完成时间并保持全局暂停；不自动重放未确认操作，人工校正后才能继续。
- WeGame 切号流程：结束指定游戏进程 → 强制结束 WeGame → 重新启动 WeGame → 点击「QQ 账号密码登录」（登录表单已出现时跳过）→ 清空并输入目标 QQ 账号 → 输入密码 → 只提交 1 次 → 识别并选中置顶的《三角洲行动》 → 识别并点击启动按钮 → 确认指定游戏进程与窗口出现。
- 每个 WeGame 步骤配置点击点、输入区域与成功识别区域；不以固定延时单独判定成功。
- 点击启动游戏后，只有游戏进程存在、窗口标题/进程匹配且配置区域识别到游戏主界面或加载完成标志，才判定启动成功；不以固定等待秒数单独判定。
- 进入游戏后默认不在“烽火地带”；固定点击指定区域进入烽火地带，再按 `Tab` 切换第一人称与大厅视角，之后才能操作特勤处 UI。
- `Tab` 后通过配置区域判定大厅视角成功；成功后停止该判定，不继续监听，以免影响进入特勤处。
- 特勤处导航成功流程：识别指定区域可选择 → 点击指定区域 → 识别指定区域文字“开始游戏” → 按 `Tab` → 识别指定区域文字“特勤处” → 点击该区域 → 识别技术中心、工作台、制药台、防具台。
- 上述每一步识别失败均重试；单步最长重试 3 分钟，仍失败则全面暂停。
- 单轮结束后，对本轮失败账号执行 1 轮补偿重试；仍失败则结束当前执行轮次，保留未完成状态。
- 当前账号完成流程后切换下一个指定账号。
- 单次执行轮次处理完当前到期任务后结束；后续按制作完成时间再次启动新轮次。
- 制作物品划分为 4 个固定大类：技术中心、工作台、制药台、防具台。
- 每个大类只有 1 个制作槽位，同一时间只能制作 1 种物品；一个账号最多并行制作 4 种物品。
- 需要记录每个账号制作对应物品的时长，并在完成时回到账号收取。
- 不同物品可有不同制作时长，例如 A 为 4H、B 为 8H。
- 某物品到期后启动一轮：进入对应账号，收取该物品并再次制作；其他物品到期时另行触发轮次。
- 每次进入账号时，处理该账号全部 `完成时间 <= 当前时间` 的任务；多个同时到期任务合并处理。
- 支持暂停：暂停期间制作计时继续按绝对时间推进，但不登录、不切号、不执行游戏操作。
- 结束暂停时立即扫描到期任务；存在可收取任务则启动执行轮次。
- 执行途中请求普通暂停时，完成当前账号流程后暂停，不再切换下一账号。
- 另设“紧急停止”：立即停止输入并释放所有按键；当前账号标记为“状态不确定”。
- 紧急停止后的当前账号禁止自动重跑；下次启动前必须由用户确认实际状态并修正完成时间。
- 因仓库空间不足或其他原因导致收取/重做失败时，标记整个账号；后续轮次跳过该账号，直到用户人工确认实际状态并修正完成时间后恢复。
- 全局失败规则：任意步骤一旦判定仓库空间不足，立即结束该账号剩余流程，标记并切换下一账号；人工处理前后续所有轮次均跳过该账号。
- 账号隔离期间，4 个制作台的完成时间继续推进，但不执行任何账号或游戏操作。
- 解除隔离时必须逐台确认实际状态与完成时间，全部确认后账号才恢复调度。
- 仓库不足前已确认成功的步骤先持久化保留；但人工处理期间可能顺手收取并重新制作，解除隔离时以人工处理后的实际状态为准，允许人工确认结果覆盖旧 checkpoint。
- 应用启动时恢复持久化完成时间并显示逾期任务，但保持暂停；必须由用户点击“继续”后才执行登录与游戏操作。
- 应用运行中检测到 Windows 休眠唤醒导致的时间跳变时，自动暂停、汇总逾期任务并将主窗口置顶；用户点击“继续”后才执行。
- 休眠唤醒后点击「继续」时不复用休眠前游戏会话；下一目标账号必须重新执行完整登录切号状态机。

## 当前数据与调度约束

- 休眠唤醒后点击「继续」时，强制结束旧游戏与 WeGame 进程，再为下一目标 QQ 账号创建新会话。
- 明文密码保存在独立的 `special_ops_settings.json`；UI 默认遮罩显示并支持一键复制，日志和错误上报不得包含密码。
- 校准数据全局共享，不按账号复制；当前只保留一套校准结果，显示或 UI 环境变化后必须重新校准，不按比例静默缩放。
- 制作完成时间应持久化，应用重启后不能因内存状态丢失而重复制作或漏收；具体恢复策略待确认。
- 调度使用 Windows 系统时间；检测到时间向前或向后跳变超过 2 分钟时，按休眠唤醒处理：自动暂停、窗口置顶、重新计算到期任务，用户点击“继续”后执行。
- 特勤处账号、明文密码、制作计划、任务状态、完成时间与校准环境独立于现有 Profile；Profile 切换不更换账号集合或调度状态，模板单独批量应用。
- “轮次”指由一个或多个到期任务触发的一次多账号处理，不等于整个自动化任务生命周期。
- 每个账号允许独立配置 4 台制作设备的物品与时长，并支持从模板批量应用到多个账号；底层按“账号 → 制作台 → 物品 → 时长 → 完成时间”保存。
- 每个账号的核心流程固定为：收取所有到期制作物 → 立即重做对应物品 → 每种子弹每日兑换一次（支持多种子弹）→ 保存本账号最新状态 → 切换下一账号。
- 子弹兑换按 `Asia/Shanghai` 自然日 `00:00` 重置；每种目标子弹每天最多成功兑换 1 次。
- 当天未执行时，次日只执行当日兑换，不补前一天次数。
- 多种目标子弹按配置顺序执行；单种失败不阻断其他子弹，但需记录失败状态。
- 系统存在多种可兑换子弹，但用户只选择其中若干种作为每日兑换目标，不执行全量兑换。
- 每个账号保存有序子弹目标列表：“子弹类型、启用状态、执行顺序、当天兑换状态”。
- 子弹兑换 UI 流程：按 `Tab` → 点击“部门”指定区域 → 点击子选项“军需处” → 点击“战术部门” → 进入兑换列表；赛季限定子弹使用独立点击区域。
- 在兑换列表中通过固定点击区域与滚轮定位目标子弹；不同目标之间可能需要不同滚轮次数。
- 每种子弹保存入口类型、从列表顶部开始的滚轮方向与次数、点击区域、成功灰色识别区域；每次选择前先重置列表到顶部，禁止从上一目标累计滚动。
- 普通子弹使用默认入口，不执行额外入口点击；赛季限定子弹必须先点击独立指定区域再执行兑换。
- 子弹执行按入口分组：先处理普通子弹组，再点击赛季限定入口处理限定组；赛季限定无启用目标时跳过入口点击。各组内部保留账号配置顺序。
- 选中目标子弹后按钮显示“一键补齐”；材料补齐、兑换、价格波动与仓库空间不足处理复用制作流程规则。
- 成功兑换后操作按钮变为灰色，通过校准区域识色确认兑换成功。
- 进入目标子弹时若兑换按钮已为灰色，连续两次识色确认后直接写入当天成功状态并跳过点击，用于兼容人工提前兑换或本地状态丢失。
- 子弹兑换中判定仓库空间不足时，不继续重试当前子弹或其他子弹，立即应用账号级仓库空间不足规则。
- 子弹模板只复制目标选择与执行顺序，不复制当天兑换状态。
- 提供全局“每日兑换时间”，默认 `08:00 Asia/Shanghai`；到点创建独立轮次，只处理当天尚未成功兑换的账号与目标子弹。
- 因暂停、休眠或应用关闭错过兑换时间时，恢复后首次点击“继续”补执行当天任务。
- 制作任务已到期且距离每日兑换时间不超过 5 分钟时，延迟制作轮次并与每日兑换合并；已过每日兑换时间的账号在下一次进入时顺带兑换；不提前执行次日兑换。
- 单种子弹兑换失败时，当天最多在该账号下一次进入时优先重试 1 次；仍失败则记录当天失败，不再无限重试，次日状态重置。
- 每日兑换时间默认 `08:00 Asia/Shanghai`，并提供 UI 自定义时间。
- 自定义时间使用 `HH:mm`，合法范围 `00:00–23:59`，固定按 `Asia/Shanghai` 解释，不支持秒或独立时区。
- 修改每日兑换时间后重新计算当天待执行状态，但当天已成功兑换的子弹不得再次执行。
- 若把每日兑换时间改到当天已过去的时刻，立即创建当天尚未完成的兑换轮次；若改到未来时刻，则等待新时间触发。
- 4 个制作台的物品与时长由用户手动配置；每次收取并重做成功后记录实际开始时间，按配置时长计算下一次完成时间。
- 制作按钮上方显示的时长只作为可选旁路校验，不直接覆盖配置。识别失败或与配置不一致时记录“时长识别异常”，仍按用户配置继续轮换，不暂停或隔离账号。
- 制作时长 UI 使用“小时 + 分钟”两个整数输入，持久化统一转为分钟；合法范围为 1 分钟至 168 小时，不允许 0、负数、小数或秒。
- 每个制作台到期后始终收取并重做该账号当前配置的同一物品；不自动更换配方。修改物品配置时必须确认当前制作状态。
- 账号可单独停用任一制作台；停用台不收取、不重做、不创建完成时间，不影响其他制作台或子弹兑换。
- 账号当前没有到期制作物、没有启用制作台且没有待兑换子弹时跳过登录，标记“本轮无任务”；只有存在到期任务、首次启动制作、待兑换子弹或人工恢复待处理时才登录。
- 收取到重新制作流程：识别制作台指定位置小感叹号 → 点击制作台收取 → 识别奖励弹窗并按空格继续；收取失败时无奖励弹窗，而以公告提示（如仓库空间不足），按账号隔离规则处理 → 识别制作台中央“空闲中” → 点击指定区域进入制作列表 → 点击已在配置阶段置顶的目标物品 → 检查按钮状态。
- 材料充足时按钮显示“生产”；材料不足时显示“一键补齐”。点击“一键补齐”后进入购买材料弹窗并点击指定区域购买；购买因仓库空间不足等失败时标记账号、跳过账号，人工处理后恢复。
- 一键补齐购买时只需点击固定区域，系统自动补齐所需数量，不输入购买数量。
- 购买失败需区分仓库空间不足与价格波动：价格波动导致失败时再次点击购买会按当前价格自动对齐并继续购买；仓库空间不足则按账号隔离规则处理。
- 价格波动购买最多重试 3 次，每次间隔 1 秒并重新识别；重试后仍未成功则标记材料购买失败并隔离账号。
- 自动一键补齐不设置消费上限；配置阶段明确提示用户预留足够货币，运行时按购买弹窗当前价格直接成交。
- 补齐成功后按钮变为“生产”；点击“生产”后按钮变为“中止”，以此确认制作真正开始。
- 新一轮 `startedAt` 取识别到按钮变为“中止”的确认时刻，`finishedAt = startedAt + 用户配置时长`；不以点击“生产”的时刻起算。
- 制作物品配置阶段要求用户将目标物品置顶制作列表；运行时直接点击固定区域选中，不重复识别物品名称。
- 修改正在制作的物品或时长时，默认保留当前计时，新配置从下一次成功“收取并重做”后生效。
- 提供“立即重置当前制作”选项，要求二次确认，并将该制作台状态标记为人工变更。
- 提供校准向导，按流程逐项捕获点击点与识别区域；交互复用摩斯采样区域、识别触发区域监听、识色与点击区域的现有模式。
- 校准数据全局共享，账号只保存业务配置；当前只保留一套校准结果，不维护多个显示环境，也不提供账号级覆盖点。
- 显示或 UI 环境变化后禁止复用旧坐标；用户必须重新框选并上传当前版本参考图，不按比例静默缩放。
- 可收取主判定信号为制作台指定位置的小感叹号；不再依赖“无倒计时”单独判定。
- 点击制作台后，收取成功应出现奖励页面并按空格继续；仓库空间不足公告持续时间太短，不作为必要识别信号。
- 奖励弹窗实际表现为稳定的奖励页面；收取失败公告在屏幕上方短暂出现后消失。网络卡顿时可重复点击收取位置；若此前已收取成功，再次点击原位置会进入制作列表。
- 收取点击后识别奖励页面则按空格继续；识别到制作列表则视为此前已经收取成功并直接进入选物品流程；两者均未出现时每隔 2 秒重试，最多 3 次。3 次后仍保持可收取小感叹号，判定为仓库空间不足，标记并跳过该账号，其他账号继续正常轮换；若状态无法归类则标记“状态不确定”并隔离。
- 收取成功后制作台中央显示“空闲中”；进入制作列表并选中置顶目标物品后，材料充足显示“生产”，材料不足显示“一键补齐”；点击“生产”后按钮变为“中止”，据此确认制作已真正开始。
- 收取状态识别仍要求连续两次一致，采样间隔约 `300–500ms`；识别不一致则重新采样，不点击、不更新持久化状态。
