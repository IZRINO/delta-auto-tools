# 特勤处人工恢复、利润截止与导航重试设计

日期：2026-08-06

## 目标

修正完整人工校正的剩余时间预填；把利润截止从“无条件兑换”改为最终两次利润筛选；将游戏内导航识别超时限制为当前账号本轮末尾重试一次；为不涉及业务状态的账号级故障提供单一人工恢复入口。

## 非目标

- 不修改制作台、子弹兑换、仓库不足和紧急停止现有人工校正规则。
- 不修改每日兑换时间前的利润查询 cadence、KKRB 主源与 Moligod fallback 规则。
- 不持久化利润达标资格、查询 generation、查询进度或 active round 目标。
- 不让导航窗口、截图、输入等执行错误降级为账号级重试。

## 账号级人工恢复

### 状态

新增账号状态 `manualCheckRequired`，前端显示“需人工检查”。它仅表示同一轮次内第二次游戏内导航识别超时。

现有状态语义不变：

- `needsManualLogin`：未找到记住账号。
- `loginFailed`：登录失败。
- `uncertain`：制作或兑换输入后业务状态不确定。
- `isolated`：仓库空间不足或同类隔离错误。

### 本轮导航重试

round 的初始冻结任务保持不变。每项冻结账号任务增加仅运行期有效的导航重试计数，初始为零。

1. 游戏内导航返回 `TimedOut` 时，若重试计数为零，不写入账号失败或状态，不暂停 scheduler，将该完整账号任务移动到当前 round 队尾，并将计数设为一。
2. 当前队列其他原始账号继续执行。
3. 队尾任务重新执行完整登录、导航、制作和子弹流程；导航在任何步骤再次返回 `TimedOut` 时，账号持久化为 `manualCheckRequired`，记录实际失败步骤和消息，随后继续其他账号。
4. `Paused`、截图失败、窗口异常、鼠标键盘输入失败、持久化失败与取消语义不变，仍是系统级失败并全面暂停。

因为导航发生在制作和子弹操作之前，重试任务不会重复制作或兑换已持久化成功的业务动作。

### 单一恢复动作

新增 `special_ops_confirm_account_manual_check` 命令，使用现有 `settingsRevision` 和 `SettingsCoordinator` 写入临界区。

命令只接受以下状态：`needsManualLogin`、`loginFailed`、`manualCheckRequired`。其他账号状态一律拒绝。

确认后：

- 清除账号 `lastFailure`。
- 账号恢复 `ready`。
- 保留四制作台状态、`startedAtMs`、`finishesAtMs`、子弹当天成功状态和重试状态。
- 成功写盘后发送 scheduler `Notify`。

账号卡片与该账号全部 24 小时任务行均显示“已人工检查”。点击后先显示简短二次确认；确认成功后两处同步恢复普通显示。

对三种账号级状态隐藏完整制作台/子弹人工校正。`uncertain` 与 `isolated` 继续使用既有完整或单项业务校正，不能使用本命令绕过。

自动化继续时，恢复后的到期任务立即可调度；自动化暂停时任务继续显示“0 分钟后”，直至用户点击继续。

## 完整人工校正剩余时间

只修改账号页面完整人工校正 modal，不修改 24 小时任务行单项校正。

用户点击某制作台“正在制作”时，前端以点击时刻计算：

`remainingMinutes = ceil((finishesAtMs - nowMs) / 60_000)`

当且仅当计算结果在 `1..=10_080` 内时，将其拆分预填到小时和分钟输入框。用户可以继续编辑。

无 `finishesAtMs`、完成时间已到期、时间异常或结果超界时，输入保持空；提交时仍要求用户手填有效剩余时间。选择“立即到期”或“空闲中”保持现有空剩余时间校验。

不新增配置字段，不改变后端人工校正 payload 或时间计算。

## 利润截止最终筛选

`cutoffTime` 保持现有配置名称和 UI 位置，但语义从“开始绕过利润”改为“开始最终筛选”。

### 截止前

从每日兑换时间到 `cutoffTime` 前，保持现有立即、5 分钟、5 分钟、50 分钟查询 cadence。每条规则使用自身 `minimumProfit`。

### 截止时

到达 `cutoffTime` 时：

1. 使普通 cadence 与旧达标资格失效。
2. 收集当天尚未成功、未耗尽游戏内重试、未被轮空、已配置点击点且已绑定有效利润规则的目标。
3. 对这些目标执行最终第 1 次查询。查询仍遵守 KKRB 主源、整体失败才 fallback Moligod 的规则。
4. 最终查询统一使用固定门槛 `totalProfit >= 10_000`，忽略规则原 `minimumProfit`。

每个规则独立处理结果：

- 利润大于或等于 10,000：关联目标冻结进兑换 round。
- 利润低于 10,000：立即记录当天轮空，不进行第 2 次查询。
- 请求失败、精确名称缺失、重复匹配或利润无效：加入 5 分钟后的最终第 2 次查询。
- 目标缺少 `profitRuleId`、`profitRuleId` 未指向现存规则，或 KKRB 精确名称为空：直接记录当天轮空，不等待重试。

第 2 次查询仍以固定门槛 10,000 判断。达到门槛进入兑换 round；其余所有结果记录当天轮空。

### 当天轮空持久化

在 `profitFilter` 增加当前自然日 `cutoffState`：

- `day`：`Asia/Shanghai` 日期。
- `targets`：截止开始时冻结的 `accountId + targetId + ruleId` 范围快照。
- `skips`：稳定 `ruleId`、轮空原因与决定时间。

范围快照只限定哪些目标允许参与当天最终筛选；它不表示达标资格、查询 attempt 或 active round。达标资格仍仅存在于运行期。

- scheduler、round plan 与 24 小时时间轴均排除范围快照外的新增目标及当天已轮空规则关联的目标。
- 应用重启后继续排除；次日加载、保存和 scheduler 唤醒时清理前一自然日记录。
- 当天修改既有规则的名称、最低利润或绑定关系不清除其轮空记录。
- 当天新增规则或新增目标不触发截止后筛选，等待下一自然日。

运行态新增“截止最终查询”和“5 分钟后最终补查”阶段。删除 `cutoffBypass` runtime/timeline 类型和“已到截止时间，忽略利润”文案；时间轴改为展示最终查询、补查或“今日轮空”。

## 错误处理与不变量

- 首次导航超时不得改变账号状态或写入失败记录。
- 第二次导航超时只改变当前账号，不终止其他账号轮换。
- 单一人工恢复不得修改任何制作台或子弹运行态。
- 截止筛选失败、目标缺失和低利润不增加游戏内兑换失败次数，不隔离账号。
- 仅最终查询达标规则可创建截止后的兑换 round；不得沿用截止前旧资格。
- 已成功兑换和游戏内重试耗尽始终优先排除。

## 测试

前端：

- 完整人工校正点击“正在制作”预填未来完成时间，按分钟向上取整。
- 到期、缺失和异常完成时间不预填。
- 三种账号级状态显示单一恢复按钮及二次确认；其他状态不显示。

Rust：

- 导航首次 `TimedOut` 队尾重试，其他账号先执行。
- 二次 `TimedOut` 写入 `manualCheckRequired`；系统级导航错误仍全面暂停。
- 人工恢复命令仅接受三个账号级状态，并保留制作台和子弹运行态，成功后唤醒 scheduler。
- 截止首查达标、首查低利润轮空、失败后 5 分钟补查达标、补查失败轮空。
- 当天轮空跨重启过滤，次日自动失效；截止后配置修改不清除当天轮空。
- round plan 与时间轴不再产生 `cutoffBypass`。
