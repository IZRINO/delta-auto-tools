# 特勤处子弹兑换试运行设计

状态：已实现；二次确认与多账号调度已由后续设计接入，待桌面实机验收。

## 目标

先交付可真实购买、真实兑换的单账号子弹试运行；同时修正连续账号切换时模式选择页面尚未可交互导致烽火地带点击被吞的问题。后续已接入每日多账号兑换调度与二次确认窗口。

本阶段复用现有账号业务配置、子弹点击点、A/D 重置后向下滚动位置、模板双采样、operation window、紧急停止与 `SettingsCoordinator`。不使用 OCR 识别子弹名称，不新增任意动作编排器。

## 范围

本阶段包含：

- `game.modeReady` 命中后、点击 `game.beaconMode` 前的可配置固定等待。
- 子弹入口中“军需处”和“战术部门”各自独立的可配置固定等待。
- 单账号全部启用子弹目标的真实兑换试运行。
- 普通目标先执行、赛季目标后执行。
- 补齐、购买、价格波动重试、兑换成功灰色按钮确认。
- 单目标失败记录、仓库空间不足账号隔离、紧急停止。
- 每目标成功即时持久化当天状态。
- 隔离账号恢复时同时确认四制作台和当天启用子弹状态。

原阶段未包含、现已由后续设计交付：

- 每日兑换时间触发的多账号 round。
- 制作任务与每日兑换任务的五分钟合并调度。
- 网络北京时间服务。
- 完整游戏/WeGame 崩溃恢复。

## 连续账号导航等待

`NavigationDelays` 增加 `beacon_ms`。`game.modeReady` 双采样命中后执行可取消固定等待，再点击 `game.beaconMode`。

- 持久化字段：`navigationBeaconDelayMs`。
- 默认：`3000ms`。
- UI 与后端范围：`0–60000ms` 整数。
- 入口：点击区域校准列表中 `game.beaconMode` 对应行。
- 等待期间普通取消或紧急停止生效后，禁止发送烽火地带点击。
- 不新增中间模板，不更改现有点击坐标。

## 子弹试运行入口

新增 Tauri command：

```text
special_ops_start_ammo_trial(accountId, settingsRevision)
```

试运行使用主页面当前选中账号，解析默认或账号独立 `BusinessConfig`，冻结全部启用目标及账号当天运行态。已有 active special_ops run、全局总开关关闭、配置 revision 陈旧、账号非 `Ready`、目标点击点缺失或必需模板未验证时拒绝启动，不创建 operation window，不发送输入。`ammo.supply`、`ammo.tactical` 和 `ammo.seasonal` 只要求点击点，不要求参考图。

兑换入口 `ammo.department` 在两种前置页面使用同一屏幕位置和同一校准目标：

1. 仅兑换子弹：游戏完成 Space、Tab 后不点击“特勤处”，直接点击 `ammo.department`。
2. 已处理制作任务：停留在四制作台页面，直接点击同一 `ammo.department`。

单账号手动试运行要求当前页面已经显示共享 `ammo.department` 入口；执行器先双采样确认该目标，再点击。它不负责登录、启动游戏或自动判断是否存在制作任务。

## 页面导航

入口动作顺序：

1. 双采样确认并点击 `ammo.department`。
2. 等待 `ammoSupplyDelayMs`，直接点击 `ammo.supply` 点击点。
3. 等待 `ammoTacticalDelayMs`，直接点击 `ammo.tactical` 点击点。
4. 执行全部普通目标。
5. 存在当天待执行赛季目标时，直接点击一次 `ammo.seasonal` 点击点。
6. 执行全部赛季目标；目标之间不重复点击赛季入口。

`ammoSupplyDelayMs` 与 `ammoTacticalDelayMs` 独立保存，默认均为 `3000ms`，前后端只接受 `0–60000ms` 整数。固定等待本身不发布倒计时；等待结束后的点击遵循 run 级倒计时。等待或倒计时被取消后禁止发送点击。

删除 `ammo.list` 与 `ammo.seasonalList` 校准目标。旧配置中的这两项目标在 normalize 时清理，不再进入执行预检。`ammo.supply`、`ammo.tactical`、`ammo.seasonal` 从“识别与点击区域”迁移为点击点，旧参考图和模板验证状态不再参与执行。

每次点击、滚轮或按键后先移动鼠标至 `runtime.mouseParking`，再执行下一次截图。所有等待、倒计时和识别都响应取消。

## 键鼠倒计时边界

子弹流程使用 run 级 operation window 提示，文案为“X 秒后执行键鼠操作”。每个 run 首个键鼠操作块显示 5→4→3→2→1；后续原本需要提示的连续操作块只显示 1。识别、固定等待和持久化不倒计时；每个连续键鼠操作块开始前只提示一次：

- `ammo.department`、`ammo.supply`、`ammo.tactical`、`ammo.seasonal` 各自点击一次。
- 每个目标定位块“按 A → 等待 100ms → 按 D → 等待 100ms → 逐次向下滚 `scrollSteps` 次 → 等待 1000ms → 点击目标”合并为一个连续操作块；相邻滚轮事件间隔 100ms。
- `scrollSteps = 0` 的目标不发送滚轮事件，但仍执行 A/D 与 1000ms 等待后点击。
- `ammo.fill`、每次 `ammo.purchase`、`ammo.exchange`、`ammo.confirm` 各自点击一次。

倒计时完成后到该操作块结束前不再插入重复倒计时。紧急停止或取消在倒计时期间生效时，该操作块不得产生任何输入。

## 单目标状态机

目标按业务配置 `order` 排序；普通组先于赛季组，各组内部保持配置顺序。前端配置列表与实际执行顺序必须一致，不允许视觉混排。

1. 若账号运行态中 `lastSuccessDay` 已是当前 `Asia/Shanghai` 自然日，零输入跳过该目标。
2. 按 run 级规则发布一次倒计时。按 A 并等待 100ms，再按 D 并等待 100ms；将鼠标移动到目标 `clickPoint`，逐次向下滚 `scrollSteps` 次，相邻事件间隔 100ms；无论次数是否为 0，均等待 1000ms 后点击目标。
3. 双采样检查 `ammo.success`。命中表示人工已兑换或本地状态落后，立即写入当天成功并结束当前目标。
4. 未命中时双采样识别 `ammo.exchange` 或 `ammo.fill`。
5. 命中 `ammo.fill` 时点击补齐，等待并点击 `ammo.purchase`。购买失败最多重试 3 次，每次间隔 1 秒并重新识别；每次点击购买时使用游戏当前价格，不设置消费上限。
6. 补齐完成或步骤 4 直接命中 `ammo.exchange` 时点击兑换。
7. 双采样命中全局 `ammo.confirm` 用户参考图后点击区域中心，关闭置顶二次确认窗口。
8. 双采样确认 `ammo.success`；成功后立即通过 `SettingsCoordinator::with_runtime_change` 保存 `lastSuccessDay` 并清零该目标 `retryCount`。`ammo.success` 只做模板差异匹配，不读取颜色。
9. 成功或已记录普通失败后结束当前目标，不执行兑换后滚轮。
10. 进入下一目标；按其自身 `scrollSteps` 重新执行 A/D 重置与向下定位。

点击、购买或兑换不能以固定延时作为成功条件；固定等待只用于价格波动重试间隔。模板不一致、截图失败和窗口异常不得继续发送下一输入。

## 失败与停止

### 普通目标失败

单目标未能完成补齐或兑换、且未判定账号级故障时：

- 若 `retryDay` 不是当天，先把 `retryCount` 归零并写入当天；随后增加该目标当天 `retryCount`。
- 保存失败步骤、目标 ID、备注和时间。
- 继续同组下一个目标。
- 当天后续再次进入该账号时只允许再重试一次；仍失败则当天不再执行，次日运行态按既定自然日规则重新计算。

### 仓库空间不足

补齐/购买重试耗尽且界面仍处于不能继续的状态，或既定识别信号明确判定仓库空间不足时：

- 不执行其他子弹目标。
- 不继续该账号其他业务。
- 原子保存账号 `Isolated`、失败步骤、目标和时间。
- 后续 round 跳过该账号，直到人工恢复。

### 系统级故障

窗口归属、截图、模板文件、runtime 资源或持久化失败属于系统级故障：全面暂停，停止本次试运行，不把未知结果写成成功。

### 紧急停止

紧急热键立即停止输入并释放所有被跟踪按键。当前账号标记 `Uncertain`，禁止自动重跑；operation window 和热键在 durable 状态写入完成后清理。

## 持久化与当天状态

业务目标继续来自解析后的 `BusinessConfig.ammoTargets`；当天状态继续按账号 `AccountPlan.ammoTargets` 的稳定目标 ID 保存。账号运行态新增可选 `retryDay`，明确 `retryCount` 属于哪个 `Asia/Shanghai` 自然日；旧配置缺失时按 `null` 迁移。默认/独立业务配置复制不得复制 `lastSuccessDay`、`retryDay` 或 `retryCount`。

每个目标确认成功后立即持久化，不把多个成功结果积存在内存后一次保存。后一目标失败不得回滚前一目标已保存的当天成功状态。

试运行完成后只更新实际执行过的目标状态；已在当天成功而被零输入跳过的目标保持原值。

## operation window 与进度

`LoginRunKind` 增加 `ammo`，operation window 继续使用固定 label `special-ops-operation` 和同一紧急热键资源。进度显示：

- 当前账号 QQ。
- 普通或赛季组。
- 当前目标备注。
- 当前目标序号与总数。
- 当前步骤：进入入口、倒计时、A/D 重置、目标定位、检查已兑换、补齐、购买、兑换或确认成功。

主窗口保持可见；其他功能窗口按现有 special_ops 运行期仲裁隐藏。active run 清理完成前禁用配置、校准、模板测试和新试运行。

## 隔离账号人工恢复

现有四制作台人工校正 dialog 扩展为账号业务恢复 dialog。恢复 `Isolated` 或 `Uncertain` 账号时必须一次提交：

1. 四制作台逐台选择立即到期、正在制作或空闲；正在制作填写剩余小时和分钟。
2. 当前 `Asia/Shanghai` 自然日内每个启用子弹目标选择“已成功兑换”或“当天未成功”。
3. 二次确认摘要。

后端在同一 `SettingsCoordinator` revision 临界区内完成全量校验、四台计时校正、子弹 `lastSuccessDay`/`retryCount` 校正、失败记录处理、一次磁盘写入和内存替换。全部成功后恢复 `Ready`；任一字段无效时零部分写入。

“已成功兑换”写入当天日期、`retryDay = 当天` 并清零重试；“当天未成功”清空当天成功日期、写入 `retryDay = 当天` 并把 `retryCount` 重置为 `0`，允许恢复后的后续流程按首轮执行。恢复不会复制默认业务配置，也不更改目标顺序和点击点。
