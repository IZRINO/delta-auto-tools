# 特勤处轮次入口精简与 KKRB 刷新稳定性设计

## 目标

减少无效手动入口，避免 KKRB 临时繁忙阻断名称配置，并压缩特勤处配置页纵向长度。

## 范围

### 删除手动到期轮次入口

前端删除“开始当前到期轮次”按钮、对应 handler 与提示文本。保留 `special_ops_start_due_round` 后端 command，scheduler 继续由“继续”成功持久化后 arm，不改自动轮次、暂停或利润筛选语义。

### KKRB 名称手动刷新

`special_ops_fetch_profit_catalog` 仅在 KKRB 返回业务码 `-101` 时重试，最多 3 次；两次间隔 1 秒。其他 HTTP、网络、JSON 或业务错误立即返回。3 次仍为 `-101` 时返回固定错误“KKRB 暂时繁忙，名称列表未更新”。前端保留已加载的 catalog，不清空已有名称。

后台利润查询沿用已有查询节奏与 Moligod fallback，不复用此手动刷新重试规则。

### 配置折叠

三处使用原生 `<details>` 与 daisyUI `collapse collapse-arrow`：

1. 默认账号配置中的“子弹兑换顺序”。
2. 每个账号已启用后的“独立设置”主体。
3. 联网利润筛选中的“业务目标”绑定表。

三处均默认折叠，展开状态不写入配置。折叠仅改变显示，不改变保存、校验、点击点或业务目标绑定。

## 验证

- 前端测试确认删除入口文案与三处折叠容器。
- Rust 测试确认 `-101` 可被分类，手动刷新最多调用 3 次；非 `-101` 不重试。
- 运行定向测试、全量前端测试与 Rust 编译检查。
