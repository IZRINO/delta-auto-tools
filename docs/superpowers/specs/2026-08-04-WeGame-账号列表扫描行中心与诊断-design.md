# WeGame 账号列表扫描行中心与诊断设计

## 背景

`wegame.accountList` 的现有测试仅证明两次 Windows OCR 都读到至少一个纯数字片段。运行时扫描则把整个框选区域机械三等分后点击三次，并只在最终失败时保存“未找到目标 QQ”。

因此，测试通过不能证明三个点击坐标命中真实账号行，也无法区分列表动画、行中心偏移和重复选中。

## 目标

1. 保留“点击账号行后复制顶部 QQ”作为唯一身份校验。
2. 利用 Windows OCR 的文本纵向边界定位可见账号行中心，但不使用 OCR 文本匹配目标 QQ。
3. OCR 行信息不完整时继续支持原三等分扫描，避免漏字阻塞流程。
4. 扫描失败时保存足够的脱敏诊断，用户可直接判断扫描过哪些行。

## 非目标

- 不新增账号行点击点或额外校准项。
- 不保存、显示或输入密码。
- 不使用 OCR 文本决定目标账号身份。
- 不修改列表分页、滚动、强制重启 WeGame 或登录提交规则。

## 行中心解析

每次确认账号列表展开时，现有双采样 OCR 返回 `OcrWord` 及相对矩形。扫描器从两次样本中提取纵向文本中心，并按相邻中心距离聚类为最多三个可见行。

当两次样本都能得到相同数量、顺序稳定且位于列表区域内的 1–3 个行中心时，扫描器把这些中心作为本页点击槽位。X 坐标仍取 `wegame.accountList` 水平中心；稳定识别到一或两行时，只扫描实际可见槽位，绝不额外点击空白行。

两次样本行数不同、同序行中心偏差超过 8 像素、存在无效边界，或无法形成 1–3 个顺序行中心时，扫描器回退到当前区域三等分槽位。回退仅在两次样本均至少包含一个数字片段、即列表已确认展开时发生；否则保持现有 `ListUnavailable` 失败，不执行点击。回退不使用 OCR 文本内容，因此不会把漏字或错误识别变成错误账号匹配。

扫描页始终按从上到下顺序处理三个槽位。每次点击后保持现有流程：清空剪贴板、双击顶部已选账号、发送 `Ctrl+C`、读取纯数字 QQ、精确比对目标；非目标后重新展开列表。滚动、底部判定和停止条件不变。

## 失败轨迹

`AccountSelectionError::NotFound` 扩展为携带扫描轨迹。每条轨迹记录：页码、槽位序号、实际点击坐标及复制到的 QQ 脱敏尾号。行中心槽位和三等分回退槽位都记录同一格式的实际坐标。

脱敏规则：纯数字 QQ 仅保留最后四位，前缀固定为 `***`；无有效复制值记为“未复制到 QQ”。完整 QQ 不写入 `lastFailure`、日志或前端错误文案。

最终 `NeedsManualLogin` 仍使用 `ScanRememberedAccounts`，但错误文案追加扫描轨迹。完整 QQ 不进入 `lastFailure`、运行日志、轮次账号错误或前端错误文案；现有“账号复核不匹配，实际复制 QQ”路径也统一改为脱敏尾号。账号状态、跳过规则和 scheduler 规则不变。

## 测试与验收

1. 两个 OCR 样本都提供稳定的 1、2 或 3 行时，运行时按 OCR 行中心点击，不使用三等分坐标；不足三行时不点击额外空白槽位。
2. OCR 行中心不稳定时，回退到三等分坐标并保持旧扫描顺序；两个样本任一为空时返回 `ListUnavailable`，不点击。
3. 目标出现在 OCR 行中心第二槽位时成功；OCR 文本本身不影响目标匹配。
4. 扫描到底失败时，返回脱敏轨迹且不含完整 QQ。
5. 既有首屏命中、滚动后命中、重复页到底和复制失败测试继续通过。
