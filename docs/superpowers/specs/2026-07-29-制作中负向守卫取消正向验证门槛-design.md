# 制作中负向守卫取消正向验证门槛设计

## 问题

`craft.inProgress.<station>` 是负向守卫：制作中状态存在时禁止点击；状态不存在时允许点击制作台。当前制作试运行 preflight 却要求当前台先通过一次正向模板测试。空闲或可收取状态不会显示“制作中”，因此测试必然失败，用户无法启动本应由负向守卫处理的流程。

## 规则

制作试运行 preflight 对当前台 `craft.inProgress.<station>` 只要求：

- 已上传可读取的共享制作中参考图。
- 已框选当前制作台独立识别区域。
- 共享 threshold 合法。
- 当前制作台点击点满足现有空间校验。

不再要求 `verifiedSignature` 与 `verifiedAtMs` 有效。校准页面继续保留四台测试按钮；测试结果只用于诊断当前画面能否命中，不作为试运行启动 gate。

## Runtime 决策

- 两次有效采样均达到 threshold：判定仍在制作，零点击、零持久化。
- 两次有效采样均低于 threshold：授权点击制作台，再按奖励页或当前台制作列表分流。
- 一高一低：采样不一致，停止且不点击。
- 截图失败、参考图读取失败、匹配任务失败或取消：停止且不点击。

该改动只取消“必须提前正向测试”的 preflight 条件，不把系统错误转换为未命中。

## UI 与持久化

- 不新增 UI、Tauri command 或持久化字段。
- 测试失败仍清除当前目标的诊断验证签名，但不阻止制作试运行。
- 共享图片、threshold 或区域变化后，已有诊断签名仍按现有逻辑失效。

## 验证

- 后端测试：当前台拥有共享图和 rect、但无验证签名时，制作 preflight 成功。
- 后端测试：缺共享图、缺当前台 rect、共享图文件不存在时，preflight 继续失败。
- runtime 既有测试继续证明双命中零点击、双低分点击、不一致与采样错误零点击。
- 运行统一质量门禁后交付实机测试：未显示制作中状态的技术中心应进入点击后分流，不再报“尚未测试或验证失效”。
