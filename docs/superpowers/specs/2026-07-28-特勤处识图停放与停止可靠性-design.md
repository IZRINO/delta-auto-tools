# 特勤处识图停放与停止可靠性设计

## 目标

修正制作试运行中的四类关联问题：

1. 鼠标停留在点击后的识别区域，hover 状态改变画面，导致后置模板持续无法命中。
2. 全局总开关关闭时仍可启动特勤处试运行。
3. 特勤处紧急停止热键已注册，但被全局热键 gate 拦截。
4. 普通取消 command 已返回，后台 worker 或资源清理仍可能长期不结束，并统一误显示“正在取消登录试运行”。

## 范围

“特勤处鼠标停放点”只属于 `special_ops` 校准配置，由全部特勤处账号和登录、导航、制作流程共用。Timer、Counter、Rapidfire、Morse、Recognition 等其他工具不得读取或执行该坐标。

本设计取代 `2026-07-28-制作试运行取消与收尾-design.md` 中“普通取消不标记状态不确定”的旧约束。新测试发现制作输入已经发生时，本地状态可能无法证明与游戏端一致，因此改用保守状态。

本轮不修改制作完成时间算法、多账号 round 或子弹兑换流程。

## 方案

### 特勤处鼠标停放点

校准目标新增 `runtime.mouseParking`：

- UI 名称为“特勤处鼠标停放点”；
- 类型为点击点，仅保存屏幕坐标；
- 不上传参考图，不做模板验证；
- runtime 只移动鼠标到该点，禁止点击。

登录、导航、制作流程每次完成点击或按键后，在下一次截图前把鼠标移到停放点。当前键鼠步骤的三秒倒计时同时覆盖业务动作和紧随其后的鼠标停放，不为停放动作重复倒计时。

需要执行键鼠与后置识图的试运行必须通过停放点预检。未配置时拒绝启动并提示“特勤处鼠标停放点尚未校准”。

### 全局开关与紧急停止

登录、导航、制作三个试运行 command 在创建 run 前读取 `GlobalState`。全局总开关关闭时拒绝启动，不注册热键、不创建操作提示窗、不启动 worker。

`special-ops-emergency` 是唯一允许绕过全局热键 gate 的普通热键 scope。该 scope 仍只在特勤处 run 存活期间注册，run 清理后立即移除，因此非运行期按键无效果。

热键 callback 不执行持久化和完整资源清理。callback 只触发紧急停止请求并把后续处理派发到后台，避免公共热键监听线程被窗口销毁、配置写入或输入释放阻塞。

### 普通取消与状态风险

普通取消继续先设置当前 run 的取消标志，由 worker 退出流程并统一收尾。停止提示按 run 类型生成：

- 登录：正在取消登录试运行；
- 导航：正在取消游戏内导航试运行；
- 制作：正在取消制作试运行。

制作试运行在首次键鼠输入前取消时直接安全结束。进入任何制作键鼠输入后取消时，账号与当前制作台标记为“状态不确定”，禁止自动重跑；用户人工核对游戏状态并修正完成时间后才能恢复。该规则覆盖已收取、已购买材料或已点击生产但尚未确认 `craft.abort` 的情况。

### 有界资源清理

输入释放必须有界：

- 先使全部可取消输入 generation 失效；
- 对已追踪按键执行有限次数释放重试；
- 重试耗尽后返回明确错误并继续后续清理，禁止无限循环；
- 无论输入释放是否成功，都继续清除紧急热键、销毁操作提示窗并恢复特勤处启动前可见窗口；
- 多个清理错误合并记录，不用首个错误遮蔽后续结果。

普通取消不得提前删除 active run，也不得在旧 worker 未结束时允许新 run 启动。worker 完成有界清理后释放单实例。

## 日志边界

为以下阶段记录开始、成功或失败，字段至少包含 `run_id`、`run_kind` 和失败信息：

1. worker 流程返回；
2. 业务状态持久化；
3. 释放已注入输入；
4. 清除紧急停止热键；
5. 销毁操作提示窗；
6. 恢复其他功能窗口；
7. runtime 完成并释放单实例。

日志只用于诊断，不改变成功判定，也不记录 QQ 密码或其他敏感输入。

## 错误处理

- 鼠标停放失败：停止当前流程，不继续后置识图；已进入制作输入时按状态不确定处理。
- 全局总开关关闭：试运行 command 直接失败，不产生半初始化资源。
- 紧急停止：即使全局总开关关闭，运行期热键仍能登记停止；非运行期无 scope，按键无效果。
- 输入释放重试耗尽：记录清理失败，继续清理其余资源；账号保持需要人工确认的安全状态。
- operation window 销毁或窗口恢复失败：记录错误并结束 run，不无限等待窗口 API。

## 测试

1. 每次业务输入完成后，鼠标停放发生在下一次模板采样之前。
2. 未配置停放点时，登录、导航、制作试运行预检失败。
3. 全局总开关关闭时，三个试运行 command 均拒绝启动。
4. 普通热键受全局 gate 约束，`special-ops-emergency` 在已注册期间可绕过 gate。
5. 紧急热键 callback 不在公共监听线程同步执行完整停止流程。
6. 三类 run 的普通取消文案正确。
7. 制作首次输入前取消不改业务状态；首次输入后取消把账号和制作台标记为状态不确定。
8. 输入 emitter 创建失败或释放失败时，有界重试结束并返回错误。
9. 输入释放失败不阻止热键、提示窗和其他窗口继续清理。
10. 现有登录、导航、制作、热键冲突及全量质量门禁继续通过。

## 非目标

- 不让其他工具复用特勤处鼠标停放点。
- 不引入固定屏幕角落或坐标比例缩放。
- 不为 hover 状态增加额外参考图。
- 不让普通取消绕过 worker 并提前开放下一个 run。
- 不改变紧急停止后账号状态不确定的既有规则。
