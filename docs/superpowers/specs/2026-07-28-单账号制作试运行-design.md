# 单账号制作试运行设计

## 范围

本阶段实现一个账号、一个制作台的“收取并重做”试运行闭环。流程复用现有登录/导航 runtime、`RuntimeTarget` 双采样守卫、操作窗口、键鼠倒计时、普通取消和紧急停止。

本阶段不实现多账号轮换、四台批处理、子弹兑换、自动更换配方或完整仓库异常恢复。

## 流程

1. 要求游戏已处于 `game.stationGrid` 成功状态。
2. 当前台 `craft.inProgress.<station>` 使用四台共享的一张“制作中”参考图，但保存独立 rect。执行一次 400ms 间隔双采样。
3. 两次均命中：返回 `StillInProgress`，零点击、零持久化，提示“当前制作尚未完成，本次未执行点击”。
4. 两次均为有效低分：允许点击 `craft.station.<station>`。一高一低、截图/参考图错误或取消均停止，不得降级成未命中。
5. 点击后同时观察 `craft.reward` 与 `craft.recipeListReady.<station>`。命中奖励页则按一次空格，等待 `game.stationGrid`，再点同一制作台进入列表；命中制作列表则直接继续。
6. 两者均未命中时等待 2 秒并重试，总点击最多 3 次。三次失败后保存实际步骤和最后 similarity 摘要，账号及当前台标记 `Uncertain`。
7. 双采样并点击置顶配方 `craft.recipe.<station>`。
8. 若 `craft.produce` 命中，点击生产；否则双采样 `craft.fill` 后点击补齐，等待 `craft.purchase`，点击购买，再等待 `craft.produce` 并点击生产。
9. 等待 `craft.abort` 连续双采样，记录第二次采样对应的实际时间为 `startedAtMs`。
10. 以账号制作台配置的 `durationMinutes` 计算 `finishesAtMs = startedAtMs + durationMinutes * 60_000`。

## 状态与结果

状态机只负责步骤推进和结果分类，不直接修改 UI。结果包括：成功、普通取消、紧急停止、识别超时、动作失败、配置失败。

`StillInProgress` 不修改配置或 revision。`Started` 仅更新选定账号和制作台的 `startedAtMs`、`finishesAtMs`、状态。首次点击前失败不写业务状态；首次点击后失败会暂停自动化，并把账号与当前台标记 `Uncertain`，保存实际失败步骤和文本。

制作台首次点击由“制作中”负向守卫授权，不再配置正向点击 guard。配方、补齐、购买、生产与空格仍要求对应模板双采样。空格仅在 `craft.reward` 已命中后发送一次。

## 运行入口

新增独立 Tauri command 和前端按钮，参数为账号 ID、制作台类型和 settings revision。制作试运行与登录、导航试运行共用窗口仲裁：隐藏其他功能窗口，主工具窗口保持当前可见与置顶状态，不隐藏、不最小化、不临时置顶。仍创建 operation window、注册紧急热键并保持单实例。共享“制作中”参考图及当前台 rect 必须配置并通过当前签名测试；其他动态制作模板只要求矩形与参考图。command 返回带 `runKind` 的 `LoginRunSnapshot`，步骤通过现有 `special-ops://run-changed` 事件显示。

任一步骤成功、失败、普通取消、紧急停止后都必须释放已注入按键、注销紧急热键、销毁 operation window、恢复其他功能窗口并释放单实例。倒计时结束后必须发布“正在聚焦游戏窗口”“正在复核识别目标”“正在执行键鼠动作”等阶段状态，禁止把阻塞中的 focus 或模板等待继续显示为 `1 秒`。

## 测试

- runtime 测试覆盖：制作中零点击、空闲直接进入列表、奖励页返回台面、第三次点击成功、三次失败进入 `Uncertain`、`abort` 时间、取消与紧急停止。
- command 注册、capability 和页面入口做静态契约测试。
- 完成后运行 `bun run check`、`codegraph sync`、`git diff --check`。
